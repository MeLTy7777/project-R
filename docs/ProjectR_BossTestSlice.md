# ProjectR ボス戦の縦断スライス(Phase A16・Playtest専用)

既存の戦闘(Hendrix・剣・G17)・敵の攻撃予約(`ProjectR_EnemyAttack`)・神託の予兆・月桂冠の弾防ぎ・Hermes/Apolloのカード・デッキの基盤を**一緒に**評価するための、Playtest専用のDEVボス戦。
ストーリーの敵・報酬・本番の取得経路は作っていない。既存のダメージ・Cooldown・ドロー・セーブ・カードの仕様は変えていない。

## 見つかった問題(ゲームプレイ・設計)
1. **警告がカード頼み(最大の問題)**: ボス自身の攻撃には見える予兆が無く、`ProjectR_EnemyAttack` の記録を絵にしているのは神託のカードだけ。神託なしでは近接は判定が出るのが3frameだけで**事実上避けられず**、遠距離も弾が出てから。神託自体も「次の1回の攻撃だけ」を5秒間(Lv1)で、第三形態の連射(間隔 85f)には足りない。→ ボスは、カードに関係なく出る基本の予兆(足元の範囲・向きの線)を持つべき。
2. **予兆が読みにくい**: 遠距離の線は細く薄い(灰色の床で見えづらい)。近接の範囲は主人公と重なる半透明の四角。神託を使うと左上に大きな「目」のカットインが出て、画面の隅を占める。
3. **敵の弾が味方の矢に見える**: DEVの弾は黄金の矢のPrefabを複製しており、プレイヤーのApolloの矢と同じ絵。敵の弾は別の絵(色・形)にすべき。
4. **HUDの重なり**: ボスのHP表示(名前・数値)に「ULTIMATE n/100」の文字が重なる。
5. **歩き続ける近接ボスは避けにくい**: 第三形態の歩く速さ(3.3)はプレイヤー(3.1)より速く、逃げ続けられない。近づいたボスの近接は溜め 32f(=約0.5秒)で、人の反応(15〜20f)+動き(0.4〜0.8マスで約8〜16f)にほぼ余裕がない(ボットでは全フェーズ避けられたが、**人が実際に避けられるかは未確認**)。初代ボスは歩く速さ ≤ プレイヤー、近接の溜め ≥ 40f を推奨。
6. **敗北の後は復活もリトライも無い**: HP0でボス戦は終わるが、プレイヤーは死亡のまま(`PlayerDeath` は自動で復活しない)。次の戦闘はHPを戻さないとすぐ「敗北」になる。リトライ(`BossFramework.retry` + 復活のフック)は製品側の実装待ち。
7. **入力の競合(既知)**: 攻撃ボタン J は、剣・G17・竪琴の音符選び・狙って撃つカード(黄金の矢)の確定に共用される。ボス戦中に狙い撃ちと剣を同時に使うことはできない(カードの確定を待つ間は攻撃が使えない)。カードのキー Q/E/X/C/V は手札の位置に固定。
8. **Eventの数**: 攻撃とカードで Event が基準の約2.6倍(131)に増える。Hendrixの弾・判定・Apolloの矢/花/根が主。1フレームの時間は余裕(最大15.7msで一度だけ予算 16.7ms の近く)だが、さらに重い演出を足すなら注意。
9. **ボスの体**: アリーナのダミー1体(小さな絵・移動の向きを変える絵もない)。第一形態から第三形態で見た目が変わらず、フェーズの変化が絵で伝わらない(HUDの文字だけ)。

### 良かった点(測れた範囲)
- 本物の予約・弾・判定・公式ダメージの経路で、避ける/避けないの差が出る。ボットは全フェーズの全攻撃を避けられる(幾何的には避けられる)。
- 月桂冠 Lv3・ヒュアキントス・神託・G17・剣・混成デッキ(指輪2つ・30枚・検証つき)が、ボス戦の中で壊れず動く。
- 計測上の負荷は小さい(Game_Map.update の平均 1ms)。

## PartyCombat の制限(明示)
**製品の仲間は0人**。DEVのつなぎ(`allies: 1〜2`)は、ボスの弾を仲間の体(Event + `linkedActorId`)に当てて `PartyCombat.damageAlly` へ渡すだけで、仲間の移動・攻撃のAIは動かない。「本番の仲間の統合」ではない。仲間の被ダメージ(固定30)・ダウン・復帰しない規則・終了時の片付けだけを確認した(実機 B8)。

## 最初の本番ボスへの提案
1. **ボス自身の予兆**を最初に作る(`ProjectREnemyAttack.onAnnounce/list` を絵にする。範囲・向き・残り時間。カードの有無に関係なく出す)。神託は「より早く・長く・複数を見せる」補助に回す。
2. 敵の弾の**絵を別に**する(色・形・当たりの大きさが分かる)。
3. **速さと溜め**: 歩く速さ ≤ プレイヤー(3.1マス/秒)・近接の溜め ≥ 40f・連射は2発目以降も ≥ 30f。数値は人のプレイテストで決める。
4. **フェーズの変化を絵と音で**(今は文字だけ)。HUDの重なりを直す。
5. **敗北 → リトライ**(復活・位置・HP)の流れを製品側で決める。
6. ボス以外のEventを増やしすぎない(弾の上限・寿命)。
7. 本番の仲間を入れる前に、敵 → 仲間のダメージの窓口(量・防御・狙われ方)を決める。
