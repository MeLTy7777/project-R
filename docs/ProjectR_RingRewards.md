# ProjectR_RingRewards(Stage 5-B1)

通信ランクを満たしたときの「指輪の入手」と、特定のイベントによる「スキルの固定レベル報酬」を、イベントのプラグインコマンドから安全に行うための窓口です。

- プラグイン: `js/plugins/ProjectR_RingRewards.js`
- 新しいセーブ領域は作りません。CardDeckCore の既存の保存(指輪の所有・カードのレベル)だけを使います。
- ヒロインの名前・ランクの閾値・ゲーム変数の番号・通信の画面・マップのイベントは、このプラグインには入っていません(イベント側で指定します)。未設定のままでは何も付与しません。
- 指輪の装備・スキルの枠への割り当て・Q の選択は行いません(メニューでプレイヤーが行います)。

## コマンド1: 通信ランクを満たしたら指輪を入手する(`AcquireRing`)

| 引数 | 内容 |
|---|---|
| 指輪(神) | apollo / janus / themis / athena(hermes は本編の入手のまま。対象外) |
| ランクを保存している変数 | 通信ランクを入れているゲーム変数。0(未設定)は付与しない |
| 必要ランク | 変数がこの値以上のとき入手できる。0(未設定)は付与しない |
| 結果コードを入れる変数(任意) | 0 なら書かない。ランク用の変数は指定できない(下の「設定の誤り」) |
| 完了にするスイッチ(任意) | 結果が 1 か 2 のときだけ ON。失敗では触らない |

判定の順(最初に当てはまったもので終わる):

0. 通信ランクの登録表に誤りがある → `-1`(何も書かず、イベントの処理を中断。下の「通信ランクの登録表の誤り」)
1. 結果の変数がランク用の変数と重なる → `-1`(イベントの処理を中断。下の「設定の誤り」)
2. 結果の変数・完了スイッチに、使えない番号を指定した → `-1`
3. 指輪のIDが不正・対象外 → `-2`
4. ランク変数 / 必要ランクが未設定(または範囲外) → `-1`
5. すでに主人公が持っている → `2`(何も変えない。ランクが後で下がっていても同じ)
6. 仲間が持っている(受け渡した指輪) → `-5`(取り上げない)
7. ランク変数 < 必要ランク → `-3`
8. 戦闘中(カード戦闘中 / 画面に生きた敵がいる) → `-4`(あとで呼び直せる)
9. 主人公の所持にする → `1`

指輪を持つと、その指輪のスキル5つが使えるようになります(カードの個別の所持は不要)。

## コマンド2: スキルのレベルを固定値まで上げる(`RaiseSkillLevel`)

| 引数 | 内容 |
|---|---|
| スキルID | 指輪のスキルとして登録されているID(25種。例: `janus_reflection`) |
| 目標レベル | Lv2 か Lv3 |
| 結果コードを入れる変数 / 完了にするスイッチ(任意) | 上と同じ |

**そのスキルの指輪を主人公が持っているときだけ成功します**(hermes のスキルは hermes の指輪)。所持は CardDeckCore の指輪の所有(`hasPlayerRing`)で確かめます。

実際のレベルは `max(いまのレベル, min(目標, カードの最大レベル))` です。下げません。繰り返し呼んでも増えません。

判定の順(最初に当てはまったもので終わる):

0. 通信ランクの登録表に誤りがある → `-1`(何も書かず、イベントの処理を中断)
1. 結果の変数が、通信ランクに登録した変数 → `-1`(イベントの処理を中断)
2. 結果の変数・完了スイッチに、使えない番号を指定した → `-1`(レベルは上げない)
3. スキルIDが不正 / 目標が 2・3 以外・未設定 → `-2`
4. その指輪を主人公が持っていない(未所持 / 仲間が持っている) → `-6`
5. 戦闘中 → `-4`(戦闘中にレベルが変わらないようにするため)
6. いまのレベルが目標(上限)以上 → `2`
7. 引き上げた → `1`

`-6` のときは、レベル・カードの所持フラグ・所持枚数・完了スイッチを何も変えません。目標がいまのレベル以下でも `2`(済み)にはしません。すでにセーブに保存されているレベルは、書き換えも取り消しもしません(指輪を持てば、そのレベルから使えます)。

成功しても、カードの所持フラグ・所持枚数・ほかのスキル・指輪・デッキ・戦闘の処理は変えません。

## 結果コード

| コード | 意味 |
|---|---|
| 1 | 成功(指輪を入手した / レベルを上げた) |
| 2 | すでに済み(成功と同じ「完了」の扱い) |
| -1 | 設定が足りない・誤り |
| -2 | 入力が不正 |
| -3 | ランクが足りない |
| -4 | 戦闘中 |
| -5 | 仲間が指輪を持っている(指輪の入手 `AcquireRing` だけ) |
| -6 | スキルの指輪を主人公が持っていない(レベル上げ `RaiseSkillLevel` だけ。未所持・仲間が持っている) |
| -9 | そのほかの失敗 |

変数の初期値の 0 は「まだ呼んでいない」です。

## 通信ランクの登録表の誤り

`ProjectR_CommunicationRank` の「通信ランクの登録」が読めない場合や、誤りのある登録が1件でもある場合は、守るべきランク用の変数がどれか分かりません。そのため、指輪の入手もレベル上げも(hermes のスキルを含め)何もしません。

- 結果コードの変数も完了スイッチも書かず、そのイベントの処理を中断します。前に残った `1` や `2` で先へ進まないようにするためです。
- API の戻り値は `code: -1`、`status: "rankConfigurationInvalid"` です。
- 空の登録 `[]` や、通信ランクのプラグインが無い場合は誤りではなく、これまでどおり動きます。
- 直し方は [通信ランク](ProjectR_CommunicationRank.md) を参照してください。

## 設定の誤り

「結果コードを入れる変数」「完了にするスイッチ」は、0(または空)なら使いません。それ以外で使えない番号(データベースの範囲外・負の数・数字でない文字)を指定すると、黙って無視せず、次のように拒否します。

| 指定の誤り | 指輪の付与・レベル上げ | 結果の変数 | 完了スイッチ | イベント |
|---|---|---|---|---|
| 使えない完了スイッチ | しない | 使える番号なら `-1` を書く | どれも変えない | 続く |
| 使えない結果の変数 | しない | 書かない | 触らない | 続く |
| 結果の変数がランク用の変数と重なる | しない | 書かない(ランクを守る) | 触らない | **中断する** |

結果の変数がランク用の変数と重なる場合だけは、結果を書ける場所がありません。書くとランクが壊れ、書かないとランクの値が 1 や 2 のとき、後ろの条件分岐が「成功」「済み」と読んでしまいます。そのため、標準の「イベント処理の中断」と同じ動きで、そのイベントの後ろの命令を実行しないようにします。

- 原因はコンソール(テストプレイで F8)の警告 `[ProjectR_RingRewards] resultVariableIsRankVariable` に出ます。
- 台詞やフェードの後始末なども実行されないので、テストプレイで必ず確認してください。
- 自動実行・並列処理のイベントでは、設定を直すまで同じ警告が繰り返し出ます(自動実行は操作できなくなります)。
- コモンイベントの中で呼んだ場合、中断するのはそのコモンイベントだけで、呼び出し元は続きます。コマンドはマップのイベントに直接置くのが安全です。
- スクリプトから `ProjectRRingRewards.acquireRing(...)` を呼んだ場合は中断しません。戻り値の `ok`(と `abortEvent`)を確かめてください。
- 「ランク用の変数」は、指輪の入手の「ランクを保存している変数」と、`ProjectR_CommunicationRank` の「通信ランクの登録」に書いたすべての変数です。指輪の入手とレベル上げの両方で検出します。
- 通信ランクに登録していない変数をランクに使っている場合、レベル上げのコマンドはそれがランク用だと分からないので検出できません。ランク用の変数は登録してください([通信ランク](ProjectR_CommunicationRank.md))。

## イベントの作り方(例)

1. コマンド「通信ランクを満たしたら指輪を入手する」を、変数・必要ランク・結果コードの変数・完了スイッチを指定して置く。
2. 結果コードの変数で条件分岐し、`1` ならお礼の台詞、`2` なら「もう渡した」の台詞、`-3` ならランク不足の台詞、`-4` なら「今は渡せない」の台詞にする。レベル上げのイベントでは、`-6`(指輪をまだ持っていない)の台詞も用意する。指輪より先にレベル上げのイベントが起きる可能性があるときは、指輪を入手した後にもう一度起きるようにする(完了スイッチは `-6` では ON になりません)。
3. このイベントのページ条件に「完了スイッチが ON」を使えば、成功(または済み)になってから会話済みの状態にできる。失敗したときは、もう一度会話できる。

## まだ決まっていないこと(イベント側で指定する)

- 各指輪の必要ランクと、渡すイベント(対応する人物と、ランクの変数 101〜104 は決定済み。[ヒロイン通信の設計書](ProjectR_HeroineCommunicationDesign.md))
- どのイベントが、どのスキルを Lv2 / Lv3 にするか(そのスキルの指輪を入手した後に起きる順番にする)
- ランクの上げ方・通信の画面
