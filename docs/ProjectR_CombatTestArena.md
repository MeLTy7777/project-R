# ProjectR Combat Test Arena（開発用テスト会場）

> **Phase 5A-RT3 の更新**: カードキーは **Q / E / X / C / V**、HUDは明示的な戦闘イベントだけで出ます。最新の手順は [ProjectR_CombatRuntimeCompliance.md](ProjectR_CombatRuntimeCompliance.md) を参照してください。

現在の戦闘システム（HUD・5枚手札・7枚のカード・常駐Ultimate神・Divine HP・Gauge・Hermes/Apollo Ultimate・マップ移動）を、**ゲームを進めずに手で確認する**ための開発専用マップです。

- 本編のストーリー・通常のマップからは**繋がっていません**。入口は F8 Console のコマンドだけです。
- **Playtest（エディタの「テストプレイ」）専用**です。配布版（デプロイ版）では何も動きません。
- 戦闘のロジックは新しく作っていません。既存のProjectR APIを呼ぶだけです。

> **注意（必ず読んでください）**
> - **開発用の New Game のテストプレイで使ってください。** 既存の本編セーブを読み込んで使わないでください。
> - テスト開始時に、指輪（Hermes/Apollo）を主人公の所持にして7枚のカードを所持にします。**「カード戦闘を終了」または「アリーナから出る」で開始前の値に戻ります**が、**テスト中にセーブしない**でください。
> - 敵ダミーを倒すと経験値・ゴールドが入る設定の場合があります。気になる場合は使い捨てのテストプレイで確認してください。

## 0. まず最初に（この順番で試してください）

1. MZ の **テストプレイ**（Playtest）を始める（開発用の New Game で構いません）。
2. **F8** を押して Console を開き、次を入力して Enter を押す。

```js
ProjectRCombatTestArena.enter()
```

3. アリーナが開きます。**この時点では戦闘HUDは出ていません**（敵ダミーも見えません）。探索モードで、普通に歩けて、普通に調べられます。
4. **黄色い玉（操作盤）** まで歩きます（出現位置のすぐ北です）。
5. **決定キーで普通に調べます**（このプロジェクトのボタン設定では **F**。`Interact` として設定されています。Enterなどはボタン設定で外れている場合があります）。
6. メニューから **Start Hermes Test** か **Start Apollo Test** を選びます。
7. 戦闘が始まり、**戦闘HUDが現れ、敵ダミーも現れます**。
8. **戦闘中も、操作盤や端末（研究室のGauge/Divine、南東の門）を普通に調べられます**。リセットや終了にF8は要りません。

> **HUDが出る条件（ProjectR全体の決まり）**: 戦闘HUDは**実際の戦闘イベント中だけ**表示されます。「カード戦闘が有効」なだけ、「敵ダミーがマップにいる」だけでは出ません。アリーナは、テスト戦闘中を「戦闘イベント中」と宣言し、そのときだけダミーを出します。
>
> **補充のテスト**（カードの使用と補充）: 開始直後の `DRAW 25 / DISCARD 0 / COOLDOWN 0` と、スロット1のカード（Golden Arrow）を覚えます → ゲーム画面をクリックして `Q` を押す → **スロット1が入れ替わり**（元のスロット2のカードが左へ詰まって入り、**新しく引いたカードは右端のスロット5**に入ります）、**DRAW が 24**、**COOLDOWN が 1** になれば正常です。連続して押すと、そのたびに DRAW が1ずつ減り、COOLDOWN が1ずつ増えます。何も変わらない時は、操作盤の右の**状態表示**（青い玉）を調べると `直近のカード入力: 失敗 ○○` と**失敗した理由**が出ます（発動に失敗した時は、仕様どおり手札は変わりません）。

## 1. 入り方（F8）

1. MZのエディタで **テストプレイ** を開始します（New Gameで構いません）。
2. キーボードの **F8** を押して開発者ツールを開き、**Console** タブを選びます。
3. 次の1行を入力して Enter を押します。

```js
ProjectRCombatTestArena.enter()
```

4. 画面が暗転して、`DEV_CombatTestArena`（マップID **4**）の中央下（操作盤の手前）に移動します。**移動するだけで、戦闘は始まりません**（HUDも敵ダミーも出ません）。
5. **ゲーム画面を一度クリック**してから操作します。F8 Consoleにフォーカスがあると、キー入力がゲームに届きません。

入る前の場所（マップ・座標・向き）は実行中のメモリにだけ記録され、セーブされません。

その他のF8コマンド（上級者向け。普段は使いません）:

| コマンド | 内容 |
|---|---|
| `ProjectRCombatTestArena.exit()` | 入る前の場所へ戻る（戦闘終了＋データ復元つき） |
| `ProjectRCombatTestArena.status()` | 今の戦闘・神・Gauge・手札などの詳細（オブジェクト） |
| `ProjectRCombatTestArena.statusLines()` | 同じ内容の4行表示 |
| `ProjectRBattleHUD.getViewModel()` | HUDが今描こうとしている値（Phase 5A） |

## 3. 操作盤（Control Hub）

中央の **黄色い玉**（x25,y24）を、手前（y25）から上向きに**決定キー**（F）で調べると、メニューが開きます。**戦闘中も同じように使えます**（戦闘中は、決定キーを押した瞬間に、すぐ隣の端末の方向へ自動で向きを合わせます。マウスの照準がよそを向いていても調べられます）。右隣（x27）の**青い玉**は、いつでも「現在の状態」を表示します。

| 選択肢 | 動作 |
|---|---|
| Start Hermes Test | 7枚の実カード＋常駐Ultimate神=**Hermes**でカード戦闘を開始 |
| Start Apollo Test | 同じ7枚＋常駐Ultimate神=**Apollo**でカード戦闘を開始 |
| Reset Current Test | マップを読み直して**敵ダミーを復活**させ、直前のテスト（Hermes/Apollo）を最初からやり直す |
| End Card Battle | カード戦闘を終了（HUDが消え、アリーナが変えた所持データを元に戻す） |
| Show Test Instructions | 操作の説明を表示 |
| Exit Arena | 戦闘を終了し、入る前の場所へ戻る |
| Close | 何もせず閉じる（ESCでも閉じるだけ。Exitにはなりません） |

**テストの仕組み**（知っておくと安心な点）:

- 本番のデッキ（30枚・同じカードの枚数上限）の規則は**一切変えていません**。本番の規則では、いま実装済みの7種類だけでは30枚のデッキは作れません。
- そこでアリーナは、テスト開始の**一瞬だけ**7枚の実カード定義の「枚数上限」を差し替えて戦闘を開始し、**直後に必ず元へ戻します**（失敗しても戻る仕組みです）。保存してあるプレイヤーのデッキは変えません。
- 引き順は固定です。最初の手札は左から **1: Golden Arrow / 2: 病の矢(Plague) / 3: Hermes剣術 / 4: 高速移動(Swift) / 5: 葦笛睡眠(Reed Flute)**。次に引くのは **リラの支援(Lyre Calm) → 認識阻害(Obscure)**、その後は同じ並びの繰り返し（全30枚。使い切ったら通常どおり再シャッフル）です。
- 戦闘中のカード使用・クールダウン・補充・DRAW/DISCARD/COOLDOWNは、すべて実際のCoreの挙動そのままです。

## 4. 最初のおすすめテスト（Hermes）

1. F8で `ProjectRCombatTestArena.enter()` を実行する（第1章）。
2. 中央の黄色い玉を調べ、**Start Hermes Test** を選ぶ。上に「OK」と状態が表示される。**ここで初めて戦闘HUDと敵ダミーが現れる**。
3. **HUD確認**: 画面下に5枠（左から Q E X C V）、手札の右上に `DRAW / DISCARD / COOLDOWN`、左下に **HERMES / DIVINE HP 100/100 / ACTIVE**、上に Ultimate円弧（`ULTIMATE`、0/100）が出ている。テスト開始前（アリーナに入った直後）は**何も出ていない**（敵ダミーも見えない）。
4. **カード**を使う（ゲーム画面をクリックしてから、左から順に `Q` `E` `X` `C` `V`。数字キー1〜5は使いません）。使うたびに、使ったカードが手札から抜け、**残りが左へ詰まり、新しく引いたカードが右端（スロット5）に入り**、`DRAW` が1減り、`COOLDOWN` が増える。数秒〜十数秒後に `DISCARD` へ移る。
5. 南西の**研究室**へ行き、**Gauge満タン**端末（左から2番目）を調べる。円弧が明るい金色になり `U - ULTIMATE`（ready）になる。
6. **北東の射撃レーンか東のタンクダミー**へ移動し、`U`（ゲーム画面にフォーカスがある状態）で **Hermes Ultimate**（6連斬撃）を出す。ダミーに複数回ヒットし、Gaugeが0に戻る。
7. 研究室で **神を崩壊させる** 端末を調べる。Divine HPが0、`COLLAPSED  RECOVERING x.xs` と秒数が減っていく。**ゲームを遊び続けて（メニューや会話を開かずに）約15秒**待つと、`ACTIVE` に戻りDivine HPが **50 / 100** になる。
8. 崩壊中に **Gauge満タン** を押すと、円弧が紫の `GAUGE FULL / UNAVAILABLE`（満タンだが使えない）になり、`U` を押しても発動しない。
9. 北のダミーが倒れたら、操作盤で **Reset Current Test**（敵とHPが復活し、同じテストが最初から再開）。
10. 終わったら **End Card Battle**（HUDが消える）、または **Exit Arena**。

> 回復の15秒は**本物のタイマー**です。早送りの本番機能は付けていません。メニュー・会話・ウィンドウを開いている間と、ゲーム画面がフォーカスを失っている間は進みません。

## 5. Apolloテスト

1. 操作盤で **Start Apollo Test**（手札は同じ7枚。神だけが **APOLLO**）。
2. Gauge満タンにして、射撃レーンの立ち位置（黄の床 x28,y6）から奥の標的（x44,y6）へマウスで照準し、`U`。**7本の扇状の矢**が飛ぶことを確認する。
3. タンクダミーの前でもう一度（Gauge満タン→`U`）。複数の矢が当たり、Gaugeが0に戻る。
4. **Lyre Calm（リラの支援）** の確認: 研究室の **睡眠付与** 端末（左から6番目）を調べて主人公へ睡眠(State 32)を付ける → 手札のLyre Calmを使うと睡眠が解除される。

## 6. 衝突コース（北西）— Swift Movement（カード4）

床の**黄色いマス**が立ち位置です。壁は**赤茶のレンガ**です。立ち位置に立ち、マウスを壁の方向へ向けて `4`（高速移動）を使います。**壁の手前で止まり、壁の向こうへ抜けてはいけません。**

| 確認内容 | 立ち位置 | 向き | 期待する結果 |
|---|---|---|---|
| 直線の壁 | (5,3) | 東 | 壁(7,3)の手前(6,3)までで止まる（行き止まりの通路。入口は(2,4)） |
| 壁の向こうが空き地 | (4,7) | 東 | 壁(6,7)の手前で止まり、向こう(7〜11,7)の空き地へ**瞬間移動しない** |
| L字の角 | (20,6) | 北東（角へ向けて） | 角にめり込まず、壁の手前で止まる |
| 階段状の斜め壁 | (13,7) | 南東 | 斜めの隙間を**すり抜けない** |
| 通れないEvent | (9,3) | 東 | Event（宝箱）の手前(10,3)で止まり、向こう(12,3〜)へ抜けない |

通れないEvent（宝箱の見た目）は**敵ではありません**。敵ダミー（モンスターの見た目）とは見た目で区別できます。

## 7. 射撃レーン（北東）

- 立ち位置: **黄色い床 (28,6)**。ここから東へ、奥の標的（竜のような見た目、(44,6)）へ向けて、**マウス**で狙います。
- 赤い床は立ち位置から **1 / 3 / 5 / 8 タイル**先（x=29, 31, 33, 36）の目印です。
- **Golden Arrow（1）**・**病の矢（2）**・**Apollo Ultimateの7連矢**が、実際にここを飛びます。矢の飛行距離・消える位置・ヒット位置、命中するか、壁に当たるか、を確認します。標的はHP1000でそう簡単には倒れません。
- 上下に広い空き地があるので、扇状の矢の広がりも見えます。

## 8. 複数ダミー（西）とタンクダミー（東）

- **複数ダミー**: 3体が近接して並びます（(10,15), (12,15), (11,17)）。立ち位置は黄色い床 **(11,19)**。**葦笛睡眠（5）**の範囲、**Hermes剣術（3）**、**Hermes Ultimate**が複数体に当たることを確認します。
- **タンクダミー**: HP1000で動かず攻撃もしない敵です（(37,15)）。立ち位置は **(37,18)**。Hermes/Apollo Ultimateの**多段ヒット**、**病のDoT**（時間でダメージ）、連続ダメージの確認に使います。
- どの敵ダミーも、既存の`<enemy>`の敵Eventと同じ構造で、攻撃AIはありません（HPは既存の敵「魔獣」の1000）。倒れたら**操作盤の Reset Current Test**。

## 9. Divine/Ultimate研究室（南西）

端末は y=31 に並び、手前（y=32）から上向きに調べます。左から:

| x | 端末（玉の色） | 呼ぶもの | 備考 |
|---|---|---|---|
| 3 | **Gauge +25**（青） | `addUltimateGauge(25)` | gainIdなし。何度でも押せる。100で止まる |
| 5 | **Gauge満タン**（黄） | 100まで加算 | 既に満タンなら「満タンです」 |
| 7 | **Divine範囲攻撃 -25**（赤） | Damage Bridgeの範囲API | 常駐の神の位置を中心にした範囲。毎回新しい攻撃ID |
| 9 | **Divine全体攻撃 -25**（赤系） | Damage Bridgeの全体API | 毎回新しい攻撃ID |
| 11 | **神を崩壊させる**（別種の玉） | Bridge経由で現在のDivine HP分を与える | HPを直接書き換えない |
| 13 | **睡眠付与**（緑） | Hendrix公式AddState（State 32） | Lyre Calm確認用 |
| 15 | **状態表示**（青） | — | 神・HP・Gauge・手札枚数・Ultimateキー |

端末の結果は上部に `OK` / `NG（理由）` で出ます。崩壊中のDivine攻撃は `NG - 神は崩壊中です` になります（これも正しい挙動です）。看板(17,31)にも同じ並びを書いてあります。

## 10. マップ移動テスト（南東）

南東の**門**（(37,31)）へ歩いて入ると `DEV_CombatTransferRoom` へ移動します。小部屋の下の門で戻れます。

**移動の前に**: Hermes/Apolloテストを開始し、Gaugeを入れておきます（HUDに Divine HP と Ultimate円弧と手札が出ている）。

**移動の後（現在の仕様の観察）**:

- 神・Divine HP・Ultimate Gaugeは**破棄**され、**Divine HPパネルとUltimate円弧が消える**（既存のManager/Gaugeの仕様）。
- **カード戦闘そのものは続く**ので、**手札とDRAW/DISCARD/COOLDOWNは残る**（既存のCoreの仕様。今回は**変更していません**）。
- 小部屋の**状態表示**端末で、神が「なし」になっていることを確認できます。**End Battle**端末でカード戦闘を終えられます。
- 門から戻っても、神は**復活しません**。操作盤で Start Hermes/Apollo Test を選び直します。
- Damage Bridgeの攻撃ID登録も、マップ移動で消えます（新しい攻撃IDで再び当たる）。

この挙動を将来変えるかどうかはまだ決まっていません。**このアリーナは、現状を観察するためのものです。**

## 11. 出るとき

- 操作盤の **Exit Arena**（推奨）。戦闘を終了し、データを元に戻し、**入る前のマップ・座標・向き**へ戻ります。
- F8から `ProjectRCombatTestArena.exit()` でも同じです。
- 入る前の場所が分からない場合（エディタでアリーナから直接テストプレイを始めた場合など）は、ゲームの**初期位置**へ戻ります。

## 13. 安全のしくみ（Playtest限定）

- プラグイン `ProjectR_CombatTestArena.js` は、最初に `Utils.isOptionValid("test")`（MZ公式のPlaytest判定）を確認し、**Playtestでなければ何も作らずに終了**します。グローバルAPI・プラグインコマンド・Scene_Mapのフックのいずれも作りません。
- 万一Playtest判定が途中で変わっても、すべての変更系APIは呼び出し時にもう一度確認して拒否します。
- 本番のマップ（Map001〜003）・共通イベント・Systemのどこからも、このアリーナへは繋がっていません。通常のNew Gameでは自動で入りません。
- Core（CardDeckCore）・Manager・Gauge・Bridge・Activation・7枚のカード・Hermes/Apollo Ultimate・Hendrix・DotMoveは**変更していません**。
- RT2（戦闘HUDの表示条件・戦闘中の調べる）で変更したのは次の3つだけです。数値（Cooldown・ダメージ・Divine HP・Gauge・15秒回復など）は一切変えていません。
  - `ProjectR_BattleHUD.js`: 表示条件を元の規則（実際の戦闘イベント = `ProjectRCombatPresence` だけ）に戻した。
  - `ProjectR_CombatPresence.js`: 「画面内の敵以外で戦闘イベント中を宣言する」登録口（`registerCombatSource`）を追加。アリーナはテスト戦闘中だけこれに答える。
  - `ProjectR_PlayerFacing.js`: 戦闘中、決定キーの瞬間にすぐ隣の「決定ボタン」イベントの方向へ向ける（アリーナ専用ではなく、ProjectRの戦闘全般で有効）。
- 保存データに新しい項目を足していません（戦闘状態・戻り先・スナップショットは実行中のメモリのみ）。

## 14. 既知の制限・未確認

- この環境ではMZを起動できないため、**マップの見た目・当たり判定・実機での挙動は未確認**です。マップ・Eventは通常のMZ形式で作成し、構造と通行判定は自動テストで確認しています。実機で確認してほしい点: 玉の見た目の色、看板の文章量、門の画像、メッセージの位置、壁タイルの見た目。
- 敵ダミーの見た目は既存のMonster画像の流用です（アートは作っていません）。
- 玉の色と端末の対応は看板に書いてあります（ラベルを画面上に出す仕組みは作っていません）。
- 見た目を直したい場合は、MZエディタでマップ4・5を開いてEventの画像・床タイルを自由に変えて構いません。Eventの**名前**と**プラグインコマンド**は変えないでください（自動テストが参照します）。
