## 2. 確定済みの設計ルール(今回の指示)

- レベルは**累積**。同じ効果の数値が後のレベルで変わるときは**置換**(加算・乗算しない)。→ `ProjectRCardCatalog.resolveLevels`(H1から実装済み・テスト済み)。
- **ヴェイル**の効果範囲は、効果時間のあいだ**現在のマウス位置に連続して追従**する(最初の位置に固定しない)。ワークブックの対象タイプは「その他」だが、実行時の対象タイプは `Cursor` として扱う。**現在の `ProjectR_CardDeckCore` は `cursor` を受け付けない**(`TARGET_TYPES` は direction / ground / instant / ally)ため、H2Bで対応が必要(カタログに `runtimeTargetTypeSupported:false` と記録、テストで拒否されることを確認)。
- **コピー上限の例外はデータ**で持つ(カードごとの `maxCopies`)。標準は 通常3 / 強力2 / 特殊1(記入ガイド)で、例外は 一閃・ヴェイル・ストレングス・葦笛・絶。全体の規則(30枚・コピー上限の検証)は変えていません。

## 4. 未確定事項(推測で補っていません)

**共通**
1. 「指輪」列は7枚とも空欄。神=Hermesから指輪=hermes と読んでいる。
2. 「Cut-in方向」が全カードで「ランダム」。記入ガイドでは通常カードの向きは規定がなく(左上/右上ランダム)、横/縦のランダムはUltimateのみ。通常カードの向きも横/縦なのか未確定(現在の通常カットインは横長の1種類)。
3. 「対象なし時: カードを消費する」(一閃・サイコポンポス・薙ぎ払い・葦笛)は、現在のカード基盤の「発動に失敗したら消費しない」と食い違う。H2Bで「効果が空振りでも成功として消費する」扱いが必要(絶は「失敗は非消費」で一致)。
