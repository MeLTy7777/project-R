# Apollo「ギガース殺し」(apollo_gigas_slayer) — Phase Apollo-A7

設計ID 13 / Apollo / 妨害 / 強力 / 最大5枚 / 最大Lv3 / Cooldown 3秒 / Ground / 壁越え いいえ。実装は `js/plugins/ProjectR_ApolloGigasSlayer.js`(Lv1〜3)と、弱点・傷・病などの共通の状態台帳 `js/plugins/ProjectR_ApolloStatus.js`。数値は `data/ProjectR_CardBalance.json`(開発用エディタ F6)にあり、プラグインは幾何と手順だけを持つ。

## 1. ワークブックの記述(確定)
- Lv1: 一本の太い矢(幅の当たり判定1マス)をチャージして放つ(オートチャージ)。当たった敵は弱点状態(持続5秒。被ダメージ2倍)。1ヒット100ダメージ。
- Lv2: 傷状態を付与(持続5秒。秒間30のスリップダメージ + 被ダメージ10%増加)。
- Lv3: 幅が3マスになり、連続ヒットする。連続ヒット仕様は黄金の矢と同じ。
- 成功: 範囲内に敵がいた場合 / 失敗: 範囲外 / 対象なし時: 対象外。演出: 光の粒子が弓の先端に集まり発射と同時に放出 / 金色 / 音「シュー…ズバァン」。

## 2. 実装(累積レベル。同じ効果の数値は新しいLvで置換)

## 3. 命中と消費(予約→確定。黄金の矢と同じ)
発動 → チャージ(カード未消費・矢なし) → 発射。最初の有効なヒットの瞬間に、正規の経路(`requestUseCard`)でカードを1回だけ消費し、そのヒットのダメージを与える。何にも当たらなければ非消費・Cooldownなし。チャージ中・飛行中の再発動は `gigasPending` で拒否。戦闘終了・マップ移動・ロード・死亡・対象の消滅で、矢・チャージ・ビームの絵・ヒットストップをすべて片付ける(セーブしない)。

## 4. 仮の決め(ワークブックに無い部分。確定仕様として扱わない)
1. **オートチャージの時間 0.5秒**。チャージ中は照準に追従し、放つ瞬間のマウス方向へ撃つ。
2. **矢の速さ20マス/秒・射程 ∞(従来は40マス)・貫通なし**(Lv1〜2)。壁と地図の端、寿命(約58秒)で止まる。F6の `bowRangeTiles` / `bowBeamRangeTiles`(0 = ∞)で有限にもできる。
3. **状態の合成は積**: 弱点x2 と 傷x1.1 は x2.2。監査文書 §10 A5(乗算か加算か)は未確定のままで、DamageModifiers 側の規則は変えていない。ギガース殺しの2状態は台帳が積にまとめる。
4. **状態は命中の「後」に付く**: その命中自体のダメージは倍にならない。Lv3の連続ヒットでは、ヒットごとに持続が更新され、2ヒット目以降は倍率が掛かる(1体あたり 100 + 10 x 220 = 2300)。
5. **スリップも被ダメージ倍率の対象**(HPを減らす呼び出しは同じ窓口を通るため)。Lv2: 30 x 2.2 = 66 を5回。
6. 再命中は持続時間の更新(重ねがけしない・スリップの位相は保つ)。
7. **同じframeに切れる状態の順序**: 同じframeで期限が来る状態同士は、継続ダメージを先に処理してから外す(倍率が処理順で変わらない)。
8. 効果音: ワークブックの「シュー…ズバァン」の専用音は無く、RTPの Wind5(チャージ)/ Bow2(発射)/ Blow7(命中・連続は間引く)で代用。
9. 属性は無属性(`element` 0)。

## Lv3のビーム: 幅3マスの「1本」(Phase A10の確認と絵の修正)
確認した仕様: Lv3は**1本**のビームで、幅は**3マス**、その幅全体が当たり判定。連続ヒットと、Lv1〜2から引き継ぐ効果は変えない。絵の幅と当たり判定の幅は一致させる。

- **既存の動き(確認結果)**: 撃つのは1発射(`getShots()` が1件)。当たり判定は幅3マスを、隙間なく重ならない1マス幅の3つの帯(-1.5〜-0.5 / -0.5〜0.5 / 0.5〜1.5)に分けて計算するが、1体の敵への連続ヒットは1本ぶん(最大11ヒット・ダメージ・弱点・傷は従来どおり。3帯 x 11にならない)。端は敵の体の半分まで正確に切れる(継ぎ目に隙間なし・左右対称)。壁で一部の帯だけ遮られたときは、その帯だけ短い。判定は変更なし。
- **見つかった不一致(絵)**: 絵(共有の `apollo_volley.beam`)は ① 光が端に向かって細り、見える幅(不透明部分)が約2.46マスで3マスに届かない ② 実機で中心が当たり判定の中心線より18px(0.375マス)上にずれていた(`offsetY -18` が二重に掛かる)。当たり判定の端にいる敵が、ビームの光の外に見えた。
- **修正(ギガース殺しだけ)**: 専用の絵 `apollo_gigas.beam`(`ProjectR_Gigas_Beam.png`: 幅3マス = 144pxの端まで光が続き、端に縁の線)と `apollo_gigas.beamlane`(`ProjectR_Gigas_BeamLane.png`: 遮られたときの1マス幅の帯。左右の端まで光が続き隣と隙間なくつながる)を `ProjectRPresentationVfx.register` で登録し、ビームの絵だけこの2つに差し替えた。`offsetY -9`(実機で測った値)で中心を撃つ位置の中心線に合わせた。黄金の矢の絵(`apollo_volley.beam`)・VFXの仕組み・ダメージ・状態・Cooldown・消費は変えていない。素材は自作のDEV(`tools/gen_dev_a10_assets.cjs`。既存の画像は上書きしない)。
- **実機の測定**(`tools/mz_cdp/apollo_a10_gigas_beam_verify.cjs` 6/6): 絵のSpriteの不透明部分の幅 **3.00マス**(修正前 2.46)、中心のずれ **0.022マス**(修正前 0.397)。横 ±1.4 の敵は11ヒット・横 +2.6 は当たらない・継ぎ目の敵も11ヒット。一部が壁のときは隣り合う3枚で描き、遮られた帯だけ短く、判定も同じ長さ。終わると絵・錨・召喚・Eventが残らない。
- **注意**: 黄金の矢のLv3のビームは同じ共有の絵を使っているため、同じ幅(約2.46マス)・同じずれ(18px)が残っている(今回の依頼の対象外。直すかは別の判断)。
