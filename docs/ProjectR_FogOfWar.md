# ProjectR 戦争の霧(Fog of War) v0.1.5

フィールド戦闘(`docs/ProjectR_FieldCombat.md`)のための視界の拡張です。既存の視界システム(`ProjectR_CombatOcclusion` → `ProjectR_VisionOcclusion`、`docs/ProjectR_OcclusionRecovery.md`)は**変更せず**、その計算結果を読む新しいプラグイン `js/plugins/ProjectR_FogOfWar.js`(末尾に登録)で拡張しています。

> 既存の視界プラグインを直接書き換えなかった理由: この2本は、復元元(旧プロジェクト)と同一であることを確かめるテストで保護されているためです(`tests/ProjectR_OcclusionRecovery.test.cjs`、`ProjectR_H2CB1.test.cjs`)。FogOfWar は、VisionOcclusion が公開している API(`eventTags` / `inside` / `settings` / `invalidateCache`)と、`Spriteset_Map._projectRVisionLayer` の計算結果(`visibility`)だけを使います。

## 3つの状態

| 状態 | 地形 | 敵・イベント |
| --- | --- | --- |
| 未探索 | 真っ暗(隠す) | 描かない |
| 探索済み(いまの視界の外) | **灰色**で、以前に見た静的な地形だけ | 描かない(HPバー・影・付属の画像も) |
| いま見えている | 通常の色 | 通常どおり描く |

- **視界を遮るもの**: Region 255、`<VisionWall>`(イベントのメモ/有効ページの注釈)、追加の `ExtraOpaqueRegionIds`。通行不能な地形・`<CombatWall>` は遮りません(**視界の遮蔽と通行の衝突は別**)。
- **扉**: 閉じたページに `<VisionWall>` を付け、開いたページ(セルフスイッチなどで切り替え)には付けない。開くと視線が通り、閉じるとまた遮ります(実機で確認)。
- **視界を遮る壁は、通行不能にするだけでなく Region 255 にする**(マップの外周も)。通行不能でも Region 0 のタイルは視界を遮らないので、視線が壁の端をかすめて抜けたとき、そのマスは途中までしか描かれず、斜めに欠けて見えます(Map008 の外周で起きた)。
- **既存の仕組みは残る**: 暗闇の濃さ(`DarknessOpacity`)・視界の距離/角度・Region 254(建物の画像を保持)・`<VisionKeepVisible>` は、そのままです。FogOfWar を外せば、従来の見え方に戻ります。

## 探索の記憶

- マップごとに「見えたマス」をビット列で持ち、**場所移動・セーブ/ロード**をまたいで残ります。保存先は `$gameSystem._projectRFogExplored[mapId] = { w, h, count, bits(base64), v?, hist?(base64) }`(`bits` は 60x40 のマップで約 400 文字)。`v`・`hist` は v0.1.5 で足した「滑らかな縁の履歴」(下の「滑らかな縁の保存」)。
- **旧セーブ**(この記録が無い)は、空から始まります。**マップの大きさが違う記録・壊れた記録・型が違う記録**は捨てて空から始めます(エラーなし)。
- **滑らかな縁の保存(v0.1.5)**: 記憶の縁(灰色と黒の境)の斜めの形を、セーブ・マップ移動のあとも残す。
  - 実行中は、見えた形(視界の多角形・壁のマス・主人公のマス)を、1 マスを 16x16(3px)に分けた「細かい記録(grid)」にも残す(CPU 側。`Uint16Array`、1 マスの 1 行 = 16 セル = 16 ビット)。画面の履歴(acc。GPU)は、これまでどおり多角形を直接積み上げ、ロード・マップ移動のあとは、この細かい記録から作り直す(同じ区間が続く行をまとめて描く)。
  - 保存の形(マップごとの記録に足す): `v: 2`・`hist` = base64。`hist` は、**探索済みで、全部は見えていないマスだけ**の並び。1 件 = varint((前の件とのマス番号の差 - 1) x 2 + 種類) + (種類 1 のとき)32 バイト(16 行 x 16 ビット、リトルエンディアン)。種類 0 = 探索済みだが、まだ何も見ていないマス。**全部見えたマスは書かない**ので、全部見えたマップ・旧セーブは `hist` なし(従来と同じ大きさ)。
  - 大きさ: 縁のマスだけ(Map008 17x13 で 22 マス・約 1KB、Map001 60x40 を歩いても約 6KB)。上限は 1 マップ 1500 マス(超えたマスは、全部見えた = 従来のマス単位)。大きなテクスチャは保存しない。マップごとに別の記録。
  - 互換: 旧セーブ(`v`・`hist` なし)は、探索済みのマスを全部見えたものとして読む(縁はマス単位。そこから新しく探索した所は滑らか)。壊れた `hist`・将来の版(`v` が 2 でない)・大きさの違う記録は、`hist` だけ捨てる(`bits` は残す)。旧コードは `v`・`hist` を無視して動く。
  - 履歴を持たない設定(`FeatherPixels = 0`・`ExploreRangeTiles > 0`・ループするマップ・レンダラなし・12000 マスを超えるマップ)では、新しく探索したマスは全部見えた(従来)として記録する。すでにある細かい記録は壊さない。
  - 実機(`tools/mz_cdp/fog_persist_verify.cjs`): セーブ → ロード・Map008 → 001 → 003 → 007 → 008・戦闘の出入りの繰り返しで、見えたセル(約 33,000 個)の数・ハッシュが完全に一致し、縁の位置の差は 2px 以下。ロード後の未探索(13,830 点)は完全な黒。
- 保存への書き出しは、セーブの直前(`DataManager.makeSaveContents`)・マップ移動の直前(`Game_Map.setup`)にだけ行います(毎フレームは書かない)。
- 記憶するのは**地形だけ**です。敵の位置・イベントは記憶しません(見えなくなった敵は消えます)。
- `ExploreRangeTiles`(既定 0 = 視界のすべて)を設定すると、プレイヤーからその距離までの見えた場所だけを記憶します。
- プラグインコマンド: 「探索の記憶を消す(このマップ)」「探索の記憶を消す(すべてのマップ)」。

## 隠れた敵

- いまの視界の外にいる敵・イベントは、スプライト・HPバー・付属の画像を**描きません**(`renderable=false`)。位置・AI・当たり判定・状態は**そのまま**で、行動は止めません(実機で、隠れたまま壁を越えて近づき、攻撃してHPを減らすことを確認)。
- 判定は、体の代表点(中心と、内側へ寄せた角)が、いまの視界の多角形に入っているか。壁の角をかすめる視線も、既存の多角形の計算で扱います。

## FieldCombat との連携(`ProjectR_FieldCombat.js`)

- 自動の戦闘開始・終了は、**見えている敵**だけで判断します(隠れた敵だけでは HUD も始まらない)。
- 予兆(攻撃の範囲の赤い表示)・`getVisibleEnemies()`・HUDの予兆数は、隠れた敵のものを出しません。
- 見えない敵に攻撃されて**HPが減ったとき**だけは、12 tile 以内に敵がいれば戦闘を始めます(存在は分かるが、位置は分からない)。
- 敵の行動(`attachEnemy`)は、戦闘中でなくても、隠れていても続きます(メッセージ・イベント・メニュー中だけ止まる)。
- 狙いはマウスの方向なので、隠れた敵への自動照準はありません。

## 描画と性能

- 視界の計算は既存の VisionLayer のもの(キー(位置・向き・壁の形)が変わらなければ再計算しない)を再利用し、FogOfWar はその結果から、①見えているマスの走査(視界が変わったときだけ)、②探索済みのマスクの描き直し(探索・スクロールが変わったときだけ)、③敵の可視判定(毎フレーム。敵が動くため)を行います。マップ全体を毎フレーム作り直しません。
- 記憶の地形は、全地形の Tilemap を1つ(灰色 + 暗さのフィルター。PIXI は、フィルターをかけた Tilemap に親の alpha を掛けないので、暗さもフィルターの中で下げる)と、2段のマスク(探索済みのマス × いまの視界の外)で描きます。
- 主人公の重ね描き(PlayerOverlay): Vision の保持の層は壁の絵を主人公の上に描くため、壁のすぐ近くで主人公の頭・体が隠れます。主人公(と、持っている武器の表示)だけを、暗闇・保持の層の上へ写して描きます。敵・イベントは写さないので、隠れた敵は隠れたままです。
- 実機(NW.js / Chromium 85)の測定: 動き続けて 59.9 fps。`Spriteset_Map.update` の平均は 1.5 ms(霧なし 1.1 ms)、95% 値 2.9 ms。止まっている間は、多角形の走査・マスクの描き直しが増えません。

## 未探索は完全な黒(v0.1.2)

- 縁のぼかしの変換を `アルファ = 3 × (1 − ぼかした視界)` にした(縁と、縁の約1px内側まで完全に暗い)。縁のサブピクセルの誤差でも、未探索へ明るい点が漏れない(以前の `2 ×` では、縁のすぐ外に最大 18% の明るい点が出た)。
- 暗闇は、DarknessOpacity が 1 未満でも、記憶を使うとき(Memory)は、未探索を**不透明 100% の黒**にする。記憶を使わないときだけ、従来の濃さ。
- 重ね描き(PlayerOverlay: 主人公・持っている武器)は、**探索済みのマスの中だけ**に切り抜く(壁の向こうの未探索へ、銃などがはみ出さない)。
- 柔らかい版の描画に失敗したときは、その場で硬い縁・元の暗闇へ戻す(失敗のまま元の暗闇を止めると、未探索が丸見えになる)。
- 神の表示Event(`<projectRGodVisual>`)は、プレイヤーの一部として、「視界の外の敵・イベントを隠す」の対象から外した。
- **大きな壁・扉の絵(v0.1.4)**: VisionOcclusion の「保持」の層(壁のマス・`<VisionWall>`/`<VisionKeepVisible>` のイベントの絵)は、**まるごと見せる**(扉の上の弧も)。壁のマスは「最初に当たった壁」だけが描かれるので探索済みで、イベントの絵は、イベントそのもの(透明な所は何も描かない)なので、未探索の地形は出ません。
  - 経緯: v0.1.3 は、保持の層を「探索済みのマス + 扉自身のマス」で切り抜いたため、扉の絵が自分のマスの高さで水平に切れ、扉の前に立つと、主人公の上半身が扉の絵の後ろに隠れた(重ね描きも、探索済みのマスの中だけに切り抜いていたため)。切り抜きは外した。
  - 主人公の重ね描き(PlayerOverlay): マスクは「探索済みのマス + 見えている壁・扉の絵が占めるマス」(`keepClip`)。扉の前・戸口・戸口を通る間、主人公は扉の絵・暗闇の前に出る。壁の向こうの未探索へ、銃などははみ出さない。
  - 実機の確認(A/B): 保持の層を隠した画面では、未探索が完全な黒。保持の層がある画面でも、扉の絵の範囲の外は完全な黒(扉の絵は自分の絵だけを足す)。
- **記憶の縁の階段(v0.1.4)**: 記憶した地形(灰色)と未探索(黒)の境が、マス単位の階段になっていた(探索済み = 中心が視界に入ったマス)。見えた形(視界の多角形・壁のマス・主人公のマス)を、マップ全体の半分以下の解像度のテクスチャへ**積み上げる履歴(acc)**を作り、記憶した地形を「履歴 ∩ 探索済みのマス」で表示するようにした。履歴の外の探索済みのマスの部分は黒(`accDark`)。探索済みのマスは、多角形に少しでも重なるマス(3 本の走査線)にした(履歴が必ずマスの中に収まり、記憶の縁が、実際の視界の斜めの縁になる)。
  - 実機: 記憶の縁の隣り合う行の位置の差は 3px 以下(従来のマス単位は 48px の階段)。縁の近くを歩いても、未探索 33,192 点で漏れ 0。履歴の描き直しは、視界が変わったときだけ(止まっている間は増えない)。
  - 制限: 履歴(GPU)は、実行中の積み上げですが、v0.1.5 から細かい記録(3px)として保存し、ロード・マップ移動のあとに作り直します(縁の位置は、元の多角形から最大 1.5px ずれる)。v0.1.4 以前のセーブから読んだ所は、マス単位の縁。ループするマップ・`ExploreRangeTiles` を使うとき・`FeatherPixels = 0`・マップが大きすぎるとき(24M px 超)は、従来のマス単位。
- 実機: 未探索の点 62,106 点(27 回の撮影)で、静止・移動中・扉の開閉・壁際の銃・神の演出中・硬い縁・暗闇の濃さ 0.5 のすべてで漏れ 0(`tools/mz_cdp/field_perception_verify.cjs` F1)。v0.1.4 の A/B の確認は、`tools/mz_cdp/field_facing_verify.cjs` FA6・FA8。

## 視界の縁のぼかし(FeatherPixels)

- 視界の斜めの縁は、PIXI のステンシルマスク・Graphics がアンチエイリアスされないため、ギザギザになります。見えている形(視界の多角形 + 見えている壁のマス)を、**半分の解像度のテクスチャ**へ描いてぼかし、アルファを `2 × (1 − 見える度合い)` に変換します(縁のちょうど上で 1 = 完全に暗い、内側へ向かって 0)。これを、①暗闇(未探索の黒。元の `dark` は描かない)と、②記憶した地形(探索済みの灰色)のマスクに使います。
- ぼかしは視界の**内側だけ**で、縁より外へはみ出しません(実機で、柔らかい版が硬い版より明るくなる所は、縁のサブピクセルの誤差だけ)。探索済みの暗い地形の縁は、見えている所 → 探索済みの暗さへ滑らかに変わり、暗さより暗い縁取りは出ません(暗闇は、未探索のマスだけにかけます)。
- 見えている壁のマスは、まるごと「見えている」側にします(壁のすぐ近くの床が暗くならず、壁の途中で縁が斜めに切れない)。壁の絵そのものは、従来どおり VisionOcclusion の保持の層が描きます。
- `FeatherPixels = 0`、またはレンダラが使えないとき(Node のテスト)は、従来の硬い縁です。視界の計算・敵の可視判定・当たり判定は変わりません(描画だけ)。性能: 動き続けて約 60 fps、`Spriteset_Map.update` の平均は、ぼかしなしより約 0.5 ms 増えます。
- マスクを外すと、PIXI は、そのマスク用の図形を「描く」状態(renderable = true)に戻します。切り替え(`setConfig({feather})`・霧の有効/無効)のたびに、マスク用の図形は描かない状態へ戻しています(戻さないと、白い図形が画面に出る)。

## パラメータ

| パラメータ | 既定 | 意味 |
| --- | --- | --- |
| Memory | true | 探索の記憶(灰色の地形)。false なら従来どおり視界の外は真っ暗 |
| Grayscale | true | 記憶した地形を灰色にする |
| MemoryOpacity | 0.45 | 記憶した地形の明るさ(通常に対する割合。灰色にしたうえで、この割合まで暗くする。フィルターの中で下げる) |
| FeatherPixels | 6 | 視界の縁のぼかしの幅(px)。視界の内側へ向かって滑らかにする。0 = 従来の硬い縁。0〜32 |
| PlayerOverlay | true | 壁のすぐ近くで主人公が隠れないよう、主人公(と持っている武器)だけを暗闇の上へ重ねて描く |
| HideEntities | true | 視界の外の敵・イベントを描かない |
| ExploreRangeTiles | 0 | 記憶に入れる距離(0 = 視界のすべて) |
| ExtraOpaqueRegionIds | (なし) | 視界(霧)だけを遮る追加のリージョンID(カンマ区切り。250 は使えない) |

視界の距離・角度・壁のリージョン・暗闇の濃さは、`ProjectR_VisionOcclusion` のパラメータとプラグインコマンドです。

`getTileState(x,y)`("unexplored" / "explored" / "visible")・`isExplored` / `isVisibleTile`・`isEventVisible(event)`・`isPointVisible(x,y)`・`getExploredCount(mapId?)`・`clearExplored(mapId?)` / `clearAll()` / `flush()`・`getStats()`・`setConfig({memory, grayscale, hideEntities, memoryOpacity, exploreRange, feather})` / `resetConfig()`(DEV。保存しない)。

## 既知の制限

- `ProjectR_CombatPresence`(銃の表示・武器の使用可否)は、画面内の生きている敵を**見えているかどうかに関係なく**数えます。このファイルは別の保護テストで固定されているため触っていません。隠れた敵だけが画面内にいると、銃が構えられることがあります(位置は分からない)。
- `ExtraOpaqueRegionIds` は視界(霧)の計算だけに効きます。`ProjectR.CombatOcclusion.firstBlockerBetween(mode:"vision")` など、CombatOcclusion 内部の判定には効きません。
- 敵の可視判定は体の当たり判定(hitbox)の点で行います。画像が当たり判定より大きいとき、画像の端が見える/隠れるタイミングは、当たり判定の端と少しずれます。
- Hendrix 以外の独自のスプライト(ProjectR の演出など)は、`_character` を持たないので隠せません(敵のスプライト・HPバー・その子は隠れます)。
- 地形の変更(イベントによるタイルの書き換え)は、記憶の地形にも**現在の状態**で出ます(見た時点の絵は保存しません)。
- 動く敵が視界の端に出入りする瞬間は、1フレームぶん(視界の計算は描画の更新のあと)遅れることがあります。

## 手動 Playtest の手順

1. Playtest(ニューゲーム)で Map001 を開き、F8 の Console に次を入れて、壁を作る(x=40 の縦の壁、y=10〜24)。

   ```js
   (function(){ var w=$gameMap.width(), h=$gameMap.height(), d=$gameMap.data(); for (var y=10;y<=24;y++) d[(5*h+y)*w+40]=255; ProjectR.VisionOcclusion.invalidateCache(); ProjectR.FogOfWar.clearAll(); $gamePlayer.locate(36,17); })()
   ```
2. 壁の手前では、壁の向こうが**真っ黒**(未探索)。敵(52,18 の公式銃テスト敵)は見えない。
3. 壁の南(y=26 より下)を回り込んで東側を見てから戻ると、見た場所が**灰色の地形**として残り、敵は出ない。見ていない場所は黒のまま。
4. `ProjectRFieldCombat.attachEnemy(2)` を実行して敵に行動をつけ、壁の向こうから近づいてくる様子を確認する(隠れている間は見えず、壁の端を越えると見える。HPバー・赤い予兆は出ない)。
5. マップ移動(31,19 の扉)で別マップへ行って戻ると、探索の記憶が残っている。
6. セーブして、ロードしても記憶が残る(テスト中のセーブは、保護セーブを上書きしないよう、別のスロットで)。
7. 設定を試す: `ProjectR.FogOfWar.setConfig({ grayscale:false })`(記憶した地形が色つき)、`setConfig({ memory:false })`(従来どおり真っ暗)。`resetConfig()` で戻す。
