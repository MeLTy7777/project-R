# ProjectR_CommunicationRank(Stage 5-B2)

ヒロインや NPC の「通信ランク」を、RPG ツクール MZ の**標準のゲーム変数**で管理する土台です。

- プラグイン: `js/plugins/ProjectR_CommunicationRank.js`
- ランクはゲーム変数なので、通常のセーブ/ロードでそのまま保存されます。独自のセーブ領域はありません。
- 現在、ヒロイン 4 人を登録しています(ランクはゲーム変数 101〜104、上限は 10)。キーの一覧は [ヒロイン通信の設計書](ProjectR_HeroineCommunicationDesign.md) にあります。登録していないキーのコマンドは `-1` になります。
- ランクを上げても、指輪の入手やスキルのレベル上げは自動では起きません。

## 設定(プラグインの管理 → ProjectR_CommunicationRank → 通信ランクの登録)

1件につき次の3つを入れます。

| 項目 | 内容 |
|---|---|
| キャラクターキー | コマンドで指定する文字列。ほかの登録と重ならないもの。大文字と小文字は区別し、前後の空白は無視する |
| ランクを保存する変数 | そのキャラクター専用のゲーム変数(データベースの範囲内。足りなければデータベースの変数の最大数を増やす) |
| ランクの上限 | 1 以上。0(未設定)の登録は使えない |

- ランクは `0`(まだ何もない)〜上限の整数です。変数の初期値の 0 がそのままランク 0 になります。
- 次の登録は誤りです: キーが空 / 変数が未設定・範囲外 / 上限が未設定 / **同じキーが2件** / **同じ変数を2件で使う** / 読めない行。
- 誤りは、テストプレイのコンソール(F8)で `ProjectRCommunicationRank.problems()` を実行すると一覧で確認できます。

## 登録の誤りは全体を停止します(fail closed)

登録表が読めない(JSON が壊れている)場合や、**誤りのある登録が1件でもある**場合は、守るべきランク用の変数がどれか分かりません。そのため、正しい登録も含めて全部を停止します。

| 対象 | 停止中の動き |
|---|---|
| `ReadRank` / `RaiseRankToMinimum` | 何も書かず、そのイベントの処理を中断する |
| `ProjectR_RingRewards` の `AcquireRing` / `RaiseSkillLevel`(hermes のスキルを含む) | 同じ |
| API | 戻り値が `code: -1`、`status: "rankConfigurationInvalid"`、`abortEvent: true`。何も書かない |

- 変わらないもの: ランク、結果コードの変数、「ランクを入れる変数」、スイッチ、指輪、スキルのレベル。
- 結果コードの変数も書かないので、前に実行したときの `1` や `2` が残ります。それを後ろの条件分岐が読まないように、イベントを中断します。
- **空の登録 `[]` は誤りではありません。** 通信ランクの各キーは未登録の `-1` になり、`RingRewards` はそのまま使えます。
- 作りかけの行(変数や上限が未設定)を残したままでも停止します。登録を編集したら、`problems()` が空になることを確かめてください。

## コマンド1: 通信ランクを読み取る(`ReadRank`)

| 引数 | 内容 |
|---|---|
| キャラクターキー | 登録したキー |
| ランクを入れる変数 | **必須**。今のランクが入る。失敗したときは `-1` が入る(前に読んだ値を残さないため) |
| 結果コードを入れる変数(任意) | 0 なら書かない |
| 成功で ON にするスイッチ(任意) | 読み取れたときだけ ON |

ランクは変えません。

## コマンド2: 通信ランクを指定の値まで引き上げる(`RaiseRankToMinimum`)

| 引数 | 内容 |
|---|---|
| キャラクターキー | 登録したキー |
| 引き上げる値 | 1 以上、そのキャラクターの上限以下。0(未設定)は何もしない |
| 結果コードを入れる変数 / 完了にするスイッチ(任意) | 結果が `1` か `2` のときだけスイッチを ON |

- ランクは `max(いまの値, 指定の値)` になります。下げません。同じイベントを何度実行しても増えません。
- 上限より大きい値は `-2` です(上限に切り詰めません)。
- 上限より大きい値がすでに入っている場合(直接の書き換えや、後で上限を下げた場合)は、`2` でそのままにします。
- 戦闘中の制限はありません(ランクは戦闘に影響しないため)。

## 結果コード

| コード | 意味 |
|---|---|
| 1 | 成功(読み取れた / 引き上げた) |
| 2 | すでに指定の値以上(引き上げのみ) |
| -1 | 設定が足りない・誤り(登録が無い・登録表の誤り・出力先の誤り・引き上げる値が未設定)。登録表の誤りの場合は、結果コードの変数に書かずに中断する |
| -2 | 入力が不正(キーが空・引き上げる値が不正や上限超え) |
| -7 | ランクの変数に、0 以上の整数でない値が入っている(上書きしない) |
| -9 | そのほかの失敗 |

`-1` `-2` `-9` の意味は、`ProjectR_RingRewards` の結果コードと合わせています。

## 重なりの防止(登録に誤りが無い場合)

次の指定は、ランクが結果コードで壊れたり、残ったランクの値が成功に見えたりするため、**何も変えずに拒否し、そのイベントの処理を中断します**(標準の「イベント処理の中断」と同じ)。

- 通信ランクのコマンド: 結果コードの変数、または「ランクを入れる変数」が、**登録したどれかのランク変数**
- `ProjectR_RingRewards` の指輪の入手・レベル上げ: 結果コードの変数が、登録したどれかのランク変数

注意:

- 中断すると、そのイベントの後ろの台詞やフェードの後始末も実行されません。コモンイベント内で呼んだ場合は、そのコモンイベントだけが止まり、呼び出し元は続きます。
- 自動実行・並列処理のイベントでは、直すまで同じ警告が繰り返し出ます(自動実行は操作できなくなります)。
- API(スクリプト)を直接呼んだ場合は中断しません。戻り値の `ok` と `abortEvent` を確かめてください。
- 標準の「変数の操作」コマンドで、ランクの変数を直接書き換えること(下げることを含む)は防げません。ランクはこのコマンドで上げてください。
- 結果コードの変数や完了スイッチに、使えない番号を指定した場合は、何も変えずに `-1` にします(この場合は中断しません)。

## 指輪とスキルの報酬との組み合わせ

| 報酬 | 起こし方 |
|---|---|
| Hermes の指輪 | 本編の入手のまま(通信ランクは使わない) |
| Apollo / Janus / Themis / Athena の指輪 | 決まったイベントで `AcquireRing` を呼ぶ。「ランクを保存している変数」には、**対応するキャラクターの登録と同じ変数**を指定し、必要ランクを指定する |
| スキルの Lv2 / Lv3 | 決まったキャラクターのイベントで `RaiseSkillLevel` を呼ぶ(指輪の所持が必要)。ランクが上がっただけでは上がらない |

`AcquireRing` はキャラクターキーではなく変数の番号を受け取ります。指定する番号を間違えると別のキャラクターのランクで判定されるので、イベントを作ったらテストプレイで確かめてください。

イベントの例(ランクが上がる会話):

1. `RaiseRankToMinimum`(キー、引き上げる値、結果コードの変数、完了スイッチ)
2. (指輪を渡す会話なら)`AcquireRing`(指輪、そのキャラクターのランク変数、必要ランク、結果コードの変数、完了スイッチ)
3. 結果コードの変数で条件分岐して台詞を出す

結果コードの変数は、どのランク変数とも別の番号を使ってください。

## まだ決まっていないこと

- 4 人のほかに登録する人物(NPC など)があるか
- 各指輪の必要ランク(対応する人物は決定済み)
- どのイベントでランクをいくつまで上げるか、どのスキルを何レベルにするか
- イベントを置くマップ
