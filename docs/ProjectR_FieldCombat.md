# ProjectR リアルタイム・フィールド戦闘(FieldCombat) v0.6.0

戦闘を、マップ上で連続して戦う**リアルタイム・アクション**(BAPBAP の操作感を参考)へ戻すための土台です。
ATTACK/DEFENSE の区切りも、カードのドロー・ランダムな手札も使いません。SOUL / SOUL RUSH は**コードもセーブデータも消さず**、通常のプレイでは開始できないようにしました。

- プラグイン: `js/plugins/ProjectR_FieldCombat.js`(新規。ProjectR_* の最後に登録)
- 実機の確認: `tools/mz_cdp/field_combat_verify.cjs`(40項目) / Node: `tests/ProjectR_FieldCombat.test.cjs`(16項目。従来の実エンジンのテスト用 `tests/RealEngineHarness.cjs` は、起動後に SOUL を許可し自動開始を切る)

## エンカウンター(戦闘マップ専用)

**戦闘は、NPCとの会話・物語のイベントから入る「専用の戦闘マップ」の中だけ**です(v0.2.0)。以前の「近くに敵がいれば自動で戦闘になる」は廃止しました。

- **探索マップ**: 近くに敵がいても戦闘は始まりません。戦闘の入力(Q/E/R/C/Shift・左クリック・右クリック)は無効です(CombatPresence の「画面内に敵がいれば武器が使える」も、エンカウンター中以外は止めます)。**移動・NPC・イベント・メニューは普通のまま**です。
- **流れ**: ①イベントで「エンカウンターを始める」→ 元のマップ・位置・向き(実座標も)を記録して、戦闘マップへ移動 → ②戦闘マップの準備が終わる(移動・フェード・開始時のイベント/メッセージのあと)と、戦闘・敵の行動・アビリティ・HUD が有効になる → ③敵を全員倒すと勝利(結果を**1回だけ**処理 → 戦闘を片づける → 元のマップ・位置・向きへ戻る → 結果の変数・コモンイベント)。
- **敗北**(HPが0): 自動では戻りません(既存の死亡・ロードの扱いのまま)。戦闘は片づき、結果の変数=2、エンカウンター中の**セーブ禁止は続き**、ロード/ニューゲームですべて初期状態に戻ります。
- **中断・撤退・特別な終わり方**: 「エンカウンターを終える」(勝利/中断)、「エンカウンターを中断する」。想定外のマップ移動(戦闘中に別のマップへ)・外からの戦闘の終了・ロードでは、戦闘が探索マップに残らないように片づけます(結果=中断を1回だけ)。
- **セーブ**: エンカウンター中(敗北のあとも、ロードまで)は、メニューからも「セーブ画面を開く」イベントコマンドからも保存できません(SOUL のエンカウンターと同じ方式)。

### プラグインコマンド

| コマンド | 内容 |
| --- | --- |
| フィールド戦闘: エンカウンターを始める(StartFieldEncounter) | 元のマップ・位置・向きを記録。戦闘マップ(Map ID)・出現位置・向き・結果を入れる変数・勝利/中断後のコモンイベントを指定。戦闘マップを 0 にすると「armed」で待つ |
| フィールド戦闘: 戦闘マップへ移動する(TransferToBattleMap) | 「始める」で戦闘マップを指定しなかったときに、移動先を指定して移動 |
| フィールド戦闘: エンカウンターを終える(CompleteFieldEncounter) | 結果(勝利 / 中断・撤退)を指定して、元のマップへ戻る。ボス戦・撤退などの特別な終わり方用 |
| フィールド戦闘: 敵の行動をつける(AttachFieldEnemy) | イベント(0=このイベント)を、近づいて溜めて攻撃する敵にする(メモの `<fieldEnemy>` と同じ) |
| フィールド戦闘: エンカウンターを中断する(AbortFieldEncounter) | 戦闘を片づけて元のマップへ戻る(結果=中断) |

結果の変数: 1=勝利 / 2=敗北 / 3=中断(戦闘中は 0)。**このプロジェクトの変数は 1〜20 だけです**(`$dataSystem.variables` の数。21番以降は使えません)。10〜20 は SOUL などが使用中なので、DEV の入口は 9 番を使っています。

### イベントの設定手順(F8 不要)

**戦闘マップを作る**
1. 新しいマップを作り、**マップのメモ**に `<fieldBattleMap>` と書く(印の無いマップは、戦闘を始めずに元へ戻ります。パラメータ RequireBattleMapTag)。
2. 敵にするイベントを置く。イベントの**メモ**に Hendrix の敵の印(`<hp: 敵名>` と `<enemy>`。武器・奥義が当たるように)と、フィールド戦闘の印 `<fieldEnemy>` を書く。数値を変えるときは `<fieldEnemy: windup=36, cooldown=120, reach=1.2, aggro=10, chase=1>`(すべて省略可。windup=溜め・cooldown=攻撃後の間(いずれもフレーム)・reach=届く距離(tile)・aggro=追いかける距離・chase=0で動かない)。有効なページの**注釈**に書いても有効です。プラグインコマンド「敵の行動をつける」でも指定できます。
3. 戦闘マップの準備が終わると、印のついた敵に行動がつきます。**印のついた敵を全員倒すと勝利**です。敵が1体もいない/ボス戦などは、イベントから「エンカウンターを終える」を呼びます。
4. (任意)撤退用のNPC: 話しかけると「エンカウンターを中断する」を呼ぶイベントを置く。

**入口(NPC・物語のイベント)を作る**
1. 探索マップのイベントで、会話などのあとに「エンカウンターを始める」を**最後のほうのコマンド**として置く(戦闘マップ・出現位置・結果の変数を指定)。移動はイベントが終わってから実行されます。
2. 戻ったあとの処理は、結果の変数(1/2/3)を条件にしたイベントのページ、またはコモンイベント(勝利後/中断後)で行う。
3. ヘルメースの指輪(奥義 E のため)・ポーションが必要なら、入口のイベントで与える(DEV の入口の例を参照)。

### 近接3段コンボ(左クリック)

- **1クリック = ちょうど1回の斬撃**: Hendrix の「攻撃」ボタンは、押した瞬間に1回だけ共通イベント1を予約します(`triggered`)。戦闘中は、その予約を `ProjectR_FieldCombat` が受けて、近接の1段を出します(元の経路 = 銃・旧共通イベントへは渡さない)。**押しっぱなしでは進みません**(実機: 1.5秒押し続けて斬撃1回)。J キー・ゲームパッドの攻撃ボタンも同じ経路です。
- **見た目 = 薙ぎ払いの VFX**(Stage 5b。Stage 5c で判定と一致): ヘルメースの「薙ぎ払い」と同じ VFX(`hermes_sweep.staff` 〔中心だけ判定に合わせた別名〕+ ケーリュケイオンの Swing Weapon + SE `Slash2`)を、クリックのたびに出します(強撃は反対側にもう1回=一回転)。`PresentationVfx` が無いときだけ、SwordSystem の従来の見た目(Swing Weapon)に戻ります。**当たり判定は、この見た目と同じ扇形**です(下の「Stage 5c」)。
- **段**(`COMBO`): 1段目・2段目 = 扇形の横薙ぎ(時計回り。VFX の素材が時計回りなので、判定も同じ向き)/ **3段目 = 強撃**(反対側にもう1回の扇 = 一回転。ダメージ × `ComboFinisherDamage`(既定 2)、間 30 フレーム)。〔VFX が無いときの従来の長方形 Hitbox: 1段目 幅 1.5 × 奥行 1.2・2段目 1.7 × 1.3・3段目 2.4 × 1.9〕1・2段目は**従来と同じダメージの式**(`-player weapon`)、3段目だけ `-Math.round(player weapon * 倍率)` です(Hendrix が武器ダメージの数値に置き換える)。「1振り1ヒット」・ダメージの追跡(奥義ゲージ・絶の強化)は既存の `ProjectR_SwordSystem` のままです(扇形の判定も同じ経路)。
- **段の進み**: 斬撃が**出たときだけ**進みます(間隔 18 フレームの内の連打など、出なかったクリックは段を進めない・数えない)。3段目のあとは1段目へ戻ります。前の斬撃から `ComboTimeout`(既定 0.8 秒)を過ぎても1段目へ戻ります。戦闘が始まるたびに、コンボは初期状態です。
- **銃を装備していても出ます**: 斬撃の `swing(source, { anyWeapon: true, ... })` で、近接用の武器を装備していなくても出せます。**ダメージは、装備している武器の攻撃力**(Hendrix の `player weapon`。銃を持っていれば銃の攻撃力)です。近接専用の武器スロット(持ち替え)は、まだ作っていません。
- 放射メニューを開いている間・プレイヤーが倒れている間は出ません。

### 右クリック(銃)と R(リロード)

- 右クリックは `document` の `mousedown`(button 2)で受け、**フレームの更新の中で**1発撃ちます(メッセージ・メニュー・会話中は撃たない)。マウスのボタンは押しっぱなしで `mousedown` が繰り返されないので、**1クリック = 1発**です。`contextmenu` は、戦闘中だけ `preventDefault` します。マップの「右クリックでメニュー」(`Scene_Map.isMenuCalled` の `TouchInput.isCancelled`)も、戦闘中だけ止めます(Esc のメニューは従来どおり)。
- 銃を装備していなければ何も起きません(HUD は NO GUN)。空撃ちの自動リロード(`AutoReloadOnEmpty`)・弾の飛び方・命中は既存のままです。
- R は `ProjectRGunSystem.requestReload("field")` を呼ぶだけです(銃側の R キーの受け口は、戦闘中は `ProjectR_FieldCombat` が先に受けるので、二重にはなりません)。リロードに Cooldown はありません。

### V: アイテムと放射メニュー(Stage 5c で C から V へ)

- **一覧に出るアイテム**(実際の持ち物から読む): 通常アイテム(`itypeId` 1)・消耗する・いつでも使える(`occasion` 0)・対象が味方1人/全体/自分(`scope` 7/8/11)。「-----」で始まる区切り・メニュー専用・戦闘専用・敵が対象・大事なもの・弾薬は出ません。最大 12 個(アイテムの番号順)。
- **選んでいるアイテム**: 放射メニューで選んだもの → なければ `ConsumableItemId` → なければ持っている HP 回復薬 → 最初の消耗品。選んだアイテムは、そのセッションの間(戦闘をまたいで)残ります(**保存しません**)。持っている数が 0 になっても、選び直すまでそのまま(×0・使えない表示)です。
- **短押し**(0.3秒より短く離す): 選んでいるアイテムを使います。使えない理由は `noItem`(在庫なし)/ `cannotUse` / `noEffect`(HP 満タンなど。**消費しない・Cooldown も始めない**)/ `cooldown`。成功すると、**どのアイテムも共通の Cooldown**(`ConsumableCooldown`、既定 8 秒)が始まります。
- **長押し**(`ItemHoldSeconds`、既定 0.3 秒 = 18 フレーム): 放射メニューが開きます。輪の中心は、開いた瞬間のマウスの位置(画面の外へはみ出さないように寄せる)。**マウスを動かした方向**のアイテムが光ります(真上が1番目、時計回り)。中心の小さな円の中(動かさない)は、何も選びません。**C を離す**と、光っているアイテムを「選んだ状態」にします(**使わない・個数も Cooldown も変わらない**)。
- **取り消し**: 動かさずに離す・右クリック(撃たずに閉じる)・Esc では、選んでいるアイテムは変わりません(X は固定カード1のキーなので、メニュー中は何もしません)。メッセージ・会話・イベントが始まる、ロード・シーン切り替え(`Input.clear`)、ウィンドウが外れる(`blur`)、戦闘が終わると、閉じます(選択は変えない)。
- **持ち物が変わる**: 開いている間も、0.1 秒ごとに一覧を読み直します(増えれば加わり、使い切れば消える)。**アイテムが無くても**開きます(「アイテムなし」)。使えない状態のアイテム(`canUse` が false)は暗く表示しますが、選ぶことはできます。
- **衝突の防止**: 放射メニューを開いている間は、**右クリック(銃)・左クリック・Q/E/R/Shift/X/C を受け付けません**(キーは受け取って何もしない。元の Input へも渡さない)。閉じれば、すぐ元どおりです。

### 入力の衝突の解決(マップ戦闘中だけ)

- Q / E / R / X / C / V / Shift と右クリックは、フィールド戦闘中だけ `ProjectR_FieldCombat` が先に受け取ります。戦闘外・メッセージ/メニュー/会話/イベント中・Ctrl/Alt つきは、元のまま(MZ・Hendrix)へ渡します(**Shift は絶のキーなので、修飾キーとして断りません**。Shift を押したままの E・X・C・R なども受け取ります)。
- 戦闘中はカード戦闘の入力(`ProjectR_CardBattleInput` の Q/E/X/C/V)は何も起こしません(手札が空のため)。**X はMZの元の割り当て(キャンセル / メニュー)を、エンカウンター中だけ固定カード1に使います**(キー入力を先に受け取り、元の Input へ渡さない)。戦闘外・メッセージ・メニュー・会話・イベント中は、X は従来どおり(キャンセル / メニューを開く)。V・C に元の割り当てはありません(Hendrix の文字キーのみ)。
- 戦闘中は主人公の向きがマウスに固定されるため、DotMove の「接触」イベント(扉・場所移動)は、マウスと違う向きに歩くと発火しませんでした。戦闘中だけ「移動キーを押しているのに進めなかったとき、押している方向の前方の接触イベントを起こす」補助があります。
- F(決定)は、照準している方向(主人公の向き)の隣のイベントを調べます。

## 固定アビリティのしくみ

カード効果(一閃・絶)は「手札のカードを使う」前提で作られています(使ったあとに消費・ダメージの確定など)。そこで、`ProjectR_FieldCombat` が、`ProjectR_CardDeckCore` の公開している `BattleDeckSession` を広げて**固定戦闘の窓口**を足します(CardDeckCore のファイルは変更しません。既存の戦闘は変わりません)。

- `ProjectRCardDeck.startCardBattle(ProjectRCardDeck.FIXED_BATTLE)` … デッキの検証なし・山札なしの「固定戦闘」を始める。
- `ProjectRCardDeck.useFixedCard(cardId)` … 固定戦闘の中で、そのカードの効果(既存の handler と、それを包む後処理)を1回使う。カードは手札に残り(消費・Cooldown山・ドローなし)、所持・指輪に依らない。Cooldown はこのプラグインがスロットごとに持つ。
- 通常の戦闘(手札の戦闘)では `useFixedCard` は使えません。

## 敵と予兆

- 敵は既存の `<enemy>` つきのイベント(Map001 の「公式銃テスト敵」)。`ProjectRFieldCombat.attachEnemy(eventId)` で、メモリ上だけ「近づく → 範囲に入ったら溜めて(予兆)→ 近接攻撃 → Cooldown」の行動をつけます(`ProjectREnemyAttack` の予約を使う)。溜めの間は動きません。元の並列ページの攻撃は止めます(二重にならないように)。
- 予兆は、予約の記録(`ProjectREnemyAttack.list()` の pending)をそのまま赤い範囲で画面に描きます。予約が取り消されれば予兆も消えます。範囲は攻撃が実際に当たる範囲(同じ記録)です。
- 注意: 「テスト用ゴブリン」(Map001 のイベント1)には `<enemy>` が無く、武器・奥義が当たりません(旧テスト敵)。基準の敵には「公式銃テスト敵」(イベント2)を使います。

## 敵の視界(v0.2.4)

敵は、次の3つがそろっている間だけ、プレイヤーを追い、攻撃します(従来は、壁越しでも距離内なら追っていた)。

1. **距離**: 視界の距離(既定 10 tile)の内側。
2. **視野角**: 敵の向き(イベントの向き)を中心にした視野角(既定 140°)の内側。**見つける瞬間だけ**見る。見つけたあとは、プレイヤーの方を向いて追う(見失うまで視野角は問わない)。
3. **視線**: 敵とプレイヤーを結ぶ線が、壁(Region 255)・閉じた扉(`<VisionWall>`)に遮られていない。開いた扉は視線を通す。判定は `ProjectR.CombatOcclusion.hasLineOfSight`(vision モード)で、**プレイヤーの霧(FogOfWar)とは無関係**。

- **見失うと**: その場ですぐ(1フレーム以内に)追うのをやめて、待つ。**最後に見た位置を覚えない・探さない**(見失っている間にプレイヤーがどこへ動いても、敵は動かない・向きも変えない)。
- **見えるようになると**: また見つけて追う。溜め(windup)の最中に見失ったときは、その攻撃だけは撃ち終える(従来どおり)。閉じた扉越しは、届く距離でも攻撃を始めない。
- **攻撃・ダメージ・HP・クールダウン・勝利の判定は変えていません**(攻撃を始める条件に「見えている」を足しただけ)。
- **設定**: プラグインパラメータ `EnemyPerception`(既定 true。false で従来)・`EnemySightTiles`(10)・`EnemyFovDegrees`(140)。敵ごと: イベントのメモ `<fieldEnemy: sight=8, fov=90>`(`aggro=N` も距離として使える)/ プラグインコマンド「敵の行動をつける」の「視界の距離・視野角」。敵ごとの設定は全体の設定に優先。
- **API**: `getEnemyPerception(eventId)`(aware / sees / reason(seen・range・blocked・fov)/ 距離 / 向き / 見つけた回数 / 見失った回数)・`getPerception()`・`setPerception({enabled, sightTiles, fovDegrees})`・`resetPerception()`(DEV。保存しない)。

## 敵の経路探索(v0.3.0。Stage 4)

敵が「いま見えている」間に、まっすぐ進めない(柱・家具・扉の枠の角・味方の敵などの通れない所がある)ときだけ、それをよけて回り込みます。**追うかどうかは、上の視界がすべて決めます**(視界の距離・視野角・壁・閉じた扉の判定は、いっさい変えていません)。

**方法**

1. **まっすぐ進める間は、従来どおり**(DotMove の `dotMoveToPlayer`)。「まっすぐ進める」= 敵の体(1マス以下)の四角を、敵からプレイヤーへ 0.25 tile おきに動かして、どの位置でも「どの向きにも通れるマス」だけに乗っていること(通行は `$gameMap.isPassable`、通れないイベント = 閉じた扉・NPC なども含む)。4 フレームごとに調べます。
2. **まっすぐ進めないときだけ**、タイルの格子で **A*(8方向)** を探索します。斜めは、となりの2マスと斜め先が通れるときだけ(壁の角をまたがない)。範囲はプレイヤーまわり(敵とプレイヤーを含む四角 + 8 マス)・最大 1500 ノード。目標のマス(プレイヤーのいるマス)へ届かないとき(囲まれている・上限)は、**いちばん近づけるマスまで**の経路にして、そこで待ちます。
3. 求めた経路は、**まっすぐ行ける最も遠い曲がり角**だけを結んだ折れ線にして、DotMove の通常の移動(`dotMoveByDeg` = 通常の衝突判定)で進みます(位置を直接書き換えない)。曲がり角では、折れ線からの横のずれを 1 歩の中で少しずつ戻すので、1マス幅の通路でも壁にこすりません。経路を進む間は、進む向きを向きます。
4. **見失った瞬間に、経路を捨ててその場で止まります。** 経路の目標は、見えている間の「いまの」プレイヤーのマスだけです。最後に見た位置を覚えず、隠れている間にプレイヤーがどこへ動いても向かいません。見えるようになると、また見つけて、**そのときのプレイヤーの位置へ**探し直します。
5. 探し直しは、(a) プレイヤーが別のマスへ動いて前回から 12 フレーム以上たったとき (b) 次の曲がり角のマスが通れなくなったとき(扉が閉じる等。10フレームごとに確認)(c) 経路の終わりに着いたとき、だけです。敵ごとに 12 フレーム以上あけ、**全体で 1 フレームに 3 回まで**(予算切れの敵は、古い経路で進むか待つ)。経路がなければ 30 フレーム待ってから探し直します。
6. **ふさがれたとき**: 進もうとしたのに 24 フレーム進めなければ(味方の敵が戸口・通路にいる等)、60 フレームのあいだ、味方の敵も通れない所として探し直します(回り込む)。よける道がなければ、押しつけずに待ちます。

**使う条件**: エンカウンター中(`begin` 済み)・敵の視界が有効(`EnemyPerception=true`)・ループしないマス・体が 1 マス以下の敵・DotMove のある敵。**それ以外は、従来のまっすぐの追跡**のままです(視界を切ると従来)。攻撃の溜め・Cooldown・ダメージ・敵の死・勝利・繰り返しのエンカウンター・予兆は変えていません(溜めの間は動かず、経路も持ちません)。

- **設定**: プラグインパラメータ `EnemyPathfinding`(既定 true)。敵ごと: イベントのメモ `<fieldEnemy: path=0>` または `attachEnemy(id, { pathfinding: false })` でその敵だけ従来のまっすぐ。
- **API**(DEV・検証用。保存しない): `getEnemyNav(eventId)`(mode = direct / path / idle・経路の長さ・残り・曲がり角・目標・探した回数・止まりを検出した回数・見失った回数)・`getNavStats()`(探索回数・展開したノード・探索時間・1フレームの最大の探索回数と時間・まっすぐ/経路/待ちのフレーム数・止まりの回数・例外の数)・`resetNavStats()`・`findNavPath(from, to, { avoidEnemies, allowPartial })`(動かさず、経路だけ)・`setPathfinding(on)`・`isPathfinding()`・`invalidateNavCache()`(実行中にタイルを書き換えたとき)。
- **性能**(実機 Chromium 85・敵3体が柱をよけて追う 4 秒): 経路 1 回の計算は 約 0.06 ms(戦闘マップの端から端)。1 フレーム全体(Scene_Map.update)の平均は、経路探索あり 1.64 ms / なし 1.60 ms(差 約 +0.05 ms)・60fps のまま。1 フレームの経路探索の最大は 約 1.8 ms(3 体が同時に探した瞬間)。まっすぐ進める間は、4 フレームごとの「まっすぐ進めるか」の確認だけです。

**限界(仕様)**

- **視界を変えないので、視線が切れたら止まります。** 不透明な壁(Region 255)・閉じた扉の向こうへ回り込む追跡はしません。たとえば、壁の角を曲がって逃げたプレイヤーを、敵は追いません(見えなくなった瞬間に止まる)。見えている間にできるのは、**視線は通るが通れない物(柱・家具・低い壁・味方の敵など)をよけること**だけです。壁の向こうの追跡をさせたいときは、視界の仕様(最後に見た位置へ向かう等)を別に決めてから足します。
- 経路の計算は、タイルの通行(`isPassable`)と、止まっているイベント(扉・NPC)の位置だけです。動くイベント(歩き回る NPC など)は、探索した瞬間の位置の写しで、10フレームごとに確認します。味方の敵は、止まったときだけよけます。
- 体が 1 マスより大きい敵・ループするマスは、従来のまっすぐの追跡です。
- 実行中にタイルを書き換えたとき(通常はありません)は、`invalidateNavCache()` を呼んでください(通行の記憶は 120 フレームで作り直します)。Hendrix の通行キャッシュも、書き換えたマスは `$gameMap.clearPassageCacheForPosition(x, y)` で消す必要があります。
- 向き: まっすぐ進んでいる間は従来どおりプレイヤーの方を向きます。経路を進んでいる間は進む向きを向き、攻撃の範囲(reach)に入ったら、プレイヤーの方を向いて溜めに入ります。

## 扉口の渋滞の解消(v0.3.1。Stage 4b)

Map008 の扉口(8,7)に敵が並ぶと、次の 2 つの渋滞が起きていました(実機で再現)。

| 症状 | 原因 | 直し方 |
|---|---|---|
| 敵の列が扉口で固まり、動かない | 視界の仕様で、**見失った敵はその場で止まる**。扉口に縦に並んだ敵は、プレイヤーが扉の正面の線から外れた瞬間に全員が見失い、そのまま**扉口をふさぎ続けた** | 見失って扉口(通路のマス)に立っている敵だけ、いちばん近い「出入口でないマス」へ**道を空ける**(下) |
| プレイヤーが扉口で動けない | 扉口で前後を敵にはさまれると、DotMove の通常の衝突(敵は通れない物)で、攻撃以外に抜ける道がなかった | 抜けられなくなったときだけ、行く手の敵を**プレイヤーが通り抜けられる**(下) |

倒した敵が通行をふさぐ問題は、再現しませんでした(Stage 3 の修正どおり、すぐ通れる)。ただし、DotMove の `setThrough` は「動いている間は、移動が終わってから」に予約するので、**倒した敵は予約を待たず `_through` を直接 true にし、予約も消す**ようにしました(経路探索の地図の写しも捨てる)。実機で、倒した次のフレームまでに通れることを確認しています(約 30ms)。

**1. 道を空ける(見失った敵)**
- 対象: 敵の視界が無効でなく、見失っていて(`aware=false`)、溜め中でなく、体が**通路のマス**(通れる上下か左右の 2 方向だけが向かい合っているマス = 扉口・1マス幅の通路)に 3 割以上かかっている敵(扉口の手前で、体が少しかかっているだけの敵は動きません)。
- 動き: いちばん近い「通路でないマス」(5 マス以内)へ移動する。**追跡ではない**: プレイヤーの位置は使いません(プレイヤーがどこにいても、同じ動き)。同じ近さなら、元の持ち場(攻撃開始時の位置)に近い側。味方の敵・通れない物のあるマスは使いません。20 フレーム進めなければ、その出口はあきらめて別の出口を探します。出たあとは 30 フレーム動きません(行ったり来たりしない)。
- 見えるようになれば、道を空ける動きは捨てて、また追います(視界は従来どおり)。北の部屋など、通路でない所で固まっている敵は、動きません。

**2. 通り抜け(プレイヤーがはさまれたとき)**
- 条件: ① 移動キーを押しているのに 24 フレーム(約 0.4 秒)進めない ② 行く手に敵がいる(押している向き) ③ 進めないのが敵のせい(壁・扉・柱で止まっているのではない) ④ 通路のマスで起きている(プレイヤーか敵が通路のマス)か、2 体以上に囲まれている。
- 動き: 行く手の敵だけ、Hendrix の既存の仕組み `$gameSystem._playerPassThroughEvents` に入れる(プレイヤーだけが、その敵を通り抜けられる)。**壁・閉じた扉・柱は通れないまま**・敵の `_through`(攻撃の当たり判定に関わる)も、敵同士の衝突も変えません。
- 戻す: 体が重ならなくなったら(最短 20 フレーム)・敵が倒れたら・敵を外したら・**戦闘が終わったら**(セーブデータに残さない。もとからあった別のイベントは残す)・600 フレームたったら。
- 広い所で 1 体に当たっているだけのときは使いません(横へ回れる)。

- **設定**: プラグインパラメータ `ChokeSoftCollision`(既定 true。false で従来の衝突だけ)。道を空ける動きは `EnemyPathfinding` に従います。API: `getSoftPass()`・`setSoftCollision(on)`・`getNavStats()` の `yields` / `yieldFrames` / `yieldBlocked` / `softPass` / `softEnd`・`getEnemyNav(id)` の `mode: "yield"`。
- **限界**: 通路で見張りをさせたい敵(わざと扉口に置く敵)も、見失うと通路の外へ出ます(今は止める印がありません)。通り抜けの間、プレイヤーは敵の体に重なります(攻撃の範囲は別なので、ダメージは従来どおり)。出口が全部ふさがっている(味方に囲まれている)敵は、その場で待ちます。
- **実機で再現**: tools/mz_cdp/field_traffic_verify.cjs 22/22(Stage 4b)。倒した敵は扉口でもすぐ通れる・後ろの敵と、プレイヤー(実キー W)が死体の上を通る・扉口に並んだ 3 体が、プレイヤーが線を外れると固まる(再現)→ 4.5 秒後に扉口に誰も立っていない(重ならない)・北の部屋の敵は動かない・見えれば追う・扉口ではさまれたプレイヤーが S キーで抜けられる(離れると戻る・閉じた扉と壁は通れない・戦闘が終わると一覧に残らない)・扉の開閉・全員倒して勝利・繰り返し 2 回・性能(1 フレーム全体 +0.04ms)・保存の書き込みなし。

## 8方向の向き(v0.2.5。`ProjectR_FieldFacing.js`・読み取り専用)

戦闘中のマウス照準から、プレイヤーの**8方向の向き**(N/NE/E/SE/S/SW/W/NW。テンキーの 8/9/6/3/2/1/4/7)と、正確な角度(上=0・時計回り)を出します。

- **MZ本体の向きは4方向のまま**: プレイヤーのキャラクター画像(DEV3H)は4方向で、斜めの画像(ファイル名に `8dir`)はありません。`$gamePlayer.direction()` は、既存の `ProjectR_PlayerFacing` / Hendrix の照準のまま 2/4/6/8 で、斜めの向き(1/3/7/9)を MZ本体の4方向のAPIへ渡しません。斜めの照準では、見た目は斜めの両隣の4方向のどちらか。斜めの画像(`8dir`)を使うキャラクターは、Hendrix が元から斜めの向きを持ちます(ここは何もしない)。
- **WASD と無関係**: 向きはマウスの位置だけで決まる(歩いても向きは変わらない。プレイヤーが動けば、固定したマウスとの角度は幾何学的に変わる)。斜め移動の速さ・衝突・攻撃・スキル・調べる(F)は変えていません(このプラグインは読み取り専用。向き・移動の関数を書き換えない)。
- **正確な角度**: MZ の `$gameMap.canvasToMapX` は整数のマスへ切り捨てるので、使わず、`displayX + TouchInput.x / tileWidth`(小数)で計算します(丸めると、8方向の境の近くで角度が最大1マスぶんずれる)。
- **API**: `ProjectRFieldFacing.getAim()`(active / degree / degree8 / dir8 / name / vx・vy / dir4)・`getDir8()`・`getDegree8()`・`getFacingVector()`・`toDir8(deg)`・`toName(dir8)`・`setConfig({enabled})`(DEV)。戦闘外は4方向の向きをそのまま返します。ゲームパッドは対象外(マウスだけ)。

## 神の同行(v0.2.4。`ProjectR_FieldGodCompanion.js`・表示だけ)

既存の神の表示(`ProjectR_GodSummonVisual`: 常駐=プレイヤーの子として左上に固定 / 一時召喚=スキルごとの位置)は**変更せず**、その表示Eventを毎フレーム調整する新しいプラグイン(末尾に登録)です。神のDivine HP・崩壊・復帰・スキルの効果・時間・演出は変わりません。

- **背後**: 常駐の神(Ultimate の神)を、プレイヤーの現在の向き(戦闘中は **8方向**のマウス照準。斜めも。戦闘外は4方向)の**反対側**へ置く(既定: 1.2 tile 後ろ・0.1 tile 浮かせる。斜めは距離 1.2 のまま、斜めの方向へ。**縦の余白**: 神の絵は約 44x83px(1.7 マス)で足元が基準。神が南側(北向き)では、縦の成分に比例して最大 0.9 tile 下げ(`SouthExtraTiles`)、神が北側(南向き)では最大 0.75 tile 上げる(`NorthExtraTiles`)。北向き・南向きで、合計 約 2 マス離れ、絵が足・頭に届かない)。
- **描く順番**: 神の絵(高さ約2マス・足元が基準で、上に約1.5マス伸びる)は、北向きのとき(神が南側)、以前は 0.9 tile 後ろ(足元が足の 29px 下)で、絵の上端がプレイヤーの足・脚に重なり、**前面に**描かれていた(神もプレイヤーも優先度 1 で、足元の y で並ぶため、南側の神が手前になる)。神を、プレイヤー・ほかのキャラクターの**下**(優先度 0)に描くようにした。ただし v0.2.6 の距離(合計 1.5 tile)では、実測で、神の絵の上端が靴の底より 9px 上(足に 9px かかる)だった(北向きのスクリーンショットで、神が足に接して見えた原因)。神の絵の実寸(44x83px)から、北向きは合計 2.0 tile(足との余白 15px)、南向きは合計 2.05 tile(頭との余白 14px)にした。動かないとき(無効・戦闘外)は、元の優先度・元の位置(プレイヤーの子)へ戻す。移動中・向きの変更中も毎フレーム更新。向きが変わると、瞬間移動せず、滑らかに背後へ回り込む(`Smoothing` 0.25)。
- **同じ神は1体だけ**: 同じ神の表示Event(常駐・一時召喚・追従する神)が複数あるときは、1体だけ見せる(優先: 追従する神 > 最新の一時召喚 > 常駐)。スキルの演出(一閃・絶)中は、常駐の神を**透明にして隠し**、演出が終わると背後へ戻す(隠している間も背後へ追従するので、戻るときに飛ばない)。新しい演出のスプライトが出るまでは隠さない(1フレームも神が消えない)。別の神(ヘルメースとアポロン)は、それぞれ1体。
- **後始末**: GodSummonVisual が管理していない神の表示Event(孤児)は、3フレーム後に片づける。マップ移動・エンカウンターの終了・ロード・戦闘の終了で、状態を捨てる(演出中の撤退でも、探索マップに神のEvent・スプライトは残らない)。
- **霧との関係**: 神の表示Eventは、プレイヤーの一部として、霧の「視界の外の敵・イベントを隠す」の対象から外した(演出中の神が消えていた)。未探索の暗闇は上から覆うので、神が未探索へ漏れることはない。
- **動く場所**: 既定(`FieldCombatOnly=false`)は、常駐の神がプレイヤーに付いてくる所なら**どこでも**(フィールド戦闘・旧カード戦闘・テストアリーナ)。台本の神(一時召喚・追従する神。ヴェイル等)は動かさず、同じ神が重なるときだけ、常駐の神を隠す。探索マップには、常駐の神は出ない(戦闘中だけ出る)ので、探索マップで動かすものはない(台本の神は、位置を触らず・消さない)。`FieldCombatOnly=true` なら、フィールド戦闘中だけ(それ以外は既存の左上のまま。戦闘が終わると、隠していた神を戻す)。孤児の片づけは、どちらでもフィールド戦闘中だけ。
- **パラメータ**: `Enabled`・`FieldCombatOnly`・`BehindTiles`・`LiftTiles`・`Smoothing`。API: `ProjectRFieldGodCompanion.getState() / getVisibleGods() / getDiagnostics() / setConfig()`。

- 固定カード1・2(Apollo の矢)は、使っている間だけアポロンの神の表示が出ます(戦闘のあとはヘルメースだけに戻る)。キャラクターは「ヘルメース1人」という設計とは別に、Apollo のカードを借りています(ヘルメースの攻撃カードは、一閃・薙ぎ払い・絶で使い切っています)。
- 判定の扇の中心は振った瞬間のプレイヤーのマスの中心、向きの基準はマウスとプレイヤーの足元です(足元とマスの中心の差 24px の分、マウスが近いほど向きが少しずれますが、見た目と判定は同じ向きを使います)。
- 絶が敵と重なって着地するのは、壁と敵のすきまが敵で埋まっているときだけです(重なりの救済で動けますが、見た目は重なります)。
- 近接3段コンボのダメージは、**装備している武器の攻撃力**です(銃を持っていれば銃の攻撃力)。近接専用の武器スロット(剣と銃の同時所持・持ち替え)は、まだありません。3段目の倍率(2)・間(30 フレーム)は、仮の値です(`COMBO`)。範囲(半径 4 マス・190°)は、見た目の素材に合わせています(近接としては広めです。狭めたいときは、見た目の素材か `hermes_sweep` の `radiusTiles` を替えます)。2段目も時計回りです(素材が時計回りだけのため。反時計回りの素材を足せば変えられます)。
- 右クリックの銃は、押しっぱなしの連射をしません(1クリック = 1発)。連射が必要なら別の判断です。
- 放射メニューは、アイテムを最大 12 個まで並べます(番号順)。マウスの方向だけで選びます(ゲームパッドのスティックでの選択は、まだありません)。
- 古い C(キャンセル)は廃止しました。保留中の入力を取り消す `useAbility('cancel')` は、APIだけに残してあります。
- 敵の行動は「近づいて近接攻撃」の1種類だけ(遠距離の敵は ProjectREnemyAttack の ranged で作れますが、未接続)。見えている間は、通れない物(柱・家具・扉の枠など)をよけて回り込みます(上の「敵の経路探索」)。ただし、視線が切れたら止まるので、壁・閉じた扉の向こうへの追跡はしません。
- 探索マップでは、基本攻撃(銃・剣・近接コンボ)も使えません(エンカウンター以外で戦う場面は、今は無い)。
- Map001 の既存の「銃エイム制御テスト」(銃を持つとマウスの方を向く)は、探索マップでも動きます。FieldCombat はこれを変更していません(isCombatActive を false にしたので、画面内に敵がいても向き直しが抑えられます)。
- Vision 系の制限(ProjectR_CombatPresence を変更しないため、隠れた敵だけが画面内にいると銃を構える等)は、探索マップでは武器の門で解決済みです。
- 縁のぼかしは、視界の内側へ約 6px(`FeatherPixels`)です。ぼかしの元の画像は半分の解像度なので、縁の位置は最大 約2px(画面)の誤差があります。探索済みのマス(タイル単位)の境は、ぼかさず、マスの形のままです。
- 倒れた敵の絵は、画面に残ります(消えません)。消す・フェードさせる・ドロップを出すのは、敵のイベント側の処理(`<death>` など)です。通行だけ、すぐ通れるようにしてあります。
- 戸口に**生きている**敵が立ったまま扉を閉めると、敵は閉じた扉と重なります(扉の閉じるページは通れない)。必要なら、敵のいない間だけ閉める仕掛けをイベントで作ってください。
- 主人公の重ね描きは、壁・柱の**上**に主人公を描きます(主人公が壁・木の後ろに回り込む表現はありません。壁は通れないので、通常は起きません)。
- Apollo など、ほかのカードの自動追尾(エロスの矢の追尾 等)は、まだ視界を見ません(ヘルメースの基本セットにはありません)。

## 手動 Playtest の手順(F8 不要)

1. MZ で Playtest(ニューゲーム)を始める。開始位置は Map001 の (29,19)。
2. **探索マップの確認**: 東(右)へ歩いて敵(ゴブリン・銃テスト敵)が画面に入っても、戦闘は始まらない。Q / E / R / X / C / V / Shift・左クリック・右クリックは何も起こさない(Shift はダッシュのまま)。F で NPC・宝箱を調べる、Esc でメニューを開く、は普通に使える。
3. **入口**: 開始位置から西へ(約5マス)歩き、(24,21) の NPC に、下から話しかける(F)。メッセージを F で送ると、戦闘マップへ移動する。
4. **戦闘マップ**: 下に6枠(LMB 薙ぎ払い / Shift 絶 / E 一閃 / X 黄金の矢 / C ギガース殺し + 離れた V アイテム)と、その上に操作ガイド(LMB 斬撃 ●●○ / RMB 射撃)が出る。壁の向こうは真っ黒(未探索)で、敵は見えない。WASD で動き、マウスの方向を向き、**右クリックで撃てる**(壁・扉の向こうには当たらない)。左クリックは近接(下の 14)。
5. **扉**: 扉(8,7)の南(8,8)で上を向いて F を押すと開く。視線が通り、敵が見える。敵が近づいて赤い範囲(予兆)を出したら、範囲から出る(WASD か Shift)。出れば当たらない。扉をもう一度 F で閉めると、敵が見えなくなる(でも敵は動き続ける)。
6. **アビリティ**: E(一閃)・Shift(絶。マウスの方向へ瞬間移動)を押す。Cooldown が枠に出る。Q は奥義(ゲージが満タンのときだけ)。R はリロード(弾が減っているとき)。V の短押しはアイテム(HP が減っているとき)。Shift を押しながら歩いても、走らない(戦闘中はダッシュ無効)。
7. **終わり方**: 敵を3体すべて倒す → 元のマップ・位置・向きへ戻る(NPC に話しかけると結果が出る)。撤退するなら、控え室の NPC(8,11)に話しかける。敗北(HP 0)は自動では戻らず、ロードで戻る。
8. **繰り返し**: もう一度 NPC に話しかけると、扉は閉・敵は生き返り、前回見た北側は灰色の地形として残る。
9. **SOUL が止まっていること**: F7 を押してもテストマップへ行かない。
10. **敵の視界**: 戦闘マップで、扉(8,7)が閉じている間、壁の向こうの敵は近づいてこない。扉を開けると、扇形の視線の中の敵が気づいて近づく。追われている最中に扉を閉める(扉の前で F)と、敵は止まる。壁の陰へ回り込んで扉を開けても、敵は気づかない(視線が通る所へ戻ると、また追ってくる)。
11. **神**: 画面の左に神(ヘルメース。暫定の !Crystal)がいる。マウスを回して向きを変えると、神はプレイヤーの背後へ回り込む。E(一閃)・Shift(絶)を使っても、神は常に1体だけ見える。
12. **8方向**: マウスをプレイヤーの周りで一周させる(F8 の Console で `ProjectRFieldFacing.getAim().name` を見ると、N → NE → E → SE → S → SW → W → NW)。WASD で歩いても、向き(マウスの位置)は変わらない。神は、向きの反対側(斜めも)へ、滑らかに回り込む。
13. **敵の経路探索 — DEV の柱をよける**(F8 なし。Map008 の柱 = (11〜12, 9〜10)): 
    1. 入口の NPC で Map008 へ入る(出現位置 (8,9))。扉(8,7)の南(8,8)で上を向いて F で**扉を開ける**。
    2. 出現位置 (8,9) へ戻り、**待つ**。扉の正面の敵が、扉を通って南へ近づいてくる(赤い範囲=予兆が出る前に、次へ)。
    3. 敵が**戸口(扉のあたり)に来たら**、すぐに**南の列を東へ**走る: (8,10) → (9,10) → (9,11) → (13,11) → **(13,10)** へ(柱の**東側**で止まる)。Shift(絶)を使うと速い。
    4. 敵が、**柱の中へ入らず**、柱の**北の列(y=8)**を通って(または南の列を通って)回り込み、プレイヤーに追いつく。まっすぐ柱へ突っ込んで止まることはない。追いつくと赤い範囲を出して攻撃する(範囲から出れば当たらない)。
    5. 柱の**西側**へ戻ると(同じ道で)、敵はまた回り込んで追ってくる。追われている間は、敵の進む向きが経路の向きになる。
    6. **視線が切れると止まる**: 敵がまだ**扉の北側**にいるうちに扉を閉じる(扉の前で F)と、敵はその場で止まる(経路を持ち続けない)。扉を開けて見える位置に立つと、また追ってくる。壁の向こうへ回り込む追跡はしない(仕様)。
    7. **扉口の渋滞(Stage 4b)**: 扉を開け、出現位置(8,9)で待つ。敵が縦に並んで扉口まで来たら、(3,10) あたりへ走って、扉の正面の線から外れる。見失った敵が扉口で固まらず、**数秒で扉口から出る**(扉口に誰も立たなくなる)。北の部屋に残った敵は動かない。扉の正面(8,9)へ戻ると、また追ってくる。
    8. **はさまれる**: 敵の攻撃を待つ位置(赤い範囲が出ている間)で、扉口(8,7)に入って、北と南を敵にはさまれた状態にする。S(または W)を押し続けると、**約 0.4 秒後に敵を通り抜けて**扉口の外へ出られる(壁・閉じた扉は通れない)。
    9. **倒した敵**: 扉口で敵を倒しても、後ろの敵と自分が、死体の上を通れる(すぐ)。
    10. **戸口・撤退・繰り返し**: 扉・撤退の NPC(8,11)は、柱があっても使える。いったん撤退(または敵を倒して勝利)して、もう一度入口から入ると、扉は閉・敵は初期位置で、柱はそのまま(同じ回り込みをもう一度確認できる)。
14. **未探索**: 未探索の所(壁の向こう)は、移動・扉の開閉・銃を壁へ向けても、真っ黒のまま(扉の上の弧など、壁・扉そのものの絵が自分のマスからはみ出す部分は、設計どおり見える)。

テスト中は**セーブしない**でください(ヘルメースの指輪の入手・ポーションの追加が保存されます)。エンカウンター中は、そもそもセーブできません。
14. **Stage 5 / 5b の操作**(戦闘マップ。敵の近くで):
    1. **左クリック**を1回ずつ、間をあけて押す。1回につき斬撃が1回。1回目・2回目は通常、**3回目は一回転の大きな強撃**(ダメージが約2倍。HUD の ●●○ が3つ目の金の丸になり「強撃!」と出る)。続けて押すとまた1回目から。左ボタンを**押しっぱなし**にしても、斬撃は1回だけ。押したあと 0.8 秒あけると、1回目へ戻る(ガイドの細い線が尽きる)。
    2. **右クリック**で銃を1発(押しっぱなしでも1発)。右クリックしても、メニューが出ない。弾が減ったら **R** でリロード(弾が満タンなら何も起きない)。
    3. **Shift** でマウスの方向へ瞬間移動(絶)。**敵が間にいても、すぐ隣にいても、通り抜けて着地**する(敵とは重ならない)。壁・閉じた扉は越えない。Shift を押しながら歩いても、走らない(戦闘中はダッシュ無効)。**E** で一閃。**Q** で奥義(ゲージが満タンのときだけ。上のゲージが光る)。**X** で黄金の矢、**C** でギガース殺し(マウスの方向。枠に Cooldown が出る)。左クリックのたびに、薙ぎ払いの白い杖の残像が出て、**残像が通った範囲の敵だけ**に当たる(残像の外・真後ろの敵には当たらない。3回目は反対側にもう1回)。
    4. **V を短く押す**と、選んでいるアイテムを使う(HP が減っているとき。Cooldown 8秒がアイテム枠に出る)。**V を押し続ける**(0.3秒)と放射メニューが開く。V を押したまま、マウスを**動かした方向**のアイテムが光る。**V を離す**と選ぶ(使わない)。もう一度短く押すと、選んだアイテムを使う。
    5. 放射メニューを開いたまま、右クリック(撃たずに閉じる)・Esc・動かさずに離す、のどれでも、選んでいるアイテムは変わらない。開いている間は、左クリック・右クリック・Q/E/R/Shift/X/C は何も起こさない。アイテムを全部使い切ってから開くと「アイテムなし」。
    6. **壁際の扉口**(8,8)で、最後の敵を**右クリックの銃**で倒して勝利する。エラー画面にならず、元のマップへ戻る(Stage 5b 以前は戻る瞬間に落ちた)。
    7. 画面の大きさを変えても(Playtest の画面のサイズ)、下のスキル枠・操作ガイド・放射メニューが画面に収まる。戦闘を終えて元のマップへ戻ると、HUD は従来に戻り、Q/E/R/X/C/V/Shift・クリックは何も起こさず、Shift は走る(ダッシュ)、X はメニューを開く。
    8. **Shift(絶)**(Stage 5c): 戦闘マップで、マウスを遠くへ向けて **キーボードの Shift** を押す(押しっぱなしにせず1回)→ 瞬間移動する。壁ぎわで壁へ向けて押すと動かず、枠の下に「進めない」が出る。Shift を押したまま E・X・C も使える。
    9. **薙ぎ払いの当たり**(Stage 5c): 敵の少し手前で、敵の方向へ左クリック。白い杖の残像が**敵の上を通ったときに**ダメージが出る(残像の外・真後ろの敵には当たらない)。3回目(強撃)は一回転で、後ろの敵にも当たる。斜め向きでも、残像の向きと当たる向きが同じ。
