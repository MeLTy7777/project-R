# ProjectR リアルタイム・フィールド戦闘(FieldCombat) v0.2.7

戦闘を、マップ上で連続して戦う**リアルタイム・アクション**(BAPBAP の操作感を参考)へ戻すための土台です。
ATTACK/DEFENSE の区切りも、カードのドロー・ランダムな手札も使いません。SOUL / SOUL RUSH は**コードもセーブデータも消さず**、通常のプレイでは開始できないようにしました。

- プラグイン: `js/plugins/ProjectR_FieldCombat.js`(新規。ProjectR_* の最後に登録)
- 実機の確認: `tools/mz_cdp/field_combat_verify.cjs`(40項目) / Node: `tests/ProjectR_FieldCombat.test.cjs`(16項目。従来の実エンジンのテスト用 `tests/RealEngineHarness.cjs` は、起動後に SOUL を許可し自動開始を切る)

## エンカウンター(戦闘マップ専用)

**戦闘は、NPCとの会話・物語のイベントから入る「専用の戦闘マップ」の中だけ**です(v0.2.0)。以前の「近くに敵がいれば自動で戦闘になる」は廃止しました。

- **探索マップ**: 近くに敵がいても戦闘は始まりません。戦闘の入力(Q/E/R/C/Space・基本攻撃(銃・剣))は無効です(CombatPresence の「画面内に敵がいれば武器が使える」も、エンカウンター中以外は止めます)。**移動・NPC・イベント・メニューは普通のまま**です。
- **流れ**: ①イベントで「エンカウンターを始める」→ 元のマップ・位置・向き(実座標も)を記録して、戦闘マップへ移動 → ②戦闘マップの準備が終わる(移動・フェード・開始時のイベント/メッセージのあと)と、戦闘・敵の行動・アビリティ・HUD が有効になる → ③敵を全員倒すと勝利(結果を**1回だけ**処理 → 戦闘を片づける → 元のマップ・位置・向きへ戻る → 結果の変数・コモンイベント)。
- **敗北**(HPが0): 自動では戻りません(既存の死亡・ロードの扱いのまま)。戦闘は片づき、結果の変数=2、エンカウンター中の**セーブ禁止は続き**、ロード/ニューゲームですべて初期状態に戻ります。
- **中断・撤退・特別な終わり方**: 「エンカウンターを終える」(勝利/中断)、「エンカウンターを中断する」。想定外のマップ移動(戦闘中に別のマップへ)・外からの戦闘の終了・ロードでは、戦闘が探索マップに残らないように片づけます(結果=中断を1回だけ)。
- **セーブ**: エンカウンター中(敗北のあとも、ロードまで)は、メニューからも「セーブ画面を開く」イベントコマンドからも保存できません(SOUL のエンカウンターと同じ方式)。

### プラグインコマンド

| コマンド | 内容 |
| --- | --- |
| フィールド戦闘: エンカウンターを始める(StartFieldEncounter) | 元のマップ・位置・向きを記録。戦闘マップ(Map ID)・出現位置・向き・結果を入れる変数・勝利/中断後のコモンイベントを指定。戦闘マップを 0 にすると「armed」で待つ |
| フィールド戦闘: 戦闘マップへ移動する(TransferToBattleMap) | 「始める」で戦闘マップを指定しなかったときに、移動先を指定して移動 |
| フィールド戦闘: エンカウンターを終える(CompleteFieldEncounter) | 結果(勝利 / 中断・撤退)を指定して、元のマップへ戻る。ボス戦・撤退などの特別な終わり方用 |
| フィールド戦闘: 敵の行動をつける(AttachFieldEnemy) | イベント(0=このイベント)を、近づいて溜めて攻撃する敵にする(メモの `<fieldEnemy>` と同じ) |
| フィールド戦闘: エンカウンターを中断する(AbortFieldEncounter) | 戦闘を片づけて元のマップへ戻る(結果=中断) |

結果の変数: 1=勝利 / 2=敗北 / 3=中断(戦闘中は 0)。**このプロジェクトの変数は 1〜20 だけです**(`$dataSystem.variables` の数。21番以降は使えません)。10〜20 は SOUL などが使用中なので、DEV の入口は 9 番を使っています。

### イベントの設定手順(F8 不要)

**戦闘マップを作る**
1. 新しいマップを作り、**マップのメモ**に `<fieldBattleMap>` と書く(印の無いマップは、戦闘を始めずに元へ戻ります。パラメータ RequireBattleMapTag)。
2. 敵にするイベントを置く。イベントの**メモ**に Hendrix の敵の印(`<hp: 敵名>` と `<enemy>`。武器・奥義が当たるように)と、フィールド戦闘の印 `<fieldEnemy>` を書く。数値を変えるときは `<fieldEnemy: windup=36, cooldown=120, reach=1.2, aggro=10, chase=1>`(すべて省略可。windup=溜め・cooldown=攻撃後の間(いずれもフレーム)・reach=届く距離(tile)・aggro=追いかける距離・chase=0で動かない)。有効なページの**注釈**に書いても有効です。プラグインコマンド「敵の行動をつける」でも指定できます。
3. 戦闘マップの準備が終わると、印のついた敵に行動がつきます。**印のついた敵を全員倒すと勝利**です。敵が1体もいない/ボス戦などは、イベントから「エンカウンターを終える」を呼びます。
4. (任意)撤退用のNPC: 話しかけると「エンカウンターを中断する」を呼ぶイベントを置く。

**入口(NPC・物語のイベント)を作る**
1. 探索マップのイベントで、会話などのあとに「エンカウンターを始める」を**最後のほうのコマンド**として置く(戦闘マップ・出現位置・結果の変数を指定)。移動はイベントが終わってから実行されます。
2. 戻ったあとの処理は、結果の変数(1/2/3)を条件にしたイベントのページ、またはコモンイベント(勝利後/中断後)で行う。
3. ヘルメースの指輪(奥義 E のため)・ポーションが必要なら、入口のイベントで与える(DEV の入口の例を参照)。

### 入力の衝突の解決(マップ戦闘中だけ)

- Q / E / R / C / Space は、フィールド戦闘中だけ `ProjectR_FieldCombat` が先に受け取ります。戦闘外・メッセージ/メニュー/会話/イベント中・Ctrl/Alt/Shift つきは、元のまま(MZ・Hendrix)へ渡します。
- 戦闘中はカード戦闘の入力(`ProjectR_CardBattleInput` の Q/E/X/C/V)は何も起こしません(手札が空のため)。X は元の Cancel のまま使えません(戦闘中のみ。メニューは Esc)。
- 戦闘中は主人公の向きがマウスに固定されるため、DotMove の「接触」イベント(扉・場所移動)は、マウスと違う向きに歩くと発火しませんでした。戦闘中だけ「移動キーを押しているのに進めなかったとき、押している方向の前方の接触イベントを調べる」補助を入れました。
- F(決定)は、照準している方向(主人公の向き)の隣のイベントを調べます。

## 固定アビリティのしくみ

カード効果(一閃・絶)は「手札のカードを使う」前提で作られています(使ったあとに消費・ダメージの確定など)。そこで、`ProjectR_FieldCombat` が、`ProjectR_CardDeckCore` の公開している `BattleDeckSession` を広げて**固定戦闘の窓口**を足します(CardDeckCore のファイルは変更しません。既存の戦闘は変わりません)。

- `ProjectRCardDeck.startCardBattle(ProjectRCardDeck.FIXED_BATTLE)` … デッキの検証なし・山札なしの「固定戦闘」を始める。
- `ProjectRCardDeck.useFixedCard(cardId)` … 固定戦闘の中で、そのカードの効果(既存の handler と、それを包む後処理)を1回使う。カードは手札に残り(消費・Cooldown山・ドローなし)、所持・指輪に依らない。Cooldown はこのプラグインがスロットごとに持つ。
- 通常の戦闘(手札の戦闘)では `useFixedCard` は使えません。

### HUD

既存の `ProjectR_BattleHUD` の5枠(スキル枠)を、フィールド戦闘中だけ固定アビリティ(Q 一閃 / Space 絶 / E 奥義 / R ポーション / C キャンセル)にします(BattleHUD のデータ元 `DataAdapter.skills()` / `cardCounts()` を、戦闘中だけ差し替え。BattleHUD のファイルは変更しません。枠の下の小さな文字は既存の「SKILL 1〜5」のままです)。DRAW/DISCARD/COOLDOWN の表示は出ません。HP・Divine HP・奥義ゲージ・武器の表示も既存のままです。

## 敵と予兆

- 敵は既存の `<enemy>` つきのイベント(Map001 の「公式銃テスト敵」)。`ProjectRFieldCombat.attachEnemy(eventId)` で、メモリ上だけ「近づく → 範囲に入ったら溜めて(予兆)→ 近接攻撃 → Cooldown」の行動をつけます(`ProjectREnemyAttack` の予約を使う)。溜めの間は動きません。元の並列ページの攻撃は止めます(二重にならないように)。
- 予兆は、予約の記録(`ProjectREnemyAttack.list()` の pending)をそのまま赤い範囲で画面に描きます。予約が取り消されれば予兆も消えます。範囲は攻撃が実際に当たる範囲(同じ記録)です。
- 注意: 「テスト用ゴブリン」(Map001 のイベント1)には `<enemy>` が無く、武器・奥義が当たりません(旧テスト敵)。基準の敵には「公式銃テスト敵」(イベント2)を使います。

## 敵の視界(v0.2.4)

敵は、次の3つがそろっている間だけ、プレイヤーを追い、攻撃します(従来は、壁越しでも距離内なら追っていた)。

1. **距離**: 視界の距離(既定 10 tile)の内側。
2. **視野角**: 敵の向き(イベントの向き)を中心にした視野角(既定 140°)の内側。**見つける瞬間だけ**見る。見つけたあとは、プレイヤーの方を向いて追う(見失うまで視野角は問わない)。
3. **視線**: 敵とプレイヤーを結ぶ線が、壁(Region 255)・閉じた扉(`<VisionWall>`)に遮られていない。開いた扉は視線を通す。判定は `ProjectR.CombatOcclusion.hasLineOfSight`(vision モード)で、**プレイヤーの霧(FogOfWar)とは無関係**。

- **見失うと**: その場ですぐ(1フレーム以内に)追うのをやめて、待つ。**最後に見た位置を覚えない・探さない**(見失っている間にプレイヤーがどこへ動いても、敵は動かない・向きも変えない)。
- **見えるようになると**: また見つけて追う。溜め(windup)の最中に見失ったときは、その攻撃だけは撃ち終える(従来どおり)。閉じた扉越しは、届く距離でも攻撃を始めない。
- **攻撃・ダメージ・HP・クールダウン・勝利の判定は変えていません**(攻撃を始める条件に「見えている」を足しただけ)。
- **設定**: プラグインパラメータ `EnemyPerception`(既定 true。false で従来)・`EnemySightTiles`(10)・`EnemyFovDegrees`(140)。敵ごと: イベントのメモ `<fieldEnemy: sight=8, fov=90>`(`aggro=N` も距離として使える)/ プラグインコマンド「敵の行動をつける」の「視界の距離・視野角」。敵ごとの設定は全体の設定に優先。
- **API**: `getEnemyPerception(eventId)`(aware / sees / reason(seen・range・blocked・fov)/ 距離 / 向き / 見つけた回数 / 見失った回数)・`getPerception()`・`setPerception({enabled, sightTiles, fovDegrees})`・`resetPerception()`(DEV。保存しない)。

## 8方向の向き(v0.2.5。`ProjectR_FieldFacing.js`・読み取り専用)

戦闘中のマウス照準から、プレイヤーの**8方向の向き**(N/NE/E/SE/S/SW/W/NW。テンキーの 8/9/6/3/2/1/4/7)と、正確な角度(上=0・時計回り)を出します。

- **MZ本体の向きは4方向のまま**: プレイヤーのキャラクター画像(DEV3H)は4方向で、斜めの画像(ファイル名に `8dir`)はありません。`$gamePlayer.direction()` は、既存の `ProjectR_PlayerFacing` / Hendrix の照準のまま 2/4/6/8 で、斜めの向き(1/3/7/9)を MZ本体の4方向のAPIへ渡しません。斜めの照準では、見た目は斜めの両隣の4方向のどちらか。斜めの画像(`8dir`)を使うキャラクターは、Hendrix が元から斜めの向きを持ちます(ここは何もしない)。
- **WASD と無関係**: 向きはマウスの位置だけで決まる(歩いても向きは変わらない。プレイヤーが動けば、固定したマウスとの角度は幾何学的に変わる)。斜め移動の速さ・衝突・攻撃・スキル・調べる(F)は変えていません(このプラグインは読み取り専用。向き・移動の関数を書き換えない)。
- **正確な角度**: MZ の `$gameMap.canvasToMapX` は整数のマスへ切り捨てるので、使わず、`displayX + TouchInput.x / tileWidth`(小数)で計算します(丸めると、8方向の境の近くで角度が最大1マスぶんずれる)。
- **API**: `ProjectRFieldFacing.getAim()`(active / degree / degree8 / dir8 / name / vx・vy / dir4)・`getDir8()`・`getDegree8()`・`getFacingVector()`・`toDir8(deg)`・`toName(dir8)`・`setConfig({enabled})`(DEV)。戦闘外は4方向の向きをそのまま返します。ゲームパッドは対象外(マウスだけ)。

## 神の同行(v0.2.4。`ProjectR_FieldGodCompanion.js`・表示だけ)

既存の神の表示(`ProjectR_GodSummonVisual`: 常駐=プレイヤーの子として左上に固定 / 一時召喚=スキルごとの位置)は**変更せず**、その表示Eventを毎フレーム調整する新しいプラグイン(末尾に登録)です。神のDivine HP・崩壊・復帰・スキルの効果・時間・演出は変わりません。

- **背後**: 常駐の神(Ultimate の神)を、プレイヤーの現在の向き(戦闘中は **8方向**のマウス照準。斜めも。戦闘外は4方向)の**反対側**へ置く(既定: 1.2 tile 後ろ・0.1 tile 浮かせる。斜めは距離 1.2 のまま、斜めの方向へ。**縦の余白**: 神の絵は約 44x83px(1.7 マス)で足元が基準。神が南側(北向き)では、縦の成分に比例して最大 0.9 tile 下げ(`SouthExtraTiles`)、神が北側(南向き)では最大 0.75 tile 上げる(`NorthExtraTiles`)。北向き・南向きで、合計 約 2 マス離れ、絵が足・頭に届かない)。
- **描く順番**: 神の絵(高さ約2マス・足元が基準で、上に約1.5マス伸びる)は、北向きのとき(神が南側)、以前は 0.9 tile 後ろ(足元が足の 29px 下)で、絵の上端がプレイヤーの足・脚に重なり、**前面に**描かれていた(神もプレイヤーも優先度 1 で、足元の y で並ぶため、南側の神が手前になる)。神を、プレイヤー・ほかのキャラクターの**下**(優先度 0)に描くようにした。ただし v0.2.6 の距離(合計 1.5 tile)では、実測で、神の絵の上端が靴の底より 9px 上(足に 9px かかる)だった(北向きのスクリーンショットで、神が足に接して見えた原因)。神の絵の実寸(44x83px)から、北向きは合計 2.0 tile(足との余白 15px)、南向きは合計 2.05 tile(頭との余白 14px)にした。動かないとき(無効・戦闘外)は、元の優先度・元の位置(プレイヤーの子)へ戻す。移動中・向きの変更中も毎フレーム更新。向きが変わると、瞬間移動せず、滑らかに背後へ回り込む(`Smoothing` 0.25)。
- **同じ神は1体だけ**: 同じ神の表示Event(常駐・一時召喚・追従する神)が複数あるときは、1体だけ見せる(優先: 追従する神 > 最新の一時召喚 > 常駐)。スキルの演出(一閃・絶)中は、常駐の神を**透明にして隠し**、演出が終わると背後へ戻す(隠している間も背後へ追従するので、戻るときに飛ばない)。新しい演出のスプライトが出るまでは隠さない(1フレームも神が消えない)。別の神(ヘルメースとアポロン)は、それぞれ1体。
- **後始末**: GodSummonVisual が管理していない神の表示Event(孤児)は、3フレーム後に片づける。マップ移動・エンカウンターの終了・ロード・戦闘の終了で、状態を捨てる(演出中の撤退でも、探索マップに神のEvent・スプライトは残らない)。
- **霧との関係**: 神の表示Eventは、プレイヤーの一部として、霧の「視界の外の敵・イベントを隠す」の対象から外した(演出中の神が消えていた)。未探索の暗闇は上から覆うので、神が未探索へ漏れることはない。
- **動く場所**: 既定(`FieldCombatOnly=false`)は、常駐の神がプレイヤーに付いてくる所なら**どこでも**(フィールド戦闘・旧カード戦闘・テストアリーナ)。台本の神(一時召喚・追従する神。ヴェイル等)は動かさず、同じ神が重なるときだけ、常駐の神を隠す。探索マップには、常駐の神は出ない(戦闘中だけ出る)ので、探索マップで動かすものはない(台本の神は、位置を触らず・消さない)。`FieldCombatOnly=true` なら、フィールド戦闘中だけ(それ以外は既存の左上のまま。戦闘が終わると、隠していた神を戻す)。孤児の片づけは、どちらでもフィールド戦闘中だけ。
- **パラメータ**: `Enabled`・`FieldCombatOnly`・`BehindTiles`・`LiftTiles`・`Smoothing`。API: `ProjectRFieldGodCompanion.getState() / getVisibleGods() / getDiagnostics() / setConfig()`。

- Map001 の既存の「銃エイム制御テスト」(銃を持つとマウスの方を向く)は、探索マップでも動きます。FieldCombat はこれを変更していません(isCombatActive を false にしたので、画面内に敵がいても向き直しが抑えられます)。
- Vision 系の制限(ProjectR_CombatPresence を変更しないため、隠れた敵だけが画面内にいると銃を構える等)は、探索マップでは武器の門で解決済みです。
- 縁のぼかしは、視界の内側へ約 6px(`FeatherPixels`)です。ぼかしの元の画像は半分の解像度なので、縁の位置は最大 約2px(画面)の誤差があります。探索済みのマス(タイル単位)の境は、ぼかさず、マスの形のままです。
- 倒れた敵の絵は、画面に残ります(消えません)。消す・フェードさせる・ドロップを出すのは、敵のイベント側の処理(`<death>` など)です。通行だけ、すぐ通れるようにしてあります。
- 戸口に**生きている**敵が立ったまま扉を閉めると、敵は閉じた扉と重なります(扉の閉じるページは通れない)。必要なら、敵のいない間だけ閉める仕掛けをイベントで作ってください。
- 主人公の重ね描きは、壁・柱の**上**に主人公を描きます(主人公が壁・木の後ろに回り込む表現はありません。壁は通れないので、通常は起きません)。
- Apollo など、ほかのカードの自動追尾(エロスの矢の追尾 等)は、まだ視界を見ません(ヘルメースの基本セットにはありません)。

## 手動 Playtest の手順(F8 不要)

1. MZ で Playtest(ニューゲーム)を始める。開始位置は Map001 の (29,19)。
2. **探索マップの確認**: 東(右)へ歩いて敵(ゴブリン・銃テスト敵)が画面に入っても、戦闘は始まらない。Q / E / R / C / Space・左クリックは何も起こさない。F で NPC・宝箱を調べる、Esc でメニューを開く、は普通に使える。
3. **入口**: 開始位置から西へ(約5マス)歩き、(24,21) の NPC に、下から話しかける(F)。メッセージを F で送ると、戦闘マップへ移動する。
4. **戦闘マップ**: 下に5枠(Q 一閃 / Space 絶 / E 奥義 / R ポーション / C キャンセル)が出る。壁の向こうは真っ黒(未探索)で、敵は見えない。WASD で動き、マウスの方向を向き、左クリックで撃てる(壁・扉の向こうには当たらない)。
5. **扉**: 扉(8,7)の南(8,8)で上を向いて F を押すと開く。視線が通り、敵が見える。敵が近づいて赤い範囲(予兆)を出したら、範囲から出る(WASD か Space)。出れば当たらない。扉をもう一度 F で閉めると、敵が見えなくなる(でも敵は動き続ける)。
6. **アビリティ**: Q(一閃)・Space(絶)・R(ポーション。HP が減っているとき)を押す。Cooldown が枠に出る。E は奥義(ゲージが満タンのときだけ)。C はキャンセル。
7. **終わり方**: 敵を3体すべて倒す → 元のマップ・位置・向きへ戻る(NPC に話しかけると結果が出る)。撤退するなら、控え室の NPC(8,11)に話しかける。敗北(HP 0)は自動では戻らず、ロードで戻る。
8. **繰り返し**: もう一度 NPC に話しかけると、扉は閉・敵は生き返り、前回見た北側は灰色の地形として残る。
9. **SOUL が止まっていること**: F7 を押してもテストマップへ行かない。
10. **敵の視界**: 戦闘マップで、扉(8,7)が閉じている間、壁の向こうの敵は近づいてこない。扉を開けると、扇形の視線の中の敵が気づいて近づく。追われている最中に扉を閉める(扉の前で F)と、敵は止まる。壁の陰へ回り込んで扉を開けても、敵は気づかない(視線が通る所へ戻ると、また追ってくる)。
11. **神**: 画面の左に神(ヘルメース。暫定の !Crystal)がいる。マウスを回して向きを変えると、神はプレイヤーの背後へ回り込む。Q(一閃)・Space(絶)を使っても、神は常に1体だけ見える。
12. **8方向**: マウスをプレイヤーの周りで一周させる(F8 の Console で `ProjectRFieldFacing.getAim().name` を見ると、N → NE → E → SE → S → SW → W → NW)。WASD で歩いても、向き(マウスの位置)は変わらない。神は、向きの反対側(斜めも)へ、滑らかに回り込む。
13. **未探索**: 未探索の所(壁の向こう)は、移動・扉の開閉・銃を壁へ向けても、真っ黒のまま(扉の上の弧など、壁・扉そのものの絵が自分のマスからはみ出す部分は、設計どおり見える)。

テスト中は**セーブしない**でください(ヘルメースの指輪の入手・ポーションの追加が保存されます)。エンカウンター中は、そもそもセーブできません。
