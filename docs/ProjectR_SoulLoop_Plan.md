# SOUL戦闘 新ループ(準備 → 攻撃 → 防御 → 準備)実装計画

状態: **L0(準備フェーズの骨組み・境目の後始末)・L1(キャラ→デッキの読み取り窓口・マナコスト確認表)・L2(準備画面: キャラ選択・10枚から5枚・割り当て)・L3(10枚ドロー・固定手札)・L4-A(マナの資源の土台)・L4-B(承認済みD8コストによる判定と消費・slotCooldown の廃止・竪琴の割引)まで実装済み**。アイテム使用・キャラ切り替え時の見た目/武器・準備の制限時間は未実装。調査日 2026-11-06。コードの事実は各項の「根拠」のファイルで確認したもの。
書いていないルール(数値・手順)は「未決定」として末尾にまとめ、勝手に作っていない。

## 1. 目指すループ

```
PREPARATION ──(「攻撃」を選ぶ)──▶ ATTACK ──(時間切れ)──▶ DEFENSE ──(時間切れ)──▶ PREPARATION …
   │ 選択肢: 攻撃 / アイテム
   │ 攻撃: 出撃できる既存のキャラを選ぶ → そのキャラの実際のデッキから10枚引く → 5枚を Q/W/E/R/T へ割り当てる
ATTACK : カードのクールダウンの代わりに「マナ」(上限10・毎秒+1)。カードごとにマナコスト。通常武器の攻撃間隔は今のまま
DEFENSE: マウスのハート移動だけ。攻撃・アイテム・スキル発動なし。スキルの効果は持ち越さない
```

## 5. カードの消費・クールダウンに関わる影響

- 今のカードは「使う → クールダウンの山 → 時間が来たら捨て札 → 山札が空なら混ぜて引く」。マナに替えると、**山札・捨て札・クールダウンの山の意味が変わる**。
  - 5枠を固定して何度でもマナで使うなら、使用後の「引き直し」「シャッフル」「クールダウンの山」はSOULでは使わない(今回の山札の動きの表示も不要になる)。
  - 1枚ずつ使い切りなら、10枚のうち使い終えた枠は空になり、補充の元(残り5枚)が必要。
- `deck.updateCooldown` は他のタイマーの時計なので**消さない**。カードの使用可否だけ、`requestUseCard` の手前で判定する。
- 竪琴の「冷却短縮」(本文の効果が冷却山札を速めるもの)・絶のクールダウン6秒は、マナになると意味が変わる。作り直しに仕様の承認が要る。
- 通常武器の攻撃間隔(剣・銃)はカードとは別の時計。変えない。神託の攻撃間隔−20%も武器側のまま。
- 準備フェーズでカードを割り当てたあと、ATTACKが終わったときの手札・使用済みの扱い: **D5・D6 で決定(次の準備で30枚を混ぜ直す。カードは消費されない)。12章**。

## 7. L0 の実装内容(準備フェーズの骨組みだけ)

- **制御役** `ProjectR_SoulBattle.js`(唯一の状態): `start({ prepare:true })` または プラグインパラメータ `PrepareLoop` のときだけ **PREPARE → ATTACK → DEFENSE → PREPARE** を回す。既定(指定なし)は従来の攻撃⇄防御のまま。
  - PREPARE は時間で終わらない。`beginAttack()`(メニューの「攻撃」)か `skipPhase()` で ATTACK へ。ラウンドは DEFENSE が終わったときに進む。
  - PREPARE 中の遮断: カード・通常攻撃・ホットバー・必殺技は DEFENSE と同じ仕組みで止める(理由は `soulPrepare`。DEFENSE は従来の `soulDefense`)。
  - PREPARE 中の戦闘の時計の停止: SOULのフェーズ時間は数えない / `$gameMap.eventsPaused` を立てる(敵ハートの動き・敵の攻撃・飛んでいる弾・武器) / カードのクールダウンの時計 `deck.updateCooldown` を進めない。自分が立てた `eventsPaused` は、準備を出る・終了・マップ移動のどれでも必ず戻す(他が先に立てていたら触らない)。
- **準備メニュー** `ProjectR_SoulBattlePrepare.js`(新規・表示と選択だけ): 「攻撃」「アイテム」。アイテムは「未実装」と明示し、選んでも何も消費せずフェーズも変えない。マウス(クリック)とキー(S=切り替え / F=OK)。開いた直後の15フレームは入力を受けない。
- **他のプラグイン**(準備を防御として扱わず、明示的に扱う): Input(`swallowedPrepare`・メニューのクリックは通常攻撃にしない)/ Skills(`soulPrepare`)/ Dodge(準備中は回避AIの時計を進めない)/ HUD(「PREPARE・選択待ち」・手札は「準備中」)/ Stage(準備ではキャラと神を出し、プレイヤーのハートは出さない)/ Sandbox(`options.prepare` を渡す)。
- **まだ決めていない・やっていないこと**: D3〜D13。PREPARE→ATTACK のとき手札・山札は何も変えない(今のまま)。マナ・コスト・アイテム使用なし。フェーズ境目の飛び道具は **8章の後始末で片づける**(準備ループのときだけ)ので、準備の凍結から再開する弾は無い。

## 8章. フェーズ境目の後始末(L0 の追加分。`ProjectR_SoulPhaseCleanup.js`)

- **問題**: 準備ループでは準備の間、`$gameMap.eventsPaused` で時計を止める。ATTACK で撃った矢・薙ぎ払いの判定待ち・一閃の演出がそのまま残ると、DEFENSE の間に敵ハートに当たったり、PREPARE で止まっていた矢が次の ATTACK で動き出したりする。
- **対処**(準備ループ `prepare:true` のときだけ。従来の攻撃⇄防御は変えない): フェーズが切り替わる瞬間(ATTACK→DEFENSE / DEFENSE→PREPARE / PREPARE→ATTACK)と SOUL 終了時に、
  1. 判定の時刻に達していない薙ぎ払いの溜め(遅延ダメージ)は、**ダメージを与えずに取り消す**(早く判定しない)。薙ぎ払いの扇・一閃の演出・追尾中の斬撃の記録も片づける(`ProjectRSoulBattleMelee.cancelPhase`)。
  2. プレイヤー側の攻撃の印(`ProjectRSoulBattleDodge` が観測する矢・弾・斬撃・範囲の印と同じ13種)を持つ **Hendrix が生成した動的Event** だけを、各プラグインと同じ `DestroyEvent` で消し、片づけた矢の当たり履歴(`$gameSystem`)も消す。
- **触れないもの**: 攻撃の印を持たないEvent・敵ハート・常駐の神の見た目・月桂冠/ヒュアキントスの支援効果・通常のマップのEvent・通常のマップ戦闘。スキル(SOUL専用の効果)の解除は従来どおり `ProjectR_SoulSkills` が防御に入る時点で行う。
- **持ち主の分離**: 印は `player`(プレイヤーの ATTACK の攻撃)と `enemy`(将来の敵の DEFENSE の弾)に分けて登録する(`registerTag(印, 持ち主)`・持ち主は必須)。`player` は境目ごとに片づけるが、`enemy` は DEFENSE が終わるとき(と SOUL 終了)にだけ片づける。ATTACK→DEFENSE の境目でプレイヤーの攻撃を消しても、DEFENSE の頭に出る敵の弾は消えない。
- **未対応(将来)**: DEFENSE の敵の攻撃(弾幕)はまだ存在しない。作るときは `registerTag(印, "enemy")` で登録する。

## 9章. L1: キャラ→デッキのデータ窓口(`ProjectR_SoulLoopData.js`)と D2 の解決

## 13章. L4-A: マナの資源の土台(`ProjectR_SoulMana.js`)

**範囲**: 資源(マナ)の状態・回復・破棄・HUD 表示だけ。カードのコスト・マナの消費・`slotCooldown` の置き換え・既存スキルの効果の変更は**していない**(コストは未承認。コードにコストの数値は無い。テストで固定)。準備ループ(`prepare:true`)の SOUL だけで動き、従来の攻撃⇄防御・通常のマップ戦闘では何もしない。

**規則(承認済み)**:
- 上限10。ATTACK が始まるたびに10へ初期化(前の値は引き継がない)。
- ATTACK の間だけ毎秒+1(上限まで)。端数も貯まる。PREPARE・DEFENSE・一時停止(メニュー・会話・メッセージ・イベント中)・神託の時間停止・SOUL が動いていない間は回復しない。
- ATTACK の終了で残りを破棄(0)。次の ATTACK の開始で再び10。SOUL の終了・中断・マップ移動で初期状態(非アクティブ・0)へ戻る。

**実装の要点**:
- 単位は「1/60 マナ」の整数(1フレーム = 1単位)。浮動小数点の足し算を使わないので、60フレームちょうどで+1、600フレームちょうどで10。誤差は貯まらず、フレームレートや実時間(`Date.now`)に依存しない。
- 回復は ATTACK の時計(`ProjectRSoulBattle` の `elapsedFrames`。`Game_Map.update` で数え、メニュー・会話・イベント・`eventsPaused` の間は進まない)が進んだフレーム数と**完全に一致**する。ATTACK の制限時間と同じ時計なので、止まる条件も必ず同じ(神託の時間停止は `eventsPaused` のため自動的に止まる)。
- 状態の窓口(読み取り専用・凍結): `ProjectRSoulMana.getState()` = `{ active, phase, current, whole, max, ratio, units, regenerating, reason, round, lastDiscarded, stats }`。`reason` は regen / full / paused / notAttack / inactive。確認用の `devSet(マナ)` は Playtest(`test` オプション)でだけ働き、消費の仕組みではない(L4-B で消費の窓口を作る)。
- HUD(`ProjectR_SoulBattleHUD`): フェーズのチップの下に「MANA 現在値 / 10」と端数まで見える細いバー。ATTACK は強調、PREPARE・DEFENSE は 0 / 10 で薄く。準備ループのときだけ表示(従来の SOUL では出ない)。固定手札(L3)では、確定で入れ替わった手札を「NEW」「回復」と見せないよう、山札の動きの観察を止めた。

**未実装・未解決(L4-B 以降)**: カードごとのコストとマナの消費、足りないときの扱い、`slotCooldown` の置き換え、竪琴・絶の作り直し(D12)、神託の停止中にマナが回復しないことの設計上の再確認(今は承認どおり回復しない)。

**実機検証スクリプトの不安定さの調査(Stage T5 / Origin O1)**: 6回の連続実行(負荷なし)はすべて合格し、再現しなかった。T5 の失敗は常に `Graphics.pageToCanvasX(400)` が 400 でなく 361 になるもの(画面の拡縮が1.0でない = 窓の大きさ・表示状態に依存する環境の前提で、コードの不具合ではない)。O1 の失敗は命中の反映を固定の350ms後に読んでいたため、負荷で遅れると 0 に見えるもの。どちらも**スクリプト側を直した**: T5 は最初に測った素の値と比べ、戻りの再計算を最大3秒待つ。O1 は HP が変わるまで最大1.5秒待つ。

## 14章. L4-B: 承認済みD8コストによる判定と消費(`ProjectR_SoulMana.js` v0.2.0・`ProjectR_SoulLoopHand.js`・`ProjectR_SoulSkills.js`・HUD)

**範囲**: 準備ループ(`prepare:true`)のSOULだけ。従来の攻撃⇄防御・通常のマップ戦闘・カードの所持・デッキ・セーブは変えない。DEFENSE・PREPARE の使用の遮断(`soulDefense` / `soulPrepare`)は従来のまま。

**コスト**(承認済み D8。カードの所持 Lv で決まる。表の出典 = `docs/spece/ProjectR_SOUL_D8_mana_cost_approved.csv`): 一閃 5/5/6・ストレングス 2/3/5・薙ぎ払い 2/3/4・絶 4/5/6・サイコポンポス 5/6/8・葦笛 4/5/6・ヴェイル 3/4/5・黄金の矢 3/4/5・エロスの矢 4/5/7・ギガース殺し 6/7/8・ヒュアキントス 3/4/5・疫病の矢 4/5/6・月桂冠 4/5/6・竪琴 3/4/5・神託 7/8/9。

**使用の流れ**:
1. 使う前にマナを確認する(`quote`)。足りなければ `insufficientMana` で拒否(カード・マナ・効果は何も動かない)。表に無いカードは `costUndefined`。
2. 同期で成功するカード: 成功の確定(`BattleDeckSession.use`)のときに、ちょうど1回だけ引く(`settle`)。発動の失敗・拒否では引かない。
3. 予約型のカード(発動が `pending` を返す矢: 黄金の矢・エロスの矢・ギガース殺し・疫病の矢): 発動が始まった時にコスト分を予約する(`reserve`。他のカードに使われない)。**発射(launch)が成功した時点で、ちょうど1回確定して引く**(命中するかどうかは関係ない)。発射の成功 = 黄金の矢・疫病の矢は発動と同時 / ギガース殺しはチャージが終わって矢・ビームが出たとき(チャージ中は予約だけ)/ エロスの矢は最初の矢の発射かビームの開始。発射の前に失敗・中止された(チャージ中に発射できない・最初の矢の前に ATTACK が終わる)ときだけ予約を解放して引かない。発射した攻撃があとで外れる・時間切れになる・ATTACK の終了で片づけられても**返金しない**。複数の矢・ビームの攻撃も1回の発動につき1回だけ(のちの命中でカードの消費が確定しても、もう引かない)。発射の検出は各カードの読み取り専用の窓口(`getPending` / `getSequences`)を見るだけで、カードの動作は変えていない。
4. カードは5枠に装備されたまま何度でも使える(マナが足りる限り)。枠ごとのクールダウン(`slotCooldown`)は廃止。

**カードごとの安全策(準備ループのみ)**:
- **絶**: SOUL専用の冷却6秒を撤廃(元の定義のまま)。続けて使っても、構えの倍率は重ならず(`armWeaponHitBonus` は置換)、速度の強化(Lv3)も1つだけ(時間を更新)。
- **竪琴**: 冷却短縮をやめ、「速度」の音符で「次に使うカード1枚の消費マナの割引」を付ける(通常 -1・「全部同じ音符」で -2・最低1・ATTACK の時計で8秒・1回使うと消える)。重ねがけしない(大きい方で更新)。竪琴自身には効かず、竪琴の発動で割引は消えない(再帰しない)。予約中のカードがあれば、その1枚だけが割引を使える。
- **神託**: 停止中・解除後の強化中の再発動は拒否(`oracleActive`・マナを引かない)。停止は延長されず、停止中はマナが回復しない。
- **ストレングス(再設計済み・準備ループ)**: 蓄えがある間も**重ね掛けできる**(SOUL 専用の「1つだけ」の制限=`buffActive` は廃止)。発動のたびに承認済みのコスト(2/3/5)をそれぞれ1回ずつ引き、蓄えは回数分たまる(元の計算: 加算 `1 + Σ各回の%`、Lv1 +10% / Lv2・Lv3 +15%・Lv3 は防御無視。各回の値は発動時のカードレベルで記録)。マナが足りなければその発動だけ拒否され(`insufficientMana`)、蓄えは増えずマナも引かない。倍率・持続時間は変えていない。
- **回復の上限**: 発動ごとに数える(月桂冠 最大100・ヒュアキントス 最大80/100/120・エロスの矢 最大50/100・サイコポンポスは魂3つまで)。再発動しても1回の発動の上限を超えない。サイコポンポス・ヴェイル・月桂冠・ヒュアキントス・葦笛は、新しい発動が古い効果を置き換える(同じ種類は常に1つ)。敵への状態(ギガース殺しの弱体など)は同じ種類を再付与しても1つのまま。
