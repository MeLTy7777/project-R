## 1. キーとゲーム変数の割り当て(承認済み・反映済み)

### 1.1 キャラクターキー

| 人物 | キャラクターキー | 指輪(ID) |
|---|---|---|
| Tsukune Kurage-Celestial | `tsukune_kurage_celestial` | Apollo(`apollo`) |
| Charlotte Winchester | `charlotte_winchester` | Janus(`janus`) |
| Catherine Kingsley | `catherine_kingsley` | Themis(`themis`) |
| Sophia Bancroft | `sophia_bancroft` | Athena(`athena`) |

- フルネームを小文字にして `_` でつないでいます。どちらが姓かを決めつけず、後から増える人物とも重なりにくくするためです。
- キーは**イベントのコマンドに文字として保存されます**。イベントを作り始めた後は、変えないでください(変えると、そのイベントは「未登録のキー」の `-1` になります)。表示名を変えたいときも、キーはそのままにします。
- 大文字と小文字は区別されます。
- Hermes は通信ランクを使わないので、Yuki Kagari のキーと変数はありません。

### 1.2 ゲーム変数(100 番台を通信専用にする)

|---|---|---|---|
| 101 | 通信ランク_Tsukune | Tsukune のランク(0〜10) | する |
| 102 | 通信ランク_Charlotte | Charlotte のランク(0〜10) | する |
| 103 | 通信ランク_Catherine | Catherine のランク(0〜10) | する |

- `data/System.json` のゲーム変数を 20 個から **120 個**に増やしました。増やした枠にも、元の 20 個にも、名前は付けていません。105〜108 と 111〜120 は予約で、通信ランクには登録していません。
- 完了スイッチの番号は、割り当てていません(イベントを設計するときに決めます)。
- 109 番は全イベントで共用します。コマンドの**直後**に条件分岐を置いてください。間にメッセージやウェイトを入れると、並列処理のイベントなどが先に 109 番を書き換える可能性があります。

### 1.3 現在の変数の使用状況(衝突の確認)

反映の前に、作業ツリー(未コミットの変更と未追跡の `Map003.json` を含む)を調べました。追跡済みのデータで使っている番号も、この範囲に収まっています。

| 番号 | 使っている場所 |
|---|---|
| 1 | `ProjectR_TexasHoldem` の「日付の変数」(初期値の 1)と、Map003 のポーカーのイベントの引数(今は通貨がカジノチップなので、通貨の変数としては使われない) |
| 9 | Map001「DEV フィールド戦闘(入口)」のイベント(フィールド戦闘の結果) |
| 10〜19 | Map007(TEST_SOUL)とコモンイベントの、SOUL 戦の開発用の計測 |
| 20 | SOUL 戦の結果(Map007 のイベント) |
| 9999 | `Hendrix_Action_Engine` のコード内の固定値(第三者プラグイン。今の最大数では範囲外) |
| 101〜120 | 通信専用(1.2 の表)。反映の前の調査では、どこでも使われていませんでした |

- データベースの変数には、どれも名前が付いていません。
- `Hendrix_Action_Engine` の `QuickReset` コマンドは、**名前に指定の言葉を含む変数を 0 に戻します**。現在のイベントでは使っていません。使う場合や変数に名前を付ける場合は、101〜104 の名前が対象にならないようにします。
- 調べた範囲: データのイベント命令・出現条件・文章の `\V[n]`・計算式、プラグインの設定と引数(初期値を含む)、プラグインのコードに直接書かれた番号。実行中に番号を組み立てる書き方は、すべては追跡できません。今後イベントを足すときは、101〜120 を通信専用にしてください。

最大数を増やさずに 2〜7 番を使う案は、開発用の番号と混ざるため、採用していません。

### 1.4 変数の数が足りなくなった場合(確認済み)

ゲーム変数の最大数が 101〜104 より小さくなると(例: 反映の前から開いていたエディタで保存して、20 個に戻る)、登録が「使えない変数」になります。通信ランクは誤りが 1 件でもあると全体を停止するため、**通信ランクの 2 コマンドと、指輪の入手・スキルのレベル上げ(Hermes のスキルを含む)がすべて中断**します。何も書き換わらないので、最大数を 120 に戻せば直ります。

## 2. 指輪と報酬の共通ルール

| 項目 | 内容 |
|---|---|
| 指輪を入手すると | その指輪の 5 スキルと**アルティメット**が解放されます。装備、スキル枠への割り当て、Q の選択は自動では行いません(メニューで行います) |
| 指輪のスキルのレベル | 1〜3。`RaiseSkillLevel` で下がることはありません。同じイベントを繰り返しても増えません |
| レベルを飛ばすこと | **仕組み上、Lv1 から Lv3 に直接上げられます。** Lv2 を先に必須にする場合は、イベント側の条件で制御します |
| 戦闘中・画面に敵がいるとき | 指輪の入手とレベル上げは `-4` で拒否します(後で呼び直せます)。ランクの引き上げはできます |
| 仲間が指輪を持っているとき | 指輪の入手は `-5`、レベル上げは `-6` です |
| セーブ | ランクは通常のゲーム変数です。新しいセーブ領域はありません。以前のセーブはランク 0 から始まります |
| 使わないコマンド | 物語のイベントでは `ProjectR_MenuIntegration` の `GrantRing` / `GrantCard` を使いません。`GrantRing` はランクを確認せず、`GrantCard` はレベル指定でレベルを下げられます |

## 6. RPG ツクール MZ での確認手順

6.2 と 6.3 の設定は、ファイルを直接編集して**反映済み**です。エディタでは内容を確認するだけで、登録を追加しないでください(同じキーを追加すると「キーの重複」になり、全体が停止します)。

> エディタの画面は、この作業では開いていません。メニューやボタンの名前は、実際の画面で確認してください。

### 6.1 準備

1. **エディタを開く前に**、今のプロジェクトをバックアップします(フォルダのコピー、または Git のコミット)。現在、未コミットの変更が多くあります。
2. 反映の前からエディタを開いていた場合は、**保存せずに閉じて、開き直します。** 古い内容のまま保存すると、変数が 20 個に戻ったり、登録が消えたりする可能性があります。
3. エディタで保存すると、`System.json` や `plugins.js` はエディタの書式で書き直されます。保存後は Git の差分を確認します。

### 6.2 ゲーム変数の確認(名前付けは任意)

1. 任意のイベントで「変数の操作」を開き、変数を選ぶ画面を出します。
2. 最大数が **120** になっていることを確認します。
3. 名前を付ける場合は、101〜104、109、110 に 1.2 の表の名前の案を使います(105〜108 は「通信ランク_予備」)。名前を付けなくても動きます。
4. 確認のために開いたイベントの命令は、追加せずに閉じます。

### 6.3 通信ランクの登録の確認

1. 「プラグイン管理」で `ProjectR_CommunicationRank` を開きます。状態は ON のままにします。
2. 「通信ランクの登録」が、次の 4 件だけであることを確認します。後で人物を足す場合は、3 つの項目をすべて入れてから確定します。作りかけの行が 1 つでもあると、全体が停止します。

| キャラクターキー | ランクを保存する変数 | ランクの上限 |

3. 変更していなければ、保存せずに閉じます。

参考(`Characters` の中身。**手で書き換えないでください**。照合用です):

### 6.4 登録の確認

1. テストプレイを開始して、F8 でコンソールを開きます。

## 7. イベントの作り方(将来の実装用)

### 7.0 共通の決まり

- 成功は結果コード `1`、すでに済みは `2`、失敗は負の値です。**「変数 0109 ≥ 1」で「成功または済み」**を判定します。
- 条件分岐は、コマンドの**すぐ次**に置きます。
- トリガーは「決定ボタン」などの、1 回ずつ起きるものにします。自動実行や並列処理で呼ぶと、拒否されたときに警告が繰り返されます。
- 設定の誤り(結果の変数がランク用の変数と重なる、通信ランクの登録に誤りがある)の場合は、**イベントがそこで中断します**。コモンイベントの中で呼ぶと、止まるのはコモンイベントだけです。報酬のコマンドは、マップのイベントに直接置いてください。
- コマンドの前にフェードアウトや移動の固定をすると、中断した場合に戻らなくなります。報酬のコマンドは、それらの外で呼んでください。

| コード | 意味 | 主な対応 |
|---|---|---|
| 1 / 2 | 成功 / すでに済み | 続きの台詞 |
| -1 | 設定の不足・誤り | 開発中に直す |
| -2 | 入力の誤り(キー・指輪・スキル・値) | 開発中に直す |
| -3 | ランク不足(`AcquireRing`) | 「まだ渡せない」台詞 |
| -4 | 戦闘中(指輪・レベル) | 後でもう一度会話できるようにする |
| -5 | 仲間が指輪を持っている(`AcquireRing`) | 仕様を決める |
| -6 | 指輪を持っていない(`RaiseSkillLevel`) | 指輪の入手後に起こす |
| -7 | ランクの変数に不正な値がある(通信ランク) | 変数を直接書き換えていないか確認する |
| -9 | そのほかの失敗 | コンソールで確認する |

### 7.A ランクを上げる会話

1. 会話の台詞を置きます。
2. 「プラグインコマンド」→ `ProjectR_CommunicationRank` →「通信ランクを指定の値まで引き上げる」
   - キャラクターキー: 1.1 のキー
   - 引き上げる値: このイベントで到達するランク(1〜10。値は**未定**)
   - 結果コードを入れる変数: **0109**
   - 完了にするスイッチ: 未定(使わなければ 0)
3. 直後に「条件分岐: 変数 0109 ≥ 1」を置き、成功の処理を書きます。「それ以外」には失敗の処理を書きます。

指定の値まで一気に上げます(例えば 2 から 5)。順番どおりに見せたい場合は、イベントの出現条件で「前のランク以上」を指定します。ランクは下がりません。

### 7.B 指輪を託す会話(Apollo / Janus / Themis / Athena)

1. 「プラグインコマンド」→ `ProjectR_RingRewards` →「通信ランクを満たしたら指輪を入手する」
2. 引数は次の表のとおりです。**「ランクを保存している変数」は番号で指定するので、行を間違えると別の人物のランクで判定します。**

| 指輪(神) | ランクを保存している変数 | 必要ランク | 結果コードを入れる変数 |
|---|---|---|---|
| Apollo | 0101(Tsukune) | 未定(1〜10) | 0109 |
| Janus | 0102(Charlotte) | 未定(1〜10) | 0109 |
| Themis | 0103(Catherine) | 未定(1〜10) | 0109 |
| Athena | 0104(Sophia) | 未定(1〜10) | 0109 |

3. 直後に「条件分岐: 変数 0109 ≥ 1」で入手の台詞を出します。「それ以外」の中で、`-3`(ランク不足)、`-4`(戦闘中)、`-5`(仲間が所持)を分けます。
4. 必要ランクが未定のうちは、`0` のままにしてください。`0` では付与されず、`-1` になります。
5. 同じ会話でランクも上げる場合は、7.A の後に 7.B を置きます。ランクを上げただけでは、指輪は渡されません。

### 7.C スキルを強化するイベント

1. 「プラグインコマンド」→ `ProjectR_RingRewards` →「スキルのレベルを固定値まで上げる」
   - スキルID: 第 4 章の表の ID
   - 目標レベル: Lv2 または Lv3
   - 結果コードを入れる変数: **0109**
   - 完了にするスイッチ: 未定
2. 直後に「条件分岐: 変数 0109 ≥ 1」で強化の台詞を出します。「それ以外」で `-6`(指輪を持っていない)と `-4`(戦闘中)を分けます。
3. 指輪を持つ前は起きないように作ります。出現条件に指輪の入手の完了スイッチを使うか、条件分岐の「スクリプト」で `ProjectRCardDeck.hasPlayerRing("apollo")` のように確認します。
4. ランクも条件にする場合は、`ReadRank` で読むか、条件分岐で 101〜104 の値を比較します(読むだけにして、書き換えないでください)。

### 7.D ランクを読む・表示する

1. 「プラグインコマンド」→ `ProjectR_CommunicationRank` →「通信ランクを読み取る」
   - ランクを入れる変数: **0110** / 結果コードを入れる変数: **0109**
2. 文章では `\V[110]` で表示できます。失敗した場合は、0110 に `-1` が入ります(登録の誤りの場合は、何も書かずに中断します)。

### 7.E Hermes の本編イベント

1. 物置で指輪を見つける場面に、`ProjectR_HermesProductionDeck` →「`AcquireHermesRing`」を置きます。
2. 戦闘中や画面に敵がいる場面では呼ばないでください(指輪の受け渡しが拒否されます)。
3. 所持を確認してから、その場面を完了にします(第 2 章の「結果の確認」)。

### 7.F 一度だけのイベントのページ構成

1. ページ 1: 会話と報酬のコマンド。「完了にするスイッチ」を指定します。
2. ページ 2: 出現条件を「そのスイッチが ON」にして、完了後の会話を置きます。
3. 完了スイッチは、結果が `1` か `2` のときだけ ON になります。失敗した場合はページ 1 のままなので、もう一度会話できます。
