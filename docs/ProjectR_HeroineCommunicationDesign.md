## 3. ヒロイン別の設計シート(物語の流れの案・未承認)

### 3.0 読み方と共通の決まり

**区分**

- 【確定】は、第 0 章の「物語の確定事項」に番号(T1 など)がある内容だけです。
- この章のランクの表にある目的・葛藤・前提条件・候補枠は、**すべて【案】(未承認)** です。「根拠」の列の番号は、その案がどの確定事項から出発しているかを示します。**番号が付いていても、案の内容が確定したわけではありません。**
- ランク 1〜10 の**ランクを上げるイベントの ID・場所・完了スイッチ・台詞は、すべて未割当**です。ランクを上げるのは `RaiseRankToMinimum` を呼ぶイベントです。ランク 0 は変数の初期値で、まだ何も起きていない状態です。

**共通の前提条件【案】**

- ランク n のイベントは、同じヒロインのランクが n−1 以上のときに起こします(表の「R(n−1)」)。`RaiseRankToMinimum` は一気に上げることもできるので、順番はイベントの出現条件で守ります。
- 判定は「ランクが○以上」にします(ちょうどの値で判定しない)。
- ランクは下がりません。対立や失敗の場面は、物語の中の出来事として描き、ランクを下げる処理は前提にしません。
- 通信ランクは、本編の進行の条件にしない作りにします。本編で必要な出来事は、ランクが 0 のままでも進むようにします。
- 「本編の進行」を前提にする行は、その出来事の時期が未定です。

**報酬イベントの候補枠【案】**

| 表の書き方 | 意味 |
|---|---|
| 解放候補①(早め) / ②(遅め) | 指輪の入手イベントを置けそうな区切りの候補。**解放ランクは未定です。** ①か②か、別のランクにするかは承認が必要です。両方を使うのではありません |
| 強化候補 | スキル強化のイベントを置けそうな区切り。**スキル・レベル・担当は未割当**で、1 件にするか複数にするかも未定です。指輪を持っていることが必要です |
| — | この区切りでは報酬の枠を提案しない |

- 候補枠は、設計を相談するための呼び名です。イベント ID やスイッチの番号ではありません。
- **ランクが上がっただけでは、指輪も強化も得られません。** どちらも専用のイベント(`AcquireRing`、`RaiseSkillLevel`)で起こします。
- 指輪を取らなくても、ランクのイベントはランク 10 まで進められる案です。強化のイベントは指輪を持つまで起こさず、後から起こせるようにします(エンディングを迎える前の範囲の案です。エンディング後は未定。D24)。指輪の有無で変わる台詞や展開は、まだ設計していません。
- 強化候補は、解放候補②より後のランクに置いています。指輪 1 つの強化は 10 件(5 スキル × Lv2・Lv3)あるので、**この表の枠だけに割り当てるかは決めていません。** ランクと結びつけない任意のイベントや NPC のイベントも選べます。

**指輪の入手に必要な物語上の根拠(4 つの指輪に共通。すべて未決定)**

指輪がどの家に属するかは確定しています(F1〜F4)。ただし、所属が分かっていても、ヒロインが指輪を手渡すことや、特定の人が使用を認められることは決まっていません。入手イベントを承認する前に、次の 5 点を決めます。

1. 指輪は今どこにあり、誰が持っているか(管理しているか)
2. 指輪の扱いを決められるのは誰か。そのヒロインは、どの立場で関わるか
3. Yuki の手に渡る理由と、それを認める人(または認めなくてよい理由)
4. 入手しない場合に指輪がどうなるか。取らなくても本編が成り立つ理由
5. 本編、ほかの指輪、そのヒロインの主題と矛盾しないか

入手の形の選択肢【案】(どれも選んでいません。組み合わせや別の形もあります):

| 形 | 内容 | そのヒロインの役割の例 |
|---|---|---|
| あ | 扱いを決められる人が認めて、Yuki に託す(その人はヒロインとは限らない) | 橋渡し、説得、立会い |
| い | Yuki 自身が見つける | 手がかりの提供、調査や手続きの手助け |
| う | 事情が変わり、一時的な保管者として Yuki が預かる | 預ける必要を示し、条件を確かめる |

この表の指輪の「入手」は、仕組みの上ではどれも同じ(主人公の所持になる)です。違うのは、そこに至る物語です。どの形でも、`AcquireRing` の前に、権限の根拠を示した使用の許可の場面を置きます(3.5.5 節の案)。指輪ごとの具体的な案は、3.5 節にあります(未承認)。

#### 3.5.2 `AcquireRing` でできること・できないこと【仕組み】

- **対象:** `apollo` / `janus` / `themis` / `athena` だけです。
- **判定の順:** 設定の誤り(`-1`、内容によってはイベントを中断) → 指輪の ID(`-2`) → 変数と必要ランクの設定(`-1`) → 主人公がすでに所持(`2`) → 仲間が所持(`-5`) → ランク不足(`-3`) → 戦闘中や、画面に敵がいる(`-4`) → 入手(`1`)。
- **入手すると:** その指輪の 5 スキルが使えるようになります。スキルのレベルは現在の値のままです(アルティメットは第 2 章)。装備、スキル枠、Q は自動で変わりません。
- **完了スイッチ:** 結果が `1` か `2` のときだけ ON になります。このコマンドは OFF に戻しません。
- **確認しないこと:** 物語上の使用の許可、本編の進行、場所は確認しません。指定した変数が、その指輪のヒロインの変数かどうかも確認しません。
- **必要ランク:** コマンドの引数なので、呼ぶ場所ごとに指定します。【案】1 つの指輪の `AcquireRing` は、1 か所に置きます。

そのため、**ランク以外の前提条件と使用の許可は、イベントの出現条件や条件分岐で守る必要があります。**

#### 3.5.7 エンディング前に、後から受け取れるようにする決まり【案】

**この節の対象は、エンディングを迎える前だけです。** エンディングと、その後に自由に行動できるかのルールは決まっていません。**エンディング後に指輪や強化を受け取れるとは約束しません**(D24)。

| エンディング前に起こること | 受け取れるようにする方法 |
|---|---|
| ランクに達した後、すぐに受け取らない | エンディング前は、途中の期限を付けない。相談と受け取りのイベントは、出せるようになった後は消さない |
| 本編が先へ進む | 前提は「〜より後」の形だけにする。ランク表の「本編の進行と矛盾しない時期」は、始められる時期の意味にして、途中の締め切りにしない |
| ランクのイベントを後回しにする | エンディング前は、ランクのイベントにも途中の期限を付けない(入手には、そこまでのランクが必要なため) |
| 選択肢で断る | 同じ相手に話しかければ、もう一度始められる |
| 戦闘中などで `-4` | 許可は覚えたままにする。完了スイッチは ON にならないので、後で同じイベントから呼び直す |
| 設定の誤りで `-1` | 完了にならないので、直した後に同じイベントから受け取れる |
| 仲間が持っていて `-5` | この案では、入手前の 4 つの指輪を仲間に持たせない(D9) |
| 入手後、仲間に渡している間の強化が `-6` | 完了にならないので、指輪を主人公へ戻した後に、同じイベントから呼び直す |
| 場所に行けなくなる | 別の場所か通信の手段を用意する |

**ゲームの仕組みと合わせるための注意**

- 【仕組み】`AcquireRing` の後は、期限、回数、用途の区別なしにスキルを使える。入手を取り消すコマンドはない。そのため、「調査の間だけ」「立ち会いがあるときだけ」のような条件付きの許可は、仕組みでは守れないので、どのシナリオにも入れていない。
- 【仕組み】`ProjectR_RingParty` の説明では、メニューの「指輪装備」に、指輪を仲間に渡す操作と、主人公へ戻す操作がある。渡せるのは、定義で仲間を指定した指輪だけで、製品でどの指輪を対象にするかは未定義。仲間は 1 人 1 つまでで、戦闘中は変更できない。渡すと、主人公はその指輪を持たない扱いになり、対応するカードは使えなくなる。装備とスキル・奥義の登録は解除され、戻しても自動では戻らない。仲間が戦闘で指輪の力を使う動きは、確認していない。**この節では、これらの仕組みを変えない。**
- **家の所属が変わらないことや、所有を移さないことは、それだけで、パーティー内の一時的な受け渡しを禁じるものではない。** 受け渡しを認めるか、仲間が指輪を使うことを認めるかは、**未定**(D9、D25)。禁じる場合や条件を付ける場合は、今の仕組みとどう合わせるかを別に決める。
- 【仕組み】同じ説明では、主人公はいくつでも指輪を装備できる。通常のスキル枠(5 つ)と Q の枠は増えず、選べるスキルと奥義が増える。戦闘の強さへの影響は確認していない。

### 4.6 強化イベントの共通ルール

#### `RaiseSkillLevel` の動き【仕組み】

| 項目 | 内容 |
|---|---|
| 対象 | 上の表の 25 スキルだけ。目標は Lv2 か Lv3。25 スキルの最大レベルは、すべて 3。アルティメット 5 つは対象に含まない |
| 判定の順 | 設定の誤り(`-1`) → スキル ID と目標の誤り(`-2`) → 指輪を主人公が持っていない(`-6`) → 戦闘中(`-4`) → すでに目標以上(`2`) → 引き上げ(`1`) |
| レベル | 今の値と目標の高いほうになる。下がらない。同じ呼び出しを繰り返しても増えない(`2`) |
| `-6` | 未所持でも、仲間が持っていても `-6`。目標以上のレベルでも「済み」にしない。レベルと完了スイッチは変えない。指輪を主人公へ戻せば、同じ呼び出しで受け取れる |
| 順番 | **コマンドは Lv2 を先に必須にしない。** Lv1 から Lv3 に直接上げられる |
| 完了スイッチ | `1` か `2` のときだけ ON。範囲外の番号を指定すると、何もせず `-1`。今のスイッチの最大数は 20 |
| セーブ | レベルは、今あるカードの保存データに入る。新しい保存領域は使わない。指輪を仲間に渡しても、保存したレベルは変わらない |

#### 共通の決まり【案】(順番と所持の条件は、今回の依頼で必須)

1. **所持:** 指輪を主人公が持っていることを必須にする。仲間が持っていて `-6` の場合は、「指輪を主人公へ戻してから」と案内し、後でやり直せるようにする。仲間の使用を認めるかは未定(D25)。
2. **順番:** **Lv3 は、同じ技の Lv2 を取得済み(保存レベルが 2 以上)であることを必須にする。** 呼ぶ前に確かめる。これは強化の状態の条件で、Lv2 の物語のイベントを完了したかとは別(4.10 節)。物語では、レベルを下げることもできる `GrantCard` を使わない。
3. **1 回だけ:** コマンドを呼ぶ前に、保存レベルを確かめる。**目標以上の技は、コマンドを呼ばない。** 強化を飛ばしても、完了していない物語は省かない。報酬ごとのスイッチは使わない案(4.10 節)。
4. **成功と失敗:** 目標に届いていない技だけ、呼ぶ直前に結果の変数 0109 を 0 にして呼ぶ。**成功は、0109 が `1` で、かつ保存レベルが目標以上に上がったことを確かめた場合だけ。** どちらかが欠けたら、その場で終える。前に成功した技のレベルは残り、同じイベントから呼び直せる(4.11 節)。
5. **呼ぶ場面:** 戦闘のない場面で、プレイヤーが始める。自動実行や並列処理にしない。フェードアウトや移動の固定の外で呼ぶ(7.0)。
6. **ランクと分ける:** 強化のイベントは `RaiseRankToMinimum` を呼ばない。ランクのイベントは `RaiseSkillLevel` を呼ばない。ランクは、前提条件として「以上」で読むだけにする。
7. **入手の案と分ける:** 前提は「指輪を主人公が持っている」ことで、指輪の許可のシナリオ(A/B)、決定者、解放ランク(6 / 6 / 5 / 7 と Janus の代案 9)のどれを選ぶかに左右されない。これらは未決定のまま。
8. **本編:** 本編の進行は、強化を条件にしない。エンディング前を対象にする(エンディング後は D24)。
9. **完了の条件:** 呼んだ報酬 1 件の成功は、決まり 4 の確認を通ること。呼ぶ前から目標以上の技は、強化を済みとして扱う。**物語のイベントの完了は別のもの**で、場面を最後まで進め、グループの全部の技が目標以上であることを確かめ、完了後の台詞まで終えること(4.10 節)。「その技で敵を倒す」のような戦闘中の達成条件は、判定する仕組みを確認していないので、使わない。
10. **ヒロインの役割:** 4 人のヒロインが戦えるかは、確定していない。ヒロインが担当の場面は、話し合いや確認の役にし、技の手本は求めない。

**Hermes:** 本編で必ず起こる入手(M1)の後に限る。開発・テスト用のイベントでも Hermes の指輪を渡すので(D12)、所持だけでなく、**本編の入手の完了**も条件にする。

### 4.9 `RaiseSkillLevel` の失敗と中断【仕組み】

実際のイベント実行で確かめました。「前の値が残る」は、直前の呼び出しの成功の値 `1` を残して調べた結果です。

| 状況 | 結果の変数 | その後のイベント | レベル |
|---|---|---|---|
| 成功 / すでに目標以上 | `1` / `2` を書く | 続く | 成功の場合だけ上がる |
| 完了スイッチが範囲外 | `-1` を書く | 続く | 変わらない |
| スキル ID の誤り | `-2` を書く | 続く | 変わらない |
| 指輪を仲間が持っている | `-6` を書く | 続く | 変わらない |
| 戦闘中 | `-4` を書く | 続く | 変わらない |
| **結果の変数に、範囲外の番号を指定(指定の誤り)** | **どこにも書かない(分岐で読む 0109 には、前の値が残る)** | 続く | 変わらない |
| **コマンド名が違う(呼び出し先が無い)** | **何も書かない(前の値が残る)** | 続く | 変わらない |
| 通信ランクの登録表の誤り | 何も書かない | **その場で中断** | 変わらない |
| 結果の変数に、通信ランクの変数を指定 | 何も書かない | **その場で中断** | 変わらない |
| 登録表の誤りで、**コモンイベントの中**で中断 | **何も書かない(前の値が残る)** | **コモンイベントだけが中断し、呼び出し元は続く** | 変わらない |

**太字の 3 つの状況では、「0109 が 1 以上」の条件分岐が、失敗を成功と読みます**(確認済み)。呼ぶ直前に 0109 を 0 にすると、どれも成功の分岐に入りません。

`-9`(そのほかの失敗)と、プラグインを無効にした状態は、再現していません。

安全にするための決まり【案】:

1. 呼ぶ直前に、0109 を 0 にする。
2. **呼ぶ前に保存レベルを確かめ、目標に届いていない技だけを呼ぶ。成功は、0109 が `1` で、かつ保存レベルが目標以上に上がった場合だけにする。** 片方だけでは成功にしない(4.10 節。これでも見つからない誤りがある)。
3. 報酬のコマンドと 2 つの判定、物語の完了の目印は、コモンイベントに入れず、マップのイベントの同じ処理に置く。通信がマップのイベントでない形になる場合は、1 と 2 を必ず守り、中断の後で呼び出し元が目印を ON にしない作りにする。
4. 呼ぶ前に、フェードアウトや移動の固定をしない。中断すると戻らないため。自動実行や並列処理にしない。
5. 呼び出しと直後の判定の間に、メッセージやウェイトを入れない。
6. `RaiseSkillLevel` の「完了にするスイッチ」は、0(使わない)にする。

### 4.10 強化の状態と、物語の完了の管理

#### 3 つを分けて考える

| 記録 | 単位 | 分かること | 分からないこと | 保存する所 |
|---|---|---|---|---|
| **強化の状態** | 技ごと | 保存レベルが目標以上か | そのレベルになった経緯。場面を見たか | 今あるカードの保存データ |
| **今回の呼び出しの成功** | 呼んだ技ごと | 呼ぶ前は目標未満で、結果コードが `1`、**かつ**保存レベルが目標以上になった | 呼び出しに指定した ID が正しいこと(下の表)。後からは確かめられない | 保存しない(その場の判定) |
| **物語のイベントの完了** | グループごと | 場面を最後まで進め、グループの全部の技が目標以上であることを確かめた | 個々の技のレベル。どのコマンドで上がったか | 物語の完了の目印 |

- 保存レベルを強化の状態に使うと、**報酬ごとのスイッチ 50 個は要りません。**
- **ただし、保存レベルは、イベントの物語が完了したことの証明にはなりません。** 別の経路でレベルが上がった場合や、強化の後、完了後の台詞の前に処理が止まった場合は、レベルが上がっていても、物語は完了していません。
- そのため、**物語の完了の目印を、グループごとに 1 つ、別に持ちます**(20 グループなら 20 個。合同の 3 グループを分けるなら 23 個)。

#### コマンドの前後で確かめること

| 順 | 確かめること | 結果による扱い |
|---|---|---|
| 呼ぶ前 | 保存レベルが目標以上か | 以上なら、**コマンドを呼ばない。** 完了していない物語は、そのまま進める |
| 呼ぶ直前 | 0109 を 0 にする | コマンドが何も書かなかった場合に、`0` のまま残る |
| 呼んだ後(1) | 0109 が `1` か | `1` でなければ失敗 |
| 呼んだ後(2) | 保存レベルが目標以上になったか | 呼ぶ前は目標未満なので、ここで目標以上なら、レベルが上がったことになる。足りなければ失敗 |

- 呼ぶのは目標に届いていない技だけなので、正しく指定できていれば、結果は `1` です。`2`(すでに目標以上)が返るのは、呼び出しと確認の指定が食い違っている場合で、成功にしません。
- 結果コードは、「条件分岐: 変数 0109 = 1」で確かめます。

#### 結果コードと保存レベルだけでは、見つけられない誤り

**呼んだ後の「結果コードと保存レベル」だけでは、スキル ID の誤りを全部は見つけられません。** 目的の技がすでに目標以上だと、呼び出しに別の技の ID を指定していても、目的の技の保存レベルは条件を満たすからです。前回の案(全部の技を呼び、`1` か `2` と保存レベルで判定する)では、この場合に成功と判定し、物語まで完了しました。別の技のレベルも上がりました(確認済み)。

呼ぶ前の確認を入れた今の手順での結果は、次のとおりです(確認済み)。

| 誤り | 実行中の結果 | 残る問題 |
|---|---|---|
| 目的の技は取得済みで、呼び出しの ID が別の技 | コマンドを呼ばないので、別の技は上がらない | 誤りは隠れたままで、未取得の状態で通ったときに表れる |
| 目的の技は未取得で、呼び出しの ID だけが別の技 | 目的の技が上がらないので、失敗として止まる | **別の技は、すでに上がっている。** 物語では戻さない。コマンドは順番を確認しないので、Lv3 では Lv2 を飛ばすこともある |
| 呼ぶ前の確認の ID だけが、別の取得済みの技 | 目的の技を呼ばずに飛ばす。最後の全技の確認で、未完了のまま止まる | 直すまで完了できない |
| 事前の確認、呼び出し、事後の確認が、同じ別の技の ID | 技ごとの判定は通り、成功の台詞が出る。全技の確認の ID が正しければ、未完了のまま止まる | 別の技が上がっている |
| 全技の確認まで、同じ誤った ID | **物語が完了する。実行中の判定では見つからない** | 目的の技は上がっていない |

**防ぎ方【案】:** 実行中の判定だけに頼らず、公開の前に確かめます。

1. 各イベントのスキル ID を、4.7 節の表と見比べる。
2. グループの全部の技が未取得の状態(Lv3 のグループは Lv2 の状態)から、各イベントを実行する。**25 個の技すべてのレベルを実行の前後で比べ、そのグループの技だけが目標レベルに上がったことを確かめる。** 全部の判定が同じ誤りでも、この比較では分かる(確認済み)。

**保存レベルの判定の書き方(条件分岐の「スクリプト」)【案】**

```text
(ProjectRCardDeck.getPersistentData().cardOwnership["janus_reflection"] || {}).level >= 2
```

- Lv3 の判定は、末尾を `>= 3` にします。「Lv2 を取得済み」は `>= 2` です。
- 一度もレベルを設定していないカードは、2 以上になりません(確認済み)。
- `getPersistentData()` が返すのはコピーで、書き換えても保存データは変わりません(確認済み)。この式は読むだけにします。
- レベルを返す専用の関数はありません。呼ぶ前の確認、呼び出し、呼んだ後の確認、全技の確認で、同じスキル ID を使います。存在しない ID に書き間違えると、成功にも完了にもなりません。**存在する別の技の ID に書き間違えた場合は、上の表のとおりです。**

#### 管理方法の比較

| 比べる点 | A: 報酬ごとのスイッチ 50 個 + 物語の目印 | **B: 保存レベル + 物語の目印はセルフスイッチ** | C: 保存レベル + 物語の目印はグローバルスイッチ |
|---|---|---|---|
| 報酬の状態に使うグローバルスイッチ | 50 | **0** | 0 |
| 物語の目印(グループごと) | B か C と同じものが別に要る | セルフスイッチ 20 個(分ける場合 23 個) | グローバルスイッチ 20 個(分ける場合 23 個) |
| 追加するグローバルスイッチの合計 | 50 個以上 | **0 個** | 20 個(分ける場合 23 個) |
| 今の最大数(20) | 増やす | この目的では増やさなくてよい | 増やす |
| 使える条件 | どちらの形でも | 各グループが、専用のマップイベントの場合 | イベントの形を問わない |
| 報酬の記録のずれ | スイッチとレベルが食い違うことがある | 状態はレベルそのものなので、ずれない | 同じ |
| 主な弱点 | 管理する番号が多い | 目印がマップ ID とイベント ID に結び付くので、ID の変更と再利用に注意が要る。マップのイベント以外では使えない | 番号の確保と管理が要る |

**推奨(未承認):** 強化の状態は保存レベルにします。物語の完了は、グループごとに 1 つの目印にします。目印は、各グループが専用のマップイベントなら B、そうでなければ C です。通信の呼び出し方が未定なので(D11)、**B か C かは、まだ決められません。**

#### 物語の完了の目印と、任意の「場面を一度見た」の目印【案】

2 つは別の目印です。どちらも、報酬の強化が済んだかの判定には使いません(強化の状態は保存レベルです)。

| 比べる点 | **物語の完了の目印** | 「場面を一度見た」の目印(任意) |
|---|---|---|
| 必要か | **必要** | 無くてもよい |
| 数 | グループごとに 1 つ(20 個。分ける場合 23 個) | 使う場合は、グループごとに 1 つ(追加で 20 個。分ける場合 23 個) |
| ON にするとき | 完了後の台詞が終わった後の、最後の命令。その前に、全部の技が目標以上であることを確かめる | グループの**全部の技**の場面を見せ終えたとき(報酬を呼ぶ前)。Lv2 の取得待ちで見せていない部分がある場合は、ON にしない |
| ON の意味 | 物語が完了した | 場面を一度見た。物語の完了でも、強化の成功でもない |
| 使い道 | ページ 2(完了後の会話)への切り替え。通信の入口を消してよいかの判断 | 再挑戦のときに、見終えた場面を短くする |
| OFF の場合 | イベントは未完了。場面から進める | 場面を最初から全部見せる |
| B の場合 | セルフスイッチ A | セルフスイッチ B |
| C の場合 | 専用の区画のグローバルスイッチ | 同じ区画のグローバルスイッチ(グローバルスイッチは合計 40 個。分ける場合 46 個) |

- 「場面を一度見た」が ON でも、完了後の台詞は省きません。短くするのは、見終えた場面だけです。
- 使わない場合は、再挑戦でも同じ場面を出します。報酬の動きは変わりません。
- 物語の完了の目印は、**保存レベルからは作り直せません。** 目印が OFF と読まれた場合は、場面がもう一度出ます。取得済みの技はコマンドを呼ばないので、強化は重なりません。

**セルフスイッチの注意【仕組み】**

- セルフスイッチは、**マップ ID、イベント ID、スイッチの文字(A〜D)**の組で区別され、セーブデータに入ります。
- **イベントの中身を編集しただけでは、保存された状態は消えません。** 3 つの組が同じなら、前の状態がそのまま読まれます(MZ のコードと実行で確認)。
- **ID が変わる場合は注意します。** イベントを削除して作り直した場合や、別のマップへ移した場合などで ID が変わると、新しい組では OFF と読まれます。
- **ID を使い回す場合も注意します。** 別のイベントが同じマップ ID とイベント ID になると、既存のセーブでは前の ON がそのまま読まれ、**始めていない物語が完了に見えます。** 公開したイベントの ID は変えず、削除した ID を別の用途に使わないようにします。エディタが ID をどう割り当てるかは確認していないので、作り直した場合は ID を確かめます。
- イベント ID が 0 の処理(メニューなどからコモンイベントを直接呼ぶ場合)では、セルフスイッチは変わりません。マップのイベントからコモンイベントを呼ぶと、**呼び出し元のイベント**のセルフスイッチが変わります。目印は、コモンイベントの中で操作しません。

**番号が衝突しない割り当て方【案】(番号は決めない)**

1. 使っている番号を調べる(イベントの命令と出現条件、コモンイベント、プラグインの引数、コードに直接書かれた番号。1.3 節の変数と同じ調べ方)。
2. 今の番号と重ならない、通信と報酬の専用の連続した区画を確保する。
3. 1 つの番号は 1 つの用途にして、名前を付け、使い回さない。予備を残す。

Hermes の本編の入手(M1)の目印と、指輪の許可・入手の目印は、本編と入手の設計で決めます。上の数には含めていません。

#### 別の経路でレベルが上がった場合

- 物語の完了の目印は OFF のままです。**場面は省きません。** 目標以上の技は、コマンドを呼びません。全部の技が目標以上であることを確かめ、完了後の台詞まで進めば、物語を完了にできます(確認済み)。すでに上がっている技の台詞をどう出すかは、決める必要があります(D32)。
- Lv3 の前提は、物語の完了ではなく、**強化の状態**(保存レベルが 2 以上)です。別の経路で Lv2 になっていると、Lv2 の物語を見る前に、Lv3 の物語が始まることがあります。Lv2 のグループの物語の完了も条件にするかは、未定です(D34)。今の前提条件には入れていません。
- 目印が ON になった後に、レベルを下げる経路は想定していません。物語では `GrantCard` を使わず、開発用の入手やテストの経路は本編に残さない前提です(D12)。

### 4.11 グループのイベントの前提条件と実行順【案】

#### 前提条件

| 条件 | 対象 | 確かめる場所 |
|---|---|---|
| 物語が未完了(目印が OFF) | 全グループ | ページの切り替え |
| ランクが下限以上(7 / 9 / 10) | 4 つの指輪の、下限があるグループ(グループ 2〜4) | 出現条件の「変数」。「以上」で判定する |
| 本編の入手(M1)の完了 | Hermes の全グループ | 出現条件の「スイッチ」(本編側の番号。未割当) |
| 追加の本編の区切り | Hermes-3、Hermes-4 | 未定(D29)。決まるまで、この 2 つのイベントは作らない |
| 指輪を主人公が所持 | 全グループ | 条件分岐の「スクリプト」(`ProjectRCardDeck.hasPlayerRing("指輪のID")`) |
| 同じ技の Lv2 を取得済み | グループ 3・4(技ごと) | 条件分岐の「スクリプト」(保存レベルが 2 以上) |
| 戦闘中でない | 全グループ | コマンドが `-4` で拒否する。戦闘のない場所にイベントを置く |

グループ 1 の 4 つの指輪のイベントは、出現条件のランクがありません。指輪を持っていない間の見せ方(出さない、案内だけする)は、イベントの場所と合わせて決めます。

#### ページの構成

| ページ | 出現条件 | 内容 |
|---|---|---|
| 1 | 上の表のランクや M1 の条件 | 下の実行順 |
| 2 | 物語の完了の目印が ON | 完了後の会話 |

出現条件に指定できるスイッチは 2 つまでです。足りない条件は、条件分岐で確かめます。

#### 実行順(ページ 1)

グループの中の技は、**4.8 節の配分表に書いた順**で処理します。

1. **所持を確かめる。** 持っていなければ、何も呼ばずに終える。仲間が持っている場合は、「指輪を主人公へ戻してから」と案内する。
2. **今回扱う技を決める。** Lv2 のグループは、全部の技。Lv3 のグループは、**同じ技の Lv2 を取得済み**(保存レベルが 2 以上)の技だけ。どちらも、すでに目標以上の技を含める(物語は扱うが、コマンドは呼ばない)。扱う技が無ければ、案内して終える。
3. **場面を見せる。** 物語が未完了なら、扱う技が全部取得済みでも、場面を省かない。任意の「場面を一度見た」の目印が ON の場合だけ、短くする。グループの全部の技の場面を見せ終えたら、その目印を ON にする。
4. **扱う技を、1 件ずつ順に処理する。**
   1. **コマンドを呼ぶ前に、保存レベルが目標以上かを確かめる。**
   2. **目標以上なら、コマンドを呼ばずに次の技へ進む。** 強化の台詞は出さない。
   3. 目標に届いていなければ、0109 を 0 にする。
   4. `RaiseSkillLevel`(結果の変数 0109、完了スイッチ 0)を呼ぶ。
   5. **結果コードが `1` かを確かめる。**
   6. **続けて、保存レベルが目標以上になったかを確かめる。**
   7. 両方を通った場合だけ、成功にして、強化の台詞を出す。
   8. どちらかを通らなければ、理由を案内して、**そこで終える**(イベント処理の中断)。
5. **グループの全部の技が目標以上かを確かめる。** そろっていなければ(Lv2 を取得していない技がある場合)、案内して終える。目印は OFF のまま。
6. **完了後の台詞を出し、最後の命令で、物語の完了の目印を ON にする。**

ステップ 1 から 4 のどこかで終えた場合も、目印は OFF のままです。

**最初の失敗で止める理由:** ステップ 5 まで進んだこと自体が、「今回扱った技は、すべて、呼ぶ前から目標以上だったか、呼んで成功した」ことを表します。失敗があったかを覚えておく変数やスイッチが要りません。
**弱点:** `-1`、`-2`、`-9` のような誤りがあると、直すまで、同じグループの表の順で後ろの技は処理されません。ほかのグループには影響しません。誤りの後も続ける形にするには、失敗の有無を覚える一時の記録が別に要ります(D35)。

**失敗の理由の分け方(ステップ 4)**

| 0109 の値と保存レベル | 意味 | 案内 |
|---|---|---|
| `-6` | 指輪を主人公が持っていない | 指輪を主人公へ戻してから、もう一度 |
| `-4` | 戦闘中 | 戦闘の後で、もう一度 |
| `-1` / `-2` / `-9` | 設定や指定の誤りなど | 処理できなかったことを伝える(開発で直す) |
| `0` | コマンドが何も書かなかった | 同じ |
| `2` | 目標に届いていないことを確かめて呼んだのに「済み」。呼び出しと確認の指定の食い違い | 同じ |
| `1` だが、レベルが足りない | 同じ食い違い。**別の技が上がった可能性がある** | 同じ(開発で、上がった技も確かめる) |

#### 失敗からの復帰

| 起こること | 残る状態 | 復帰の方法 |
|---|---|---|
| 一部の技の後で失敗した | 成功した技のレベルは上がったまま。目印は OFF | 同じイベントを実行する。済んだ技は呼ばずに通過し、残りだけを呼ぶ |
| `-6`(仲間が指輪を持っている) | レベルは変わらない | 指輪を主人公へ戻して、同じイベントから呼び直す(持っていない間は、ステップ 1 で止まる) |
| `-4`(戦闘中) | レベルは変わらない | 戦闘の後に呼び直す |
| `-1` / `-2` / `-9` | その技より前の成功は残る。後ろの技は未処理 | 誤りを直して実行する |
| 呼び出しに別の技の ID を指定していた | 目的の技は変わらず、目印は OFF。別の技が上がっていることがある | ID を直して実行する。上がってしまった別の技は、この手順では戻らない(4.10 節の公開前の確認で防ぐ) |
| コマンドが中断した | 中断より前の成功は残る。目印は OFF | 原因を直して実行する |
| Lv2 を取得していない技がある(Lv3) | Lv2 を取得済みの技は上がる。目印は OFF。「場面を一度見た」も OFF | その技の Lv2 を取得した後に、同じイベントを実行する |
| 全部上がった後、台詞の途中で終了した | レベルと目印は、最後にセーブした時点に戻る | もう一度実行する。上がっていた技は呼ばずに通過し、残りの物語を進める |
| 完了した後に話しかけた | 変わらない | ページ 2 の会話だけを出す。コマンドは呼ばない |

レベルと目印(セルフスイッチ、スイッチ)は、同じセーブデータに入ります。

#### ランク 10 の報酬と、通信の話が終わった後

- ランクは下がらないので、「9 以上」「10 以上」の条件は、一度満たすと続きます。
- **グループ 3・4 の報酬は、ランク 9・10 のイベントの中では呼びません。** 別のイベントにして、失敗しても後で受け取れるようにします。
- **ランク 10 になり、通信の話が終わった後も、強化のイベントに行ける入口を残します。** そのグループの物語の完了の目印が ON になるまで、消さないでください。
- グループ 4 は、ランク 10 に達してから始まります。通信の最後のイベントで入口が閉じる作りにしないでください(D33)。
- 通信の呼び出し方と場所は未定です(D11)。エンディング後の扱いは、決まるまで約束しません(D24)。

#### Hermes の順序

- 本編の入手(M1)が先です。**所持だけを条件にしません。** 開発用のイベントでも指輪を渡すので(D12)、本編の入手の目印も必要です。
- ヒロインの通信ランクは条件にしません。
- Hermes-1 と Hermes-2 は、今の案では、入手の直後からどちらも始められます。Lv3 は、同じ技の Lv2 の取得と、追加の本編の区切り(未定)の後です。

## 7. イベントの作り方(将来の実装用)

### 7.0 共通の決まり

- 成功は結果コード `1`、すでに済みは `2`、失敗は負の値です。**「変数 0109 ≥ 1」で「成功または済み」**を判定します。
- 条件分岐は、コマンドの**すぐ次**に置きます。
- **呼ぶ直前に、結果の変数(0109)を 0 にしてください。** 結果の変数の指定が範囲外の場合などは、コマンドが何も書かず、前の成功の値が残ります(4.9 節。`RaiseSkillLevel` で確認。指輪の入手も、同じ書き出しの処理を使います)。物語のスキル強化は、呼ぶ前に保存レベルを確かめて目標以上なら呼ばず、呼んだ場合は 0109 が `1` であることと、保存レベルの両方を確かめます(4.10 節)。
- トリガーは「決定ボタン」などの、1 回ずつ起きるものにします。自動実行や並列処理で呼ぶと、拒否されたときに警告が繰り返されます。
- 設定の誤り(結果の変数がランク用の変数と重なる、通信ランクの登録に誤りがある)の場合は、**イベントがそこで中断します**。コモンイベントの中で呼ぶと、止まるのはコモンイベントだけです。報酬のコマンドは、マップのイベントに直接置いてください。
- コマンドの前にフェードアウトや移動の固定をすると、中断した場合に戻らなくなります。報酬のコマンドは、それらの外で呼んでください。

| コード | 意味 | 主な対応 |
|---|---|---|
| 1 / 2 | 成功 / すでに済み | 続きの台詞 |
| -1 | 設定の不足・誤り | 開発中に直す |
| -2 | 入力の誤り(キー・指輪・スキル・値) | 開発中に直す |
| -3 | ランク不足(`AcquireRing`) | 「まだ渡せない」台詞 |
| -4 | 戦闘中(指輪・レベル) | 後でもう一度会話できるようにする |
| -5 | 仲間が指輪を持っている(`AcquireRing`) | 仕様を決める |
| -6 | 指輪を持っていない(`RaiseSkillLevel`) | 指輪の入手後に起こす |
| -7 | ランクの変数に不正な値がある(通信ランク) | 変数を直接書き換えていないか確認する |
| -9 | そのほかの失敗 | コンソールで確認する |

### 7.A ランクを上げる会話

1. 会話の台詞を置きます。
2. 「プラグインコマンド」→ `ProjectR_CommunicationRank` →「通信ランクを指定の値まで引き上げる」
   - キャラクターキー: 1.1 のキー
   - 引き上げる値: このイベントで到達するランク(1〜10。値は**未定**)
   - 結果コードを入れる変数: **0109**
   - 完了にするスイッチ: 未定(使わなければ 0)
3. 直後に「条件分岐: 変数 0109 ≥ 1」を置き、成功の処理を書きます。「それ以外」には失敗の処理を書きます。

指定の値まで一気に上げます(例えば 2 から 5)。順番どおりに見せたい場合は、イベントの出現条件で「前のランク以上」を指定します。ランクは下がりません。

### 7.B 指輪を託す会話(Apollo / Janus / Themis / Athena)

この節は、コマンドの置き方の説明です。【案】物語の流れは 3.5 節の案(未承認)で、`AcquireRing` の前に、使用の許可の場面を必ず置きます。

1. 「プラグインコマンド」→ `ProjectR_RingRewards` →「通信ランクを満たしたら指輪を入手する」
2. 引数は次の表のとおりです。**「ランクを保存している変数」は番号で指定するので、行を間違えると別の人物のランクで判定します。**

| 指輪(神) | ランクを保存している変数 | 必要ランク | 結果コードを入れる変数 |
|---|---|---|---|
| Apollo | 0101(Tsukune) | 未定(1〜10) | 0109 |
| Janus | 0102(Charlotte) | 未定(1〜10) | 0109 |
| Themis | 0103(Catherine) | 未定(1〜10) | 0109 |
| Athena | 0104(Sophia) | 未定(1〜10) | 0109 |

3. 直後に「条件分岐: 変数 0109 ≥ 1」で入手の台詞を出します。「それ以外」の中で、`-3`(ランク不足)、`-4`(戦闘中)、`-5`(仲間が所持)を分けます。
4. 必要ランクが未定のうちは、`0` のままにしてください。`0` では付与されず、`-1` になります。
5. ランクを上げただけでは、指輪は渡されません。【案】3.5.5 節の案では、ランクを上げるイベントと、指輪の使用の許可・入手のイベントを分けます。

### 7.C スキルを強化するイベント

Lv3 のイベントは、同じ技の Lv2 を取得済みであることを条件にします(コマンドは順番を確認しません。4.6 節)。下の手順はコマンドの置き方の説明です。**物語の強化イベントは、4.11 節の手順(呼ぶ前に目標レベルを確かめる、呼ぶ場合は 0109 を 0 にする、成功は結果コード `1` と保存レベルの両方で判定する、完了にするスイッチは 0、物語の完了はグループの目印)を使う案です。**

1. 「プラグインコマンド」→ `ProjectR_RingRewards` →「スキルのレベルを固定値まで上げる」
   - スキルID: 第 4 章の表の ID
   - 目標レベル: Lv2 または Lv3
   - 結果コードを入れる変数: **0109**
   - 完了にするスイッチ: 未定
2. 直後に「条件分岐: 変数 0109 ≥ 1」で強化の台詞を出します。「それ以外」で `-6`(指輪を持っていない)と `-4`(戦闘中)を分けます。
3. 指輪を持つ前は起きないように作ります。出現条件に指輪の入手の完了スイッチを使うか、条件分岐の「スクリプト」で `ProjectRCardDeck.hasPlayerRing("apollo")` のように確認します。
4. ランクも条件にする場合は、`ReadRank` で読むか、条件分岐で 101〜104 の値を比較します(読むだけにして、書き換えないでください)。

### 7.D ランクを読む・表示する

1. 「プラグインコマンド」→ `ProjectR_CommunicationRank` →「通信ランクを読み取る」
   - ランクを入れる変数: **0110** / 結果コードを入れる変数: **0109**
2. 文章では `\V[110]` で表示できます。失敗した場合は、0110 に `-1` が入ります(登録の誤りの場合は、何も書かずに中断します)。

### 7.E Hermes の本編イベント

1. 物置で指輪を見つける場面に、`ProjectR_HermesProductionDeck` →「`AcquireHermesRing`」を置きます。
2. 戦闘中や画面に敵がいる場面では呼ばないでください(指輪の受け渡しが拒否されます)。
3. 所持を確認してから、その場面を完了にします(第 2 章の「結果の確認」)。

### 7.F 一度だけのイベントのページ構成

1. ページ 1: 会話と報酬のコマンド。「完了にするスイッチ」を指定します。
2. ページ 2: 出現条件を「そのスイッチが ON」にして、完了後の会話を置きます。
3. 完了スイッチは、結果が `1` か `2` のときだけ ON になります。失敗した場合はページ 1 のままなので、もう一度会話できます。
