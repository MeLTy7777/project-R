- ランタイムIDは7つとも重複せず、定義は1つずつです(カタログが起動時に追加。旧カードのIDとは重ならない)。1回の使用で新旧のhandlerが両方動くこともありません(handlerは `targetType` の連鎖で、カードごとにcardIdで分かれる)。

## 3. 指輪の初回入手と30枚の付与(冪等)

実装: `js/plugins/ProjectR_HermesProductionDeck.js`(新規)。

### 3.1 入口(通常のゲーム進行)
既存の物語イベントでHermesの指輪を入手させている箇所は**ありません**(`data/*.json` に `GrantRing` / `GrantCard` の呼び出しなし)。物語の場面は作っていません。代わりに、イベントエディタから呼べる入口を用意しました。

| 入口 | 備考 |
|---|---|
| プラグインコマンド `ProjectR_HermesProductionDeck: AcquireHermesRing`(**本番の入口**) | 指輪が未所持なら主人公のものにして初回付与。すでに主人公が持つ/仲間が持つなら何もしない |
| 既存のプラグインコマンド `ProjectR_MenuIntegration: GrantRing`(ringId=hermes) | 本プラグインが包んで連動。未所持から入手した初回だけ付与 |
| API `ProjectRHermesProductionDeck.acquireRing("hermes")` | 上と同じ |
| 新しいゲーム(`DataManager.setupNewGame`) | CardDeckCoreの `RingDefinitions.initialOwner = player` でHermesの指輪を最初から持つ設定のときだけ、同じ付与を一度だけ。**現在の本番設定は未所持**なので何もしない |
| 低水準 `ProjectRCardDeck.assignRingToPlayer` | **付与しない**(DEVアリーナ・テスト・内部処理が使うため。進行からは使わない) |

### 3.2 付与の内容と冪等性
- 付与: 7種を所持にする(Lvは1。**すでに高いLvなら下げない**)。デッキが**空のときだけ**、30枚(設計順)でデッキを初期化。既存のデッキ(不正でも)は**上書きしません**。他の神の指輪・カード・デッキは変えません。
- 付与の記録: `$gameSystem._projectRHermesProduction = { version: 1, rings: { hermes: { granted, source, cards, totalCopies, deckInitialized, ownedBefore } } }`。**記録の無い旧セーブは「未付与」として読みます**(壊れた記録・知らないversionでも読み込めて、中身は変えない)。セーブ形式の変更はこの1項目の追加だけで、旧版で読んでも無視されます。
- 付与しない場合(二重付与の防止):

| 状況 | 結果 |
|---|---|
| 2回目以降の入手イベント(専用コマンド・既存GrantRing・API) | 付与なし。所持・Level・デッキ・記録が不変 |
| セーブ → ロード | 記録が保たれ、付与なし。デッキを30枚へ戻さない |
| 指輪を仲間へ渡して戻した | 付与なし(再取得で所持もLvも増減しない) |
| **指輪をすでに持つ旧セーブ**(記録なし)を読み込んだ | **付与なし**(「読み込んだだけ」では付与しない)。入手イベントも「すでに所持」で何もしない |
| 指輪が仲間にある旧セーブで入手イベント | 奪い返さず付与もしない(`heldByAlly`) |
| 戦闘中 | 失敗(指輪の移動は戦闘中不可の既存規則)。状態不変 |
| 旧セーブでまだ指輪を持たない(例: Apolloだけ)状態で初めて入手 | 付与する。既存のデッキ・Apolloは変えない |
- 将来の移行用に、`grantStarter({ explicit: true })` で**明示的に**旧セーブへ付与することもできます(自動では呼ばれない。一度だけ)。

## 4. デッキ初期化・検証・戦闘開始
- 付与した30枚は、指輪を主人公が持つ状態で `isDeckValid()` を通ります(30枚・所持・指輪・コピー上限)。`canStartBossBattle()` も true です(**30枚検証の規則は変えていません**)。
- 戦闘の開始(`ProjectRCombatSession.begin` / `startCardBattle`)は、**付与も初期化もしません**。プレイヤーが編集したデッキはそのまま使われ、戦闘終了後も変わりません。
- 戦闘中: メニューは開けず、デッキ編集・指輪の移動は `inCombat` で拒否(既存の規則のまま)。手札5枚・Q/E/X/C/V・使用 → Cooldown → すぐ補充 → 期限切れで捨て札 → 山札が尽きたら**捨て札だけ**を混ぜ直す(Cooldown中は含めない)も不変で、自動テストと実機で確認しました。
- 押しっぱなし: カード入力はキーリピートを無視する(押下1回 = 1リクエスト)。ストレングス(0.1秒)・絶(0.5秒)でも、押し続けて1回しか発動しません(自動テスト・実機)。

## 5. 指輪の所有・カードの有効性(既存の規則の確認)
- 主人公は複数の指輪を持て、主人公は持っている指輪のカードを混ぜてデッキに入れられます(Hermes + Apollo の30枚デッキを自動テストで確認)。
- 仲間は1人1つの指輪(`ACTOR_RING_LIMIT`)、戦闘中は移動不可、は既存どおり(変更なし)。
- 指輪を仲間へ渡すと、そのカードは**デッキに残ったまま無効**になります(`REQUIRED_RING_NOT_OWNED`)。削除・並べ替え・自動交換はしません。戻すと再び有効になり、30枚の再付与はありません。
- **表示の改善(この Phase)**: 無効の理由が7行(30枚分)並ぶ代わりに、指輪ごとに1件へまとめます(例: 「ヘルメースの指輪を主人公が持っていないため使えません：一閃・サイコポンポス・…（計30枚）。指輪を戻すと再び使えます。」)。`ProjectRMenuCore.deck.status().groupedMessages`。従来の `messages`(カードごと)は不変です。
- **仲間の適格性・仲間のキャラクターは作っていません**(Hermes の `equipActorIds` は本番では空のまま)。譲渡の検証は DEV ヘルパー `ProjectRProductionTest.allowAlly(4)` でメモリ上だけ一時的に許可して行いました。
